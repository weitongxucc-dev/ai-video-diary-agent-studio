# 视频重复口播自动精剪设计

## 目标

在现有“多段素材合并、长静音剪辑、1.05 倍速、字幕生成、剪映草稿导入”流程中增加重复口播检查。

系统自动剪掉高置信度重录片段，保留表达更完整的后一版；低置信度候选只提醒用户。旧成片和旧剪映草稿不得覆盖，新产物使用 `_dedup` 后缀。

今天的视频也需要重跑，生成新的精剪成片和剪映草稿。

## 范围

本次包含：

- 单条视频和多条短视频合并后的统一重复口播检测。
- 基于本地 Whisper 字幕的本地检测。
- 高置信度候选自动删除。
- 低置信度候选写入报告，不自动删除。
- 精剪后重新生成字幕，确保字幕与最终视频时间轴一致。
- 在网站中显示自动删除数量、删除范围、保留版本和待人工复核候选。
- 重新处理今天的视频，并另存新成片和新剪映草稿。

本次不包含：

- 依赖在线大模型判断语义重复。
- 自动处理相隔较远、主题相似但无法确认属于重录的段落。
- 覆盖或删除旧成片、旧字幕、旧草稿。

## 处理流程

```text
原始视频或多条短视频
  -> 按用户顺序合并素材
  -> 长静音预处理 + 1.05x
  -> 本地 Whisper 初次转写
  -> 重复口播检测
  -> 写入 dedup_report.json
  -> 有高置信度候选时执行二次精剪
  -> 生成 *_dedup.mp4 和 *_dedup.edit_plan.json
  -> 针对最终视频重新转写字幕
  -> 生成新的素材包和剪映草稿
```

如果本地 Whisper 不可用、初次转写失败或没有高置信度候选，流程继续使用现有预处理视频，不阻塞草稿生成。失败原因写入报告。

## 组件边界

### `RetakeDetector`

新增纯本地、可独立测试的检测器。输入为带时间范围的字幕片段，输出为重复口播分析结果。

检测器负责：

- 规范化字幕文本，忽略空格、标点和常见 ASR 差异。
- 比较相邻时间窗中的字幕片段。
- 将连续匹配合并为一组重录候选。
- 计算置信度，并给出建议删除范围和保留范围。
- 将候选分类为 `auto_remove` 或 `review_only`。

检测器不负责运行 ffmpeg，也不直接修改视频。

### `RetakeVideoRefiner`

新增重复口播精剪编排器。输入为现有长静音预处理后的 `ProcessedVideo`，输出为最终 `ProcessedVideo`。

编排器负责：

- 提取预处理视频音频并调用已有 ASR 转写器。
- 调用 `RetakeDetector`。
- 始终写入 `dedup_report.json`。
- 将高置信度删除范围交给 ffmpeg 精剪。
- 生成 `_dedup.mp4` 和新的剪辑计划。
- 没有自动删除项时原样返回预处理视频。

### 视频处理流水线

新增一个轻量流水线封装，将现有 `FfmpegVideoProcessor` 与 `RetakeVideoRefiner` 串联。所有入口共用同一条流水线：

- 单条临时视频。
- 多条临时视频。
- 预定流程中的视频。
- 自动化 worker 扫描到的视频。

这样不会出现网站手动入口能精剪、后台 worker 却漏掉精剪的分叉。

### `DraftWorkspace`

保持现有职责：针对流水线返回的最终成片生成字幕、封面、素材包和剪映草稿。

精剪完成后再次转写字幕。第一次字幕用于判断重录，第二次字幕用于最终草稿，二者用途分开。

## 自动删除规则

只有满足全部核心条件的候选才进入 `auto_remove`：

- 两次口播在相邻时间窗内，默认间隔不超过 30 秒。
- 规范化文本具有高相似度，或前一段明显是后一段的中断前缀。
- 重复内容至少包含 8 个有效中文字符或等价长度文本。
- 后一版内容不短于前一版，且能够保留完整表达。
- 删除范围不会与保留范围重叠。
- 多个重录候选合并后仍能明确保留最后一版。

以下情况进入 `review_only`：

- 轻微自我修正。
- 相似度不足以确定属于重录。
- 两段相隔较远。
- 删除后可能破坏上下文。
- 无法判断哪一版更完整。

实现时将阈值集中定义并写测试，避免散落在业务代码中。第一版优先保守：宁可少剪，不可误删。

## 报告格式

每次处理生成与视频同目录的 `*_dedup_report.json`：

```json
{
  "status": "applied",
  "source_video": "VID_preview.mp4",
  "output_video": "VID_preview_dedup.mp4",
  "auto_removed": [
    {
      "remove": {"start": 13.8, "end": 24.6},
      "keep": {"start": 24.6, "end": 31.6},
      "confidence": 0.96,
      "reason": "相邻重录，后一版表达更完整"
    }
  ],
  "review_only": []
}
```

无自动删除、ASR 不可用或处理失败时，`status` 分别为 `no_changes`、`skipped` 或 `failed`，并记录原因。

报告路径保存到 Episode，并通过 API 返回。网站的视频处理页展示：

- 自动剪掉多少段。
- 每段删除范围、保留范围和原因。
- 是否存在待人工复核候选。
- 旧成片已保留，新成片文件名。

## 文件与兼容策略

- 旧预处理成片保留。
- 精剪成片使用 `_dedup.mp4` 后缀。
- 精剪计划使用 `_dedup.edit_plan.json` 后缀。
- 报告使用 `_dedup_report.json` 后缀。
- 新字幕和新剪映草稿基于 `_dedup.mp4` 生成。
- 多条短视频仍先按用户选择顺序合并，再进入统一精剪流程。

## 错误处理

- 初次 ASR 失败：跳过自动精剪，继续生成原有草稿，并在报告和页面中显示原因。
- ffmpeg 二次精剪失败：保留预处理成片，不覆盖旧文件；后台任务标记失败并记录日志。
- 最终 ASR 失败：仍保留精剪成片；字幕使用现有 fallback 行为。
- 报告写入失败：将任务标记失败，因为自动删除必须可追溯。

## 测试

新增聚焦测试：

- 完整重录：自动删除前一版，保留后一版。
- 中断后重录：自动删除中断片段。
- 轻微自我修正：只进入 `review_only`。
- 两段远距离相似表达：不自动删除。
- 多个连续重录版本：合并删除范围并保留最后一版。
- 无 ASR：跳过精剪，不阻塞旧流程。
- 二次 ffmpeg 命令：正确拼接保留范围并生成 `_dedup.mp4`。
- 单条视频、多段视频、后台 worker 都经过同一流水线。
- Episode 序列化、API 返回和页面展示报告摘要。
- 今天的视频重跑后，最终字幕与 `_dedup.mp4` 时间轴一致，且新剪映草稿包含视频轨和字幕轨。
