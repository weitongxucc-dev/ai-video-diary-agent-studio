# AI视频日记 Agent Studio 2.1-2.5 个人创作者单人工作流设计

日期：2026-06-08

## 1. 方向判断

2.0 已经把产品从 Web 原型推进到 macOS 本地 Agent Studio，并初步打通“内容模板、语音指令、剪辑计划、剪映草稿、偏好记忆、DMG 内测”的链路。

2.1 之后不应优先扩成通用视频工具、多人协作平台或云端 SaaS。更好的方向是深耕个人创作者单人工作流：

```text
让一个人用更少时间、更少决策负担，产出更高质量、更可复盘的内容。
```

这个方向的核心不是增加更多按钮，而是把每天真实会卡住创作者的节点逐个磨平：

- 口播稿还差一点，需要快速重写和版本留痕。
- 字幕和封面决定成品感，需要可编辑、可确认。
- Agent 现在常常等待人工确认，需要给出更可信的一键建议。
- 发布反馈目前偏主观，需要接入播放、完播、互动和评论洞察。
- 创作者不是每天临时想内容，需要一周内容队列和排期。
- 鼠标操作过多，需要语音和快捷键把创作动作变成自然指令。

## 2. 产品原则

### 2.1 先闭环，再扩展

优先补齐“选题 -> 脚本 -> 视频处理 -> 字幕 -> 封面 -> 剪映草稿 -> 发布反馈”的成品闭环。任何新能力都必须服务这个链路。

### 2.2 Agent 先推荐，不先越权

Agent 可以自动选出推荐项、自动打分、自动生成下一步动作，但高风险动作仍需要用户确认。短期目标是“一键接受”，不是“无人值守”。

### 2.3 数据只辅助判断，不机械追随

播放量、完播率、点赞率和评论只是信号。系统必须显示样本量、置信度和不要过拟合的提醒，不允许单条爆款直接决定长期内容方向。

### 2.4 高内聚、低耦合

新增能力按职责拆分：

- 封面编辑只关心封面草案、封面素材和封面导出。
- 字幕编辑只关心字幕段、时间轴和字幕导出。
- 发布数据只关心指标、评论、洞察和偏好候选。
- 内容日历只关心排期、状态和阻塞原因。
- 语音指令只产出操作草案，不直接操作所有业务对象。

## 3. 版本路线

### 2.0.1：内测稳定性

目标：让 DMG 在其他同事机器上稳定启动和排障。

范围：

- 保持桌面端依赖检查、日志、错误报告包。
- 继续验证 `uv`、`ffmpeg`、剪映路径和首次打开体验。
- 剪映 10.7 加密草稿写入继续做降级处理，不阻塞内测。

非目标：

- 不做完整 Apple Developer ID notarize。
- 不做云端分发和自动更新。

### 2.1：成品闭环增强

目标：让一条内容在进入剪映前具备可编辑的脚本、字幕和封面。

核心功能：

- 脚本快捷重写：按段落快速选择“更犀利、更口语、更真实、更短、更像复盘”等重写意图。
- 字幕编辑器：展示字幕段、起止时间、文本、合并/拆分/重写/重新生成。
- 封面编辑器：编辑主标题、副标题、标签、人物截图位置、风格模板和候选封面。
- 草稿前最终检查：进入剪映草稿前显示脚本、字幕、封面、视频、模板轨道的状态清单。

验收标准：

- 用户能在 App 内完成口播稿段落重写，不覆盖旧版本。
- 用户能修正字幕文本和基础时间段，并重新导出字幕。
- 用户能编辑封面文案并生成封面资源。
- 生成剪映草稿前，系统能明确显示哪些素材已确认、哪些仍缺失。

### 2.2：Agent 质量判断与一键推进

目标：减少“等待人工确认”的阻塞感。

核心功能：

- 今日推荐主选题：Agent 按素材支撑、账号匹配、近期表现和表达新鲜度给出推荐。
- 脚本质量检查：判断开头冲突、结构完整度、口语程度、时长风险和是否有真实案例。
- 剪辑计划质量检查：判断重复录制删除是否有字幕依据、成片时长是否合理、是否存在高风险删除。
- 一键接受建议：用户可以接受 Agent 推荐并进入下一步。

风险控制：

- 选题和脚本只做推荐，不自动跳过用户确认。
- 删除视频片段仍需显示字幕依据和可回滚信息。
- 系统必须保留版本历史和推荐理由。

验收标准：

- 每个推荐都有分数、理由和风险提示。
- 用户可以一键接受推荐，也可以展开修改。
- Agent 不会在无依据时输出高置信度判断。

### 2.3：发布数据回流与表现洞察

目标：让反馈学习从主观赞踩升级到真实平台表现。

核心功能：

- 发布数据录入：支持手动填写播放、点赞、评论、收藏、完播率、发布时间和平台。
- 评论洞察增强：把评论拆成观众需求、负面反馈、共鸣点和选题建议。
- 表现洞察报告：按内容类型、选题结构、开头风格、时长和发布时间聚合。
- 洞察入库确认：只有用户确认后的洞察进入长期偏好记忆和 prompt context。

第一版不做平台 API 自动抓取。用户可以手动填数据或粘贴平台后台文本。

验收标准：

- 系统能区分“数据指标”和“评论信号”。
- 样本量不足时提示“仅作参考”。
- 已确认洞察能进入下一次选题和脚本生成上下文。

### 2.4：7 天内容日历

目标：从“每天临时想”升级为“按计划推进”。

核心功能：

- 未来 7 天内容队列：每条包含选题、模板、状态、录制计划、发布计划和阻塞原因。
- 今日任务生成：从内容队列中挑出今日应推进的任务。
- 排期状态：待选题、待脚本、待录制、待剪辑、待发布、待复盘。
- 轻量拖动或菜单调整日期。

非目标：

- 不做完整日历应用。
- 不做多人任务协作。
- 不做平台自动发布。

验收标准：

- 用户能提前排 7 天选题。
- 今日工作台能显示来自日历的下一步任务。
- 逾期任务能被标记阻塞原因，而不是无限堆积。

### 2.5：语音生产流和快捷操作

目标：把鼠标点击密集的操作变成自然生产指令。

核心功能：

- 全局快捷键唤起语音命令台。
- 脚本语音改写：“换个犀利点的角度”“这一段压短到 20 秒”。
- 字幕语音修改：“把这里改成更口语”“合并这两句字幕”。
- 剪辑语音修改：“删掉刚才重复讲的那段”“保留这个停顿”。
- 发布反馈语音录入：“这条播放 3000，评论说节奏慢，下次开头直接讲冲突”。

验收标准：

- 语音先解析为操作草案，再执行。
- 高风险动作仍需确认。
- 每条语音指令都能在操作历史里追溯。

## 4. 模块设计

### 4.1 ScriptRewriteControl

职责：

- 管理脚本段落重写意图。
- 生成重写请求。
- 展示重写前后差异。
- 保存脚本版本。

输入：

- Episode。
- ScriptSection。
- CreatorProfile。
- ContentTemplate。
- 已确认偏好记忆。

输出：

- ScriptVersion。
- RewriteReason。
- 用户确认或驳回记录。

边界：

- 不负责封面、字幕或视频剪辑。
- 不直接写长期偏好，只生成反馈事件。

### 4.2 SubtitleWorkspace

职责：

- 读取 ASR 字幕和剪辑后字幕。
- 展示字幕段、时间和文本。
- 支持编辑、合并、拆分、重新生成和导出。

输入：

- Transcription。
- EditPlan。
- ProcessedVideo。

输出：

- SubtitleTrack。
- SRT / VTT。
- 字幕修改历史。

边界：

- 不负责视频重编码。
- 不负责剪映草稿写入，只提供字幕资源。

### 4.3 CoverWorkspace

职责：

- 管理封面字段。
- 生成候选封面。
- 导出封面图片。
- 把封面资源写入草稿素材包。

输入：

- Episode。
- ScriptPackage。
- ContentTemplate cover rule。
- 视频截图或用户选择的人物截图。

输出：

- CoverDraft。
- CoverAsset。
- 封面确认状态。

边界：

- 不负责发布平台封面上传。
- 不负责复杂图像编辑，只做模板化封面。

### 4.4 AgentQualityGate

职责：

- 对选题、脚本、剪辑计划和草稿前检查进行评分。
- 生成推荐、风险和下一步动作。

输入：

- Episode 当前状态。
- 内容模板规则。
- 偏好记忆。
- 发布表现洞察。

输出：

- QualityCheck。
- RecommendedAction。
- RiskFlag。

边界：

- 不直接修改 Episode。
- 不直接执行高风险动作。

### 4.5 PerformanceInsights

职责：

- 保存发布数据。
- 解析评论信号。
- 生成表现洞察。
- 生成待确认偏好候选。

输入：

- PerformanceSnapshot。
- CommentInsight。
- Episode metadata。

输出：

- PerformanceInsight。
- PreferenceCandidate。

边界：

- 不自动决定下一次选题。
- 不绕过用户确认写入长期记忆。

### 4.6 ContentCalendar

职责：

- 管理未来 7 天内容队列。
- 记录每条内容的状态、日期和阻塞原因。
- 向今日工作台提供任务。

输入：

- TopicCandidate。
- Episode。
- 用户排期操作。

输出：

- ContentPlanItem。
- DailyTaskQueue。

边界：

- 不做多人协作。
- 不做跨平台发布。

### 4.7 VoiceCommandRouter

职责：

- 把语音或文本命令解析成操作草案。
- 根据风险等级决定是否需要确认。
- 把确认后的命令分发给对应 workspace。

输入：

- TranscribedCommand。
- 当前页面上下文。
- 当前选中对象。

输出：

- CommandDraft。
- CommandExecutionResult。

边界：

- 不直接包含脚本、字幕、封面、日历的业务逻辑。
- 只负责解析、预览、确认和路由。

## 6. UI 设计方向

### 6.1 今日工作台

新增：

- 今日推荐主选题。
- 今日阻塞原因。
- 来自 7 天内容队列的任务。
- Agent 下一步推荐动作。

### 6.2 脚本页

新增：

- 段落快捷重写按钮。
- 重写草案对比。
- 版本历史。
- 脚本质量检查卡。

### 6.3 视频 / 剪辑计划页

新增：

- 字幕编辑面板。
- 片段字幕依据和字幕编辑联动。
- 剪辑质量检查卡。

### 6.4 草稿页

新增：

- 封面编辑器。
- 草稿前最终检查清单。
- 封面、字幕、模板轨道确认状态。

### 6.5 学习页

新增：

- 发布数据录入。
- 表现洞察。

- 已确认 / 待确认 / 已驳回洞察。

### 6.6 内容日历页

- 阻塞原因。

## 7. 技术边界

### 7.1 后端

- 新增模块必须通过 router 和 service 分层接入，不继续膨胀 `main.py`。
- 每个模块有独立测试文件。
- 数据写入优先使用 SQLite repository，不在内存全局变量里长期保存。
- 生成类功能必须返回结构化结果，不能只返回自然语言。

### 7.2 前端

- 复用现有像素风组件和布局。
- 字幕、封面、质量检查、日历要拆成独立组件。
- 长列表必须有高度限制和 overflow guard。
- 所有 AI 生成草案必须有确认 / 驳回 / 回滚路径。

### 7.3 桌面端

- 继续保持本地优先。
- 发布数据第一版手动录入，不接平台爬虫。
- 移动端只作为后续轻量 PWA 评审视图，不进入 2.1-2.3 范围。

## 8. 推荐实施顺序

第一阶段：2.1A 脚本快捷重写

- 建立更明确的重写意图模型。
- 增加脚本页快捷重写 UI。
- 保存版本并支持对比。

第二阶段：2.1B 字幕编辑器

- 建立 SubtitleTrack 结构。
- 增加字幕编辑 UI。
- 支持导出更新后的字幕资源。

第三阶段：2.1C 封面编辑器

- 建立 CoverDraft 结构。
- 增加封面字段编辑和模板预览。
- 写入草稿素材包 manifest。

第四阶段：2.2 AgentQualityGate

- 为选题、脚本、剪辑计划、草稿前检查提供质量评分。
- 提供一键接受推荐。

第五阶段：2.3 PerformanceInsights

- 录入发布数据。
- 聚合表现洞察。
- 把已确认洞察进入 prompt context。

第六阶段：2.4 ContentCalendar

- 7 天内容队列。
- 今日工作台接入。

第七阶段：2.5 VoiceCommandRouter 增强

- 语音修改脚本、字幕、剪辑、反馈、日历。
- 统一操作草案和历史。

## 9. 不做什么

2.1-2.5 不做：

- 多用户 SaaS。
- 自动发布到平台。
- 完整移动端剪辑。
- 任意自由度的视频编辑器。
- 云端素材库。
- 完全跳过人工确认的无人值守 Agent。
- 让单条数据表现自动决定后续内容方向。

## 10. 成功标准

### 10.1 用户收益

- 从选题到剪映草稿的人工操作时间下降。
- 脚本、字幕、封面的返工次数下降。
- 用户每天需要做的决策更少，但仍能掌控关键判断。

### 10.2 产品收益

- 每条内容都有可追踪状态和下一步动作。
- 每次 AI 修改都有版本、理由和回滚路径。
- 发布反馈能形成可解释洞察，而不是只保存数字。

### 10.3 工程收益

- 新功能按模块独立接入。
- 不再把新增业务堆进 `main.py` 或单个大组件。
- 每个模块都有契约测试和核心业务测试。

## 11. 首个实施切片建议

首个切片建议做 `2.1A 脚本快捷重写`。

理由：

- 风险低，不涉及视频重编码和剪映结构。
- 用户价值直接，能明显减少脚本打磨时间。
- 可以复用现有段落重写和版本机制。
- 能为后续语音指令、质量检查和偏好学习打基础。

建议验收：

- 脚本页每个段落提供 5 个快捷重写意图。
- 用户点击后生成重写草案，不覆盖原文。
- 用户确认后保存新版本。
- 用户驳回后保留操作历史。
- 重写 prompt 注入内容模板、创作者画像、相关偏好和当前段落上下文。
