# Agent 能力吸收记录（2026-11-13）

这份记录把 Pi Agent 调研意见转换为当前产品可执行的边界。调研结论主要来自运行时、工具目录和契约测试；真实模型、真实设备和完整生产仍需单独验收。

## 已吸收

- Agent 可通过 `read_material_governance` 读取一条素材的分析运行、EvidenceRef、候选/确认断言、索引新鲜度、质量档案、片段血缘和索引重建状态。
- `read_material_evidence` 继续提供有界的源时间证据；治理回执只解释依据，不自动授予采用权限。
- 工具目录把治理读取能力放入首页、素材和任务编辑场景，系统提示明确要求区分 `candidate`、`stale` 和 `unavailable`。
- 模板检索回带引擎和 provenance 摘要，Agent 只能使用本轮真实读取的模板版本。
- 新增 `read_editing_resource_catalog`：把底部资源分类映射到当前真实入口，明确 `connected`、`catalog_only` 和 `planned`，避免把目录名称当成已安装能力。
- 新增 `read_agent_run_trace`：按当前回合读取脱敏的工具结果、失败分类、上下文压缩和供应商真实用量；没有回执时保持 `usage_status=unknown`。

## 仍按阶段建设

1. 把会话、回合、工具调用、业务请求和后台作业继续关联到同一条可脱敏的诊断链；当前回合已经可以读取持久化追踪，跨 Job 的长期账本仍待补齐。
2. 把已有 provider usage 投影沉淀为长期用量账本；当前读面只汇总已持久化的真实回执，没有供应商回执时保持未知，不估算成本。
3. 用真实任务回放评估目标理解、工具选择、失败恢复、未知结果和最终状态，不能用单个模型回复作为通过条件。
4. 在单 Agent Harness 稳定后，再引入只读的证据侦察、脚本审查、视觉审查和音频审查子 Agent；子 Agent 只返回结构化候选，主 Agent 是唯一采用者。

## 明确不吸收

- 不复制 Pi 官方示例里的第二套 Agent/Harness。
- 不把桌面打包或混淆当作源码保密方案。
- 不把 Worker 文件存在、模板列表存在或静态测试通过说成真实模型或真实成片验收。
