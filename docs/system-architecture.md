# 系统架构

本文件定义 AI 视频日记的运行模块、跨进程责任、外部能力适配和关键数据流。产品范围见 product-requirements.md，领域对象与状态见 domain-model.md。

## 1. 架构目标

工程结构约束由 [AGENTS.md 第1.1节](../AGENTS.md#11-高内聚低耦合与代码拆分)拥有；本文件拥有具体模块责任与数据流。短期重构实施范围通过活动合同定位，工作方案不替代本文的活动边界。

系统围绕一个 Workspace 和一条 CreationTask 事实链运行，满足：

- 本地优先，网络能力可插拔；
- 原始资产不可变，派生产物可追溯；
- 自然语言与精确编辑共享同一领域操作；
- 局部编辑按依赖图增量重算；
- 模型可以更换，领域状态不依赖供应商；
- 进程中断后任务可恢复；
- 不可用能力诚实失败，不使用隐藏 fallback；
- Web 不能绕过桌面权限提交任意本地路径。

### 1.1 稳定规则与变化边界

领域层拥有作品目标、来源、版本、采用/授权、依赖和实际用量等稳定语义，不依赖具体模型、帧率、HTTP、Pi或设备型号。业务用例组织这些规则和跨对象事务；仓储负责唯一持久事实，执行端口声明有限输入、结果、取消及恢复语义。

Agent依据目标、证据和可用能力决定叙事结构、素材选择、步骤分解、修订和方法组合；这些决策不固化成通用段数、固定阶段顺序或模板默认硬门。模型供应商、编码方案、插件、平台采样、设备执行档及调度参数属于变化层，经适配和组装注入，不能反向成为领域合法值。具体实现仍须满足共同端口的真实结果、版本、授权与恢复要求。

必要的协议/格式常量可保留在其实际owner；工程默认值说明用途、来源和可调整范围，不为每个数字新增配置。设备档区分已观测、保守估计与未验证，输入批量、临时空间和运行时限不直接等于作品规模。新增抽象以真实替换点或变化原因成立，不仅为搬文件或消除字面数字。

## 2. 运行拓扑

### 2.1 Desktop Shell

Electron 桌面壳负责：

- 应用生命周期和窗口；
- 选择文件、选择目录和保存成片的原生对话框；
- 把用户选择转换为受控文件句柄或工作区引用；
- 启动、监督和终止 API、Worker 及必要的本地模型进程；
- 安全存储 API 密钥和平台凭据；
- 打开文件、播放器和系统通知；
- 退出时清理子进程、端口和临时资源。

桌面壳不实现产品领域规则，也不接受 Renderer 提交任意源绝对路径。后台HTTP网页服务使用Electron utility process，不以主GUI可执行文件的Node模式重复登记为前台应用；仅主窗口拥有Dock/激活身份。API与模型子进程仍受原生命周期与资源协调者管理，失败由主应用呈现，退出必须回收服务与端口。

正常退出沿现有服务监督器、设备运行时与执行上下文传递停止：停止派发，通知所有在途执行器，回收其登记进程组并原子保存中断/有效检查点，再关闭API及其传输。桌面等待与API收尾使用同一有界协议，不各自设互相冲突的强杀窗口；超期升级终止保留真实信号和未确认释放状态。退出原因从执行上下文传至模型适配器和业务回执，不被非零返回码统一覆盖成供应商失败。默认用户行为见[产品§12.1](product-requirements.md#121-同一台主机的任务安排011)。

原生媒体控件会先于页面消费 Escape。Renderer 仅在顶层对象卡片内的 video/audio 获得焦点且未全屏时登记当前卡片 ID；桌面壳只接受当前窗口的登记，在前置键盘事件中转发一次并阻止同一 DOM 按键重复处理。Renderer 再检查顶层 ID、实际媒体焦点与全屏状态，沿原卡片关闭及还焦流程执行；换焦、全屏、关闭和页面重载取消登记，视频全屏保留默认 Escape 退出行为。

### 2.2 Web Renderer

Web 负责用户界面和短生命周期交互状态：

- 首页目标与预检；
- 素材、内容、人物声音、模板和自动任务管理；
- CreationTask 阶段工作区；
- 播放器、时间线、字幕和属性检查器；
- 自然语言直接编辑、必要提案选择、精确草稿编辑、撤销和重做；
- 运行状态、阻断原因和修复动作。

Web 不把 localStorage、React state 或聊天消息当作业务事实源。

### 2.3 API

API 是同步领域入口，负责：

- Workspace 和对象权限校验；
- Knowledge、Source、Media、Profile、Plan、CreationTask、Template 和 Automation 的仓储访问；
- 命令校验和状态转换；
- 自然语言意图的上下文组装与类型化提案；
- 明确自然语言、精确命令或必要提案采用后写入 EditOperation 和 TimelineVersion；
- 能力状态、失败证据和修复动作；
- 向 Worker 提交可恢复作业。

API 不执行长时间媒体渲染，也不建立 Episode、Batch 或内存 fallback。

### 2.4 Worker

Worker 执行可恢复的长任务：

- 来源抓取和内容解析；
- 视频转写、分镜和多模态分析；
- 选题、文案、配音、口型、字幕和封面生成；
- 时间线预览、增量渲染和最终编码；
- 平台发布和数据拉取；
- 失败重试、进度和产物登记。

每个作业必须幂等或带明确的重试边界，并把状态、失败原因和产物引用持久化。

### 2.5 Local Model Runtimes

语音、转写、视觉、向量或其他本地模型可以是独立进程。Supervisor 负责：

- 启动和健康检查；
- 模型文件和运行环境检测；
- 并发、显存或内存限制；
- 标准化能力状态；
- 进程退出和资源清理。

本地多模态采用媒体工具与本地模型分工：媒体探测/切点/波形、语音转写、OCR、按时间采样的视觉理解分别形成带来源的结果。按片段增量分析，限制输入帧数、分辨率和上下文；重计算任务统一经过第3.12节的整机准入，不能各服务自行放行。模型文件大小不等于运行峰值内存，选型须通过目标设备实测。调度仅服务本机现有任务，不引入分布式集群或通用平台。

语音转写默认选择本地 Whisper。云端转写仅在用户主动选择对应供应商后执行；保存云端凭据不改变默认路由，失败不跨供应商回退。设置、预检与执行使用同一选择，语言未指定时自动检测。

0.11 的本地 4B 视觉模型仅在后台素材分析链路运行。用户对话和文字创作由外部文字模型驱动，使用独立配置与运行状态；后台模型不可因对话配置变化而改变路由。对话 Agent 使用 Pi 的会话与工具调用机制，通过受控业务工具读取当前 Workspace 的资料、素材和任务，生成 Plan、Script 或 EditProposal，并按[产品第4.2节](product-requirements.md#42-对话与操作习惯)的委托与采用规则推进已有 CreationTask。Pi 会话不是新的生产事实源，不能从模型回复推断用户授权。外部请求只携带本次任务所需的文字上下文和筛选证据，不上传原始媒体，供应商失败须显式报告而不自动切换。

## 3. 核心服务

### 3.1 ProductionRepository

ProductionRepository 是 CreationRequest、Plan、CreationTask、Script、Narration、Timeline、Output 和任务事件的唯一持久化入口。旧 Episode、Batch、repo.today 或模板成功 fallback 不得进入新写链路。

### 3.2 ContentRepository

管理 KnowledgeItem、SourceConnector、SourceItem、内容版本和 ContentUseState。知识库与信息源可以共享检索基础设施，但必须保留不同来源语义。

### 3.3 MediaRepository

管理 MediaAsset、Clip、标签、分析结果、代理文件和 UsageRecord。文件系统路径只在受信任的本地进程中解析，对 Web 和领域层暴露逻辑引用。

### 3.4 ProfileRepository

管理 PersonProfile、VoiceProfile、PronunciationEntry 和版本。用户导入的档案默认可在当前 Workspace 使用；能力是否可执行由对应模型和运行环境单独决定。

### 3.5 AssetIntelligenceService

把长视频和多模态内容转化为可检索生产单元：

- 转写、说话人和静音识别；
- 镜头边界和关键帧；
- 人物、产品、场景、动作、物体、屏幕内容和文字；
- 质量、画幅、安全裁切和可复用性；
- 索引、标签、缺口和低置信复核。

分析结果写入 MediaRepository，不能只存在于模型响应或缓存。描述、OCR、转写和推断保留时间锚点与分析版本；抽帧平均向量不能替代动作顺序理解。缓存按源内容、时间区间、模型及分析参数识别；用户纠正与模型结果分开保存。

后台素材接收绑定用户已选择目录和明确 Workspace；全局路径不得自动复制到所有工作区。发现完整新文件后排队分析，周期补扫和重启恢复复用同一资产状态，避免重复分析；复制中的文件、路径越界、缺盘和模型不可用须显式处理。接收与分析不创建 CreationTask，不覆盖原始媒体。资源调度不得因每次扫描重复加载模型或并行写同一资产。

VLM输出保留观察定位、采样覆盖和未知；Pi据当前问题沿同一分析入口请求局部补充，按输入/分析版本复用结果，不重分析整库。企业含义与创作用途由[领域§3.4](domain-model.md#34-businessobject-与素材关联)分别记录。模型是否适用及是否微调按[产品第7节](product-requirements.md#7-素材智能)的真实样本口径，不以参数规模或向量相似度代替业务确认。

### 3.6 RetrievalService

按任务规模组合：

- 结构化字段和全文检索；
- 时间范围、标签和来源过滤；
- 可选向量索引和语义重排；
- Workspace、ContentUseState 和任务上下文约束。

小规模数据不强制依赖向量模型；启用向量检索时，索引必须可以从权威内容重建。检索先应用内容使用限制，再组合文字/视觉召回；仅对候选执行必要重排。分别评估召回遗漏、排序错误和库内缺失，不把不可校准的相似度显示为准确概率；索引不可用或降级必须可见。

知识正文、表格/结构定位、可复用文案分别沿所属仓储生成版本化分块；文本向量与视觉片段向量按模型/索引版本隔离，不能混用维度或相似分数。精确字段与关键词召回保护型号、数字和单位，语义召回补同义与跨语言需求；结果返回来源片段和可解释依据，不直接变为创作事实。资料导入覆盖范围由产品第6.1节拥有，解析失败不得进入已完成索引。

视频复用现有原片/片段、语音、OCR、画面观察及视觉特征；用户搜索、Agent候选和故事板统一使用可核对的候选及用途规则。结构条件回退只表示弱候选，不能自动满足事实性镜头需求。人工纠正、内容修订、撤权和删除使索引重新核验或失效，缓存不扩大权限；重新分析保留人工事实。缺模型时保留实际可用的文字检索并说明范围。先测真实召回与设备成本，再选索引实现，不预设远程向量数据库或复制资料事实源。

候选沿既有引用携带来源类型、对象/内容版本、原文定位或源时间区间及匹配依据；采用用例核对当前产品/型号、数值单位与画面用途，不把排序分数转换为事实。资料与作品的影响回查复用已有来源和使用关系，不另建知识事实副本；固定采用版本与后续新检索分开处理。

### 3.7 PlanCompiler

把用户目标、模板和当前能力编译为 Plan：

- 读取可用内容、素材、人物声音和模型状态；
- 形成内容、视觉、声音、字幕、封面和平台策略；
- 标记确认节点、缺失条件和可执行步骤；
- 依本次明确委托或人工采用判断可执行范围；未获相应授权不启动有成本或外部副作用的作业，不给已委托的中间方案额外套人工确认。

自然语言新建请求先固定数量、关系、素材范围和实际用户要求，缺少关键决定时输出澄清。总目标由ProductionRepository持久化；有限规划窗口沿同一事务展开独立子任务，以请求/窗口身份及输入摘要幂等重放。分页和实际状态聚合不随目标总数一次加载全部内容；每条复用现有制作、版本、调度与授权链，汇总只读取真实子任务。客户端、Pi和手动入口共享这一数量与授权/采用语义，不保留写死单条的旁路。

PlanCompiler 的输出是领域对象，不是聊天回答。

方案读取、要求修订、重规划、采用分别复用现有CreationRequest用例和仓储。工具传入新goals时必须实际编译并保存；遇到已有proposed窗口不能直接确认旧内容。采用前比较依赖摘要并重新核验当前授权，冲突回执包含安全错误码、对象/期望与当前版本及具体修复动作；依赖摘要限定为实际采用输入与相关能力，不将整库枚举、无关模型诊断文案作为作品版本。仍需核验所选资源失效、撤权及当前执行条件。

### 3.7.1 长内容的有界执行

30秒、30分钟和3000分钟共享“理解目标→拆解可执行单元→按依赖执行与检查→组合交付”的流程，不设短片专用直通路径和另一套长片引擎，也不固定切成30分钟作品。Agent决定内容结构、候选与修订；程序保存单元结果、依赖和恢复位置，并约束实际执行。单元按职责和资源划分，资料检索、文案、配音、镜头处理与最终组装不必使用相同时长或相同粒度。

规模约束分属内容要求、接口传输窗口、模型调用能力、设备执行单元、累计授权额度和系统保护，分别由实际事实源拥有。任何执行上限必须带明适用用途/单位、来源及验证范围；实验启动配置不是已标定生产能力。Agent读取可用能力与具体拒绝原因，在既定授权内调整执行分解，不能写入自己的安全许可。累计额度绑定实际授权范围：一个总目标可以覆盖多条交付、多个Job及重试；任务独立额度则绑定该任务。范围身份、额度修订与实际用量沿既有Repository事务持久保存，Job和执行单元引用该范围，不各自复制一份完整额度，也不通过换Job重置已用量。同一范围在同一事务内校验剩余额度并预留在途消耗，完成后按实际结算；未知消耗保留占用并先对账，可证明未消耗的预留才释放，避免多Job并发读取同一余额后各自花费。未设本地累计额度仍记实际消耗，不能凭空生成时长/字节作品总帽；单元保护独立生效。历史请求和已结算用量不改写，后续额度调整必须绑定原范围、当前修订和真实授权，不将旧实验额度永久化。仅将常量搬到环境变量、把阈值调大或保留新旧双旁路不算完成治理。

总目标时长不转换成单次LLM上下文、整段音频驻留或一个无检查点的长进程。沿现有ScriptSegment、NarrationSegment、Job、Artifact、DependencyEdge和DeviceScheduler按语义段/章节安排有界单元；分段大小由能力实测与转场、连续音轨等依赖共同决定，不新增通用分片调度器。每个单元明确输入/依赖版本、完成结果及查询身份，先保存实际成果再推进下游；结果未知先对账，不直接重复副作用。媒体段以实际输入摘要、全片时间区间、模型/后端和参数版本定位复用结果；已验证有效段在退出恢复后不重做，过期/撤权段不能复用。

对未发布工作文件的分步追加须使用明确的专用执行契约，不冒充其他后端能力。宿主从原Job检查点绑定独占文件身份、已提交区间及内容摘要，模型不能自报计费基线；准入仍声明完整实际输入，累计计量本次真实新增数据及重写元数据，已结算消耗不退款。绝对文件大小、磁盘、内存、时间与进程保护独立保持，不能统一减去旧文件大小后检查。许可复核区分允许的尾部增长与禁止的前缀变更；原开始记录、文件、结算或最终发布登记不能对账时保持未知，不截尾重跑。部分文件不可作为完成Artifact；文件发布和登记的中断沿同一原请求恢复。

统一全片帧/采样时基，组装校验时长、顺序、字幕偏移、音画连续和跨段重叠；关键帧/编码条件不满足时执行必要的边界重算或重新编码，不盲目无损拼接。预览按播放范围准备代理/缓存，UI与Agent分页读取时间线和证据，不能一次把长作品全部事件/波形/全文送入模型或渲染到页面。

调度候选读取与昂贵核验同样有界，按既有优先级、公平性和可续读位置逐批推进；不能把全片所有分段一次展开成待运行队列，再在每次授予前逐条远程核验。移出写事务解决编辑阻塞，不等于解决随队列长度增长的调度成本。长内容验收须分别量测候选数、每轮核验次数和等待时间，保留取消、撤权及最终候选新鲜核验。

每单元预算覆盖加载峰值、执行、子进程和临时空间；整片开始前估算输出与中间产物空间，运行中按实际消耗核验。有限缓存只清理可重建且归属明确的临时产物，不能删除源文件或撤销所需证据。取消/压力保护在安全点结算检查点，恢复通过既有请求、许可与产物对账；媒体任务不依赖聊天轮次存活。扩展到30分钟/50小时须分别证明流式读写、段恢复、局部修改、组装与磁盘限制；静态结构或短片通过不是长视频验收。

### 3.8 EditCompiler

把自然语言与当前任务上下文编译为 EditIntent、EditProposal 和类型化 EditOperation：

1. Web 发送命令、当前阶段、选中对象和播放位置。
2. API 从 ProductionRepository 读取权威任务和时间线版本。
3. 文字模型只负责理解意图、补全约束和生成候选提案。
4. EditCompiler 校验范围、对象类型、ContentUseState、能力和副作用。
5. 按产品确认策略区分明确指令与待决定动作；前者直接提交，后者展示对象、范围、差异和必要决定。
6. API 从实际用户指令/确认取得业务授权，写入 EditOperation 和新 TimelineVersion；Web 回读实际差异，CreationTask 指向新版本。
7. 更新依赖有效性；媒体作业由明确生成动作或已经授权的制作目标后续调度触发，普通编辑本身不新增生成授权，也不取消后者。普通编辑的交互规则引用[产品规则](product-requirements.md#23-自然语言与精确编辑共享同一事实源)。

当前操作目标与已引用资料分别维护；明确选择任务对象不能被旧素材引用暗中改成素材轮次。每轮提供与实际注册工具一致的能力和当前目标，历史工具失败不定义当前能力。原句、任务、阶段及界面默认选择由宿主绑定；模型只选择当前实际候选，不能重写这些身份事实。用户明确的镜头序号在当前任务版本中解析，不要求先多选界面对象。自动选材在有限候选截取前应用使用限制和实际源时长要求，提交时重新核验。

模型可读取业务能力目录及输入/输出 schema，提交类型化编辑候选；阶段只提供默认能力分组，不代替对象权限或执行前置检查。手动编辑、内置 Pi 和外部 CLI/MCP 复用同一动作校验与持久回执；外部入口由可信成员与请求身份绑定来源，不伪造应用助手轮次。原句作为来源保存，不要求模型把所有动作重新转换成固定自然语言语法。

可写对象必须能在当前版本中被发现：镜头、字幕、配音、音轨片段、已采用图层分别提供实际 ID、修订、单位、关系与必要样式。首页摘要可截断，按 ID 与分页读取必须从完整已授权集合取数，返回真实总数与截断信息，不能对先截断的摘要再分页。已有业务动作只有接入共同目录、对象读面和真实执行入口后才向 Agent 声明可用；schema 枚举项、手工按钮或历史回执不单独构成可调用能力。

模型可在受控编排环境中编写程序组合已有业务工具；工具子调用仍经过原成员、版本、用途及许可校验。媒体脚本须封存代码、参数、输入修订、工具链及摘要，通过既有业务 Owner 和唯一设备协调者在具备实证文件/网络隔离的执行环境中运行；资源许可不等于文件或网络隔离。脚本只能读取本作业授权输入、写入本作业输出，其产物经实测、来源登记与类型化提案进入同一版本链。短预览、正式生成与后台用途沿各自工作类别，不让全部脚本占预览优先级。

Codemode 中的图片来源、配方读取和媒体作业工具返回结构化对象，可直接读取 `items`、`media_job` 等字段；CLI 标准输出则是供外部调用方解析的 JSON 文本。明确工具 ID 的只读 describe 可直接调用共同 API，由服务端核验当前成员权限，不要求先列举；调用、更新和停用仍核验实际版本与当前授权。

Python/Pillow 程序的 `parameters` 是参数对象，`inputs[声明名称]` 与 `outputs[声明名称]` 是宿主绑定的可信文件路径。程序使用 `Image.open(inputs["input.png"])` 读取、`image.save(outputs["panel.png"])` 写入；不能把输出映射项替换成图片字节或 `BytesIO`。首包仅支持当前任务登记的 PNG 输入和单 PNG 输出，字段与命令示例见[CLI 协议](cli.md#pythonpillow-图片来源程序)。

成功 PNG 来源须另经现有图片图层操作登记到时间线；直接保存与必要提案的采用按[产品第4.2节](product-requirements.md#42-对话与操作习惯)执行。预览和正式渲染共同读取授权来源事实，声明实际输入字节、尺寸和图层数；获得设备许可后复核文件摘要、PNG 内容及修订，并记录渲染依赖。脚本作业成功、图层已采用和成片已生成是不同回执，不能互相替代。

可信宿主可注册隔离脚本的版本化工具代理；模型生成的扩展代码不直接加载到持有凭据的宿主进程。模型不得通过任意文件、Shell、数据库写入或自报许可绕过上述执行入口；未具备运行时、隔离、资源档或有效产物契约的能力明确不可执行。新持久字段与渲染语义通过正常源码实现和验证，不由扩展声明自动增加。

### 3.9 DependencyGraphService

维护 ScriptSegment、NarrationSegment、SubtitleCue、TimelineItem、PreviewOutput 和 FinalOutput 的依赖。

每次编辑计算：

- 直接变更对象；
- 需要失效的下游节点；
- 可以保持 valid 的已确认产物；
- 需要重新预览或最终渲染的范围。

Worker 只处理 invalidated 节点。输入摘要未变的 valid 产物可以复用。

局部重算的验收须比较实际受影响集、执行作业与产物摘要，证明未受影响段没有再次执行；最终整片编码或拼接单独记录。来源谱系登记、整阶段缓存及完整输出复用不能替代这一证明。

派生产物的复用身份覆盖实际源版本/区间、制作参数、模型/后端版本及相关上游摘要，不能只用镜头id或文件名。重算前复核内容使用状态与文件有效性；命中缓存不绕过撤权、缺文件或旧输入检查。时长变化、跨段字幕、转场重叠及连续音轨按真实依赖扩展失效范围；仅在编码与时基条件满足时复用拼接，不将所有修改机械编译为ffconcat。沿既有编辑回执、作业和产物记录关联原/新时间线、直接变化、失效/复用对象及实际执行范围，不新增第二套缓存事实源或通用调度层。

### 3.10 QualityEvaluationService

在预览和输出阶段执行可解释检查：

- 音视频流、时长和文件完整性；
- 音量、静音、字幕时间和遮挡；
- 画幅、安全区、裁切和平台规格；
- 文案事实来源、重复、节奏和语言一致性；
- 模型或媒体能力不可用；
- 用户偏好与模板约束。

检查结果绑定被观察的实际版本与输出摘要，包含检查范围、片段/时间、依据、可执行修复和 unavailable；过期结果只能回读历史。确定性检查与语义判断分别返回，不把已知静态标题卡、无声片等用户要求直接判为失败。Agent 通过共同 API 读取检查事实；观察成片使用实际预览/输出的有限抽样，来源素材分析不代替合成画面检查。媒体访问和外发沿第 7 节及认证边界，观察工具不获得上传原媒体或扩大授权的旁路。

读取当前任务和观察刚生成的产物不重绑定本轮编辑选择。观察请求独立封存实际当前版本，由所属用例在提交与执行时复核；后续编辑仍遵守原选择与版本校验。

文案核查已获得的有效问题应在既有数量上限内完整返回，不能只保留首项让修订反复揭露遗漏问题。每项包含本次送审稿的字段、段/片段位置、摘要和有界核查依据；模型生成的说明是待核对的数据，不是新的用户要求或工具指令，经凭据/路径清理后供修订核对。无效引用、摘要不匹配和原始上游响应不得混入有效回执；回执完整不等于放宽内容核查。

核查报告的 `issues`、`reference_ids` 若以字符串返回，只允许在该已知字段进行一次严格 JSON 解码，且整个值解码结果必须是数组；拒绝重复对象键和非标准数值。不得截取 Markdown、递归解码、把普通文字猜成数组或将任意字符串清空。解码仅消除传输表示差异，原问题类型、定位、解释、资料范围和有效内容不变；随后仍执行完整的结构、覆盖、引用及事实/要求校验。不能无损解码或校验失败时明确拒绝，保留原任务和草稿及安全的类型诊断，不再为这两类字符串类型错误追加模型格式修复请求。内容确有问题时，Agent仍沿原错误回执自主修订，不与协议错误混用。

核查对象是实际事实断言与明确要求，不要求每段必须包含事实。报告覆盖全部送审字段/段落，并明确区分有支持的事实、无据或冲突事实、没有可核实事实断言的内容；纯提问、修辞或转场可以合法，但须说明核查对象和理由，不能用一个“无需证据”标记代替核查。事实支持须绑定本次文本和合法来源，无据断言不得伪造支持引用。要求冲突独立核验，不因段内没有事实而忽略；报告仍严格校验结构、完整覆盖、唯一性、版本摘要和引用，缺段、格式错误或未知不能当通过。

文案核查作用域为当前任务的一条交付，语言、时长等取已采用的本条要求；父请求的多语言、多条数量仍保留为来源，但不要求每条稿件独自完成整组交付。画面描述在此阶段是待执行计划，可安排角标、署名及字幕，不能因实际图层尚未生成而判定文案违规；成片是否真正实现由后续实际输出核验。事实支持、固定正文、当前语言和明确用户约束继续核查，不将计划或核查器自行补充的要求当作事实或授权。核查报告的生成契约须表达实际段数、当前段的候选片段和该段允许的证据引用，服务端仍独立验证完整覆盖、唯一性和真实绑定，不自动猜配错误引用。

观察先读取带时间位置的转写、镜头摘要及相关事实，按当前疑问请求有限范围的帧序列、波形或音频检查；无对白与动作顺序不能只靠文本判断。抽样优先覆盖实际修改范围、剪辑/转场边界、字幕和声画衔接；结果说明已检查与未覆盖范围，不从少量抽帧外推全片质量。粗剪展示与检查执行解耦，失败定位到版本和对象，已有播放能力不等待主观检查完成。

确定性成片检查必须覆盖交付所需的完整文件身份、解码及PCM和帧数据判据；全片覆盖是验收要求，不强制所有计算放在一次许可中。按后端实际能力流式读取或分范围执行，记录版本、区间、检查方法和检查点，汇总须证明无遗漏且跨段连续；分片摘要不能冒充最终文件SHA。不能持久恢复的步骤如实声明重启代价，不能只因采用流式算法就声称可恢复。检查沿独立受许可执行单元运行；检查进程与原生子进程共同计入实测资源和退出边界，不占用已结束的渲染许可。结果读取只使用已完成校验的版本、登记摘要与文件身份回执；文件身份变化、缺失、未知或旧记录没有回执时，当前结果必须标为过期并要求重新检查，不以元数据冒充一次新的内容校验。同内容文件被重写也保守地要求重查，内容不匹配的完整校验失败在异步检查结果中返回。回执为内部事实，不扩展普通界面字段；旧版本检查可完成其历史记录，但不得替换另一check_id的当前结果。

自动评分提供可核对的问题和建议，不冒充用户的主观满意。已委托制作可按目标自主修订和交付，不为每条成片新增人工批准门；用户主观接受、必要澄清和外部发布授权分别处理。

### 3.11 PreferenceService

从用户明确选择、接受、撤销和模板保存中提取可解释偏好。偏好用于排序和默认值，不能静默覆盖 ContentUseState、事实来源或外部副作用确认。

### 3.12 整机资源调度

桌面自动化由同一API启动和关闭低负载到期扫描器，以持久Automation/AutomationRun及唯一到期键认领运行；不启动旧Episode循环或第二个媒体执行器。扫描器保存每次固定输入并调用已有来源、预检和生产入口；当前授权、确认或能力不满足时记录该运行的等待/阻断。媒体工作只交给下述唯一设备协调者，重启回读已有作业与输出。自动化定义、运行、确认及暂停入口仍核验原工作区和服务端成员；无令牌身份快照不提供持续授权。

产品策略的唯一来源是[产品需求第12.1节](product-requirements.md#121-同一台主机的任务安排011)。由单一设备级协调者统一受理全部本地重型调用，包括素材自动/手动分析、配音/声音预览、口型、代理生成、剪辑预览、整片渲染和仍保留的单步重做入口。线程池只负责执行，不能作为另一份排队或许可事实源。所选任务配音片段重做仍由现有creation_job业务Owner受理独立narration_edit单元，使用对应配音资源预算与当前任务局部预览分类，不能借用人物编辑许可。排队保留当前时间线和原声音；只有受许可生成成功、输入版本仍一致且检查点提交后才更新版本与下游依赖。外部文字请求使用独立限额；等待网络结果时不占本地重活许可，客户自备模型连接按[产品第2.6节](product-requirements.md#26-本地优先与用户控制)处理。

- 重活先提交持久化请求，再由协调者准入；包含服务端确定的workspace/member、已有作业/素材引用、输入版本摘要、执行类别、时间策略、依赖、资源需求及检查点。复用已有JobRun/TaskEvent、素材处理记录和Repository事务入口，不复制业务任务或建立并行成片状态机。
- 准入区分动态资源等待与固定输入/执行档拒绝：同一输入及资源档下已确定的超限不能伪装成 `resource_busy` 无限重排。沿原请求/作业持久化一次具体原因、输入摘要、超限字段实际值和上限，供Agent读取后选择合法修订或能力准备；没有输入/能力依据变化不能自动重试。等待不创建新的作业或丢失已完成单元，拒绝也不抹掉原请求的回执。
- 许可是全机共享额度；不能只用各进程的Semaphore或各模块单线程。单个本地协调者串行决定准入，并对重启、重复进程和租约失效作恢复校验；旧进程/子进程仍活着时不能仅因租约超时再次发放同一硬件额度。恢复先核实并回收/接管旧执行，未知时阻断相关重活。
- 授予许可后、执行器启动前重新核验发现固定输入明确过期，仍不得执行。确认该许可的子进程和常驻资源已释放后，复用原事务将该请求阻断为input_stale并归还许可，让其他有效请求继续；正常编辑竞态不能升级为整机永久停止。许可归属或持有记录不一致、缺少有效任务授权、业务输入事实未知、进程或资源释放未知仍保留核查边界；云端核验暂未知按认证§5判断，不抹掉有效任务授权。不以宽泛捕获异常、直改ledger、跳过版本检查或重启替代收尾。
- 调度扫描先用可信本地封存输入拒绝已明确过期的预览请求，避免为不可能执行的旧请求在SQLite写事务内重复等待远端身份核验、阻塞前台编辑。提前拒绝不能授予执行权限；仍可能有效的请求继续核验有效任务授权、版本和依赖，授权机制沿[认证§5](auth-workspace-boundary.md#5-后台任务)，不以通用成员缓存或延长数据库超时掩盖竞争。
- 进程监督只消费本地许可、有效任务授权和资源事实，远程授权观察/续期经既有运行时异步进行，不能阻塞管道消费、取消和资源采样。明确撤权、授权过期、暂时未知及资源不足分别投影到既有等待/中断路径；不将所有PermissionError映射成短间隔重启。恢复先核就绪条件，再派发重活，保留原请求/检查点。任务授权与全机资源许可职责不同，不能相互替代。
- 统一入口覆盖手动、定时、Agent工具及重试调用；嵌套阶段复用同一个执行上下文，避免持许可的父任务再次等待子任务许可而死锁。父CreationTask不跨整个流水线占许可；每个耗资源单元完成后归还，并重新公平排队。
- 文件发现和小批数据库更新单独限速。全文件哈希、解码、代理生成、转写和模型推理属于需预算的工作，不能把高磁盘读写藏在“轻量扫描”中。稳定文件登记与深度分析分开，部分分析状态不能冒充完整ready。
- 资源尚未获准的文件不得批量标为正在分析；只认领实际即将执行的单元，或把已预取但未开始的记录明确归回等待。素材的场景检测、转写、视觉批次和向量批次分别保存有效阶段结果；整个文件末尾一次写入不能满足中途让出恢复要求。分段大小须实测，所有子进程至少有有限超时与清理路径，不能在超时后放任其继续持有设备资源。
- 模型常驻占用纳入内存/显存预算；归还执行许可不等于内存已释放。复用已加载模型不能覆盖公平性，不能为少一次加载让同一用户无限连做。CPU线程、FFmpeg解码/编码参数、帧批量、缓存及IO预算使用设备配置；禁止拿一个未经验证的固定CPU百分比作为所有硬件上的性能保证。
- CPU准入与运行保护分开：准入核当前整机负载；一分钟历史load average只作诊断，不能在已取得设备许可后由声明字段检查器再以它否决编码；已获许可的不可分单元，不能仅因整机占用百分比越线就反复杀死并从头加载。Mac本地配音保留已验证的Darwin后台调度；用户主动的纯素材CPU成片使用显式正nice优先级并确认未处于Darwin BG，降低CPU竞争优先级但不强制后台磁盘/网络IO节流。Darwin BG的IO节流语义见[Apple setpriority说明](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/setpriority.2.html)，不能把它仅解释为CPU让步。两者都须在受许可启动器exec前设置并由自身回读，验证exec及子孙继承；设置或核验失败时不执行重任务。优先级值由目标机器和固定工作量实测，不宣称CPU百分比或MLX线程硬上限。原生严重内存压力、系统余量、进程/线程、IO、磁盘、取消及总时限仍独立即时保护；后续单元重新准入，不能无限延长已有许可。累计CPU端点、实际跨度及进程组归因用于诊断和实机评估；缺失/停滞计数标unknown，不能补零或将未知当作系统空闲。各执行类别的调度策略须以同候选真实任务、有效进展和前台输入/播放连续性验证，单次参数设置成功不等于效果通过。Windows与其他执行类别按其平台和已验证适配处理，不借Mac状态冒充已支持。
- 配音的启动准入预留预计新增峰值内存与系统安全余量；进入受许可运行后，按系统安全余量、实际进程占用及下述平台压力策略持续检查，已分配给本次配音的内存不再作为整份新增可用内存重复要求。模型加载与推理均属于同一受许可单元，实际磁盘读取受统一IO观测和进程优先级约束；额外完整预读不作为加载器限速证明。有限超时覆盖启动、加载、推理和输出，预算依据目标设备与固定输入的完整实测确定。
- CPU成片区分启动预留与运行占用：启动保留适用设备档的新增加载峰值及系统余量；运行检查实际安全余量、已核身份进程占用、总线程、平台压力及有效CPU/IO预算。已分配给本阶段的内存不得再作为整份新增可用内存重复要求；进程运行上限与启动预留分别由适用档说明，二者单位相同不代表含义相同。总线程不能拿单个编码器的`threads`参数冒充，缺少真实进程边界时不可放行。执行器按输入和能力限制并行解码，临时中间片、字幕、混音和发布重叠均计入实际存活文件与资源预算，不静默牺牲指定输出质量。中间编码、像素格式、帧率和最终编码由所选执行档及交付要求决定；跨段时基、色彩/画幅兼容及绝对边界帧数必须核验，避免无依据的重复有损压缩。当前后端实现由`montage.py`及其渲染契约拥有，不把其中NUT/FFV1、30fps或H.264/AAC选择变成所有作品的领域限制。内部格式不扩大外部输入接受范围；原始帧载荷只用于工作量对照，不能当压缩输出的最低字节数。
- 已完成作品的当前剪辑重新输出沿用原制作 Job，在同一事务内封存本次时间线、原身份与输入绑定、渐进清单和首个工作单元。后续画面、音频与封装单元必须属于该次输出范围，并再次核验真实来源和资源；最终采用使用独立版本与产物身份，不覆盖旧清单和旧成果。原音频仅在音轨、采样时钟、来源及成功许可回执完全相同时复用。退出恢复保留原范围与请求；消耗或释放未知时查询原回执，不能用新尝试清空额度。
- 原生文字图层复用现有字体解析与Pillow栅格化，不要求先伪装成外部PNG来源；文字、样式与区间进入时间线/渲染摘要，生成的位图计入同一图层数、画布、临时文件与总时限。导入图片仍核验登记来源、权限与实际文件事实；支持原生文字不扩大外部文件读取或其他图层类型的能力声明。
- 协作式让出只在已有持久检查点执行；不可中断能力记录边界，不能显示已暂停。要支持更细粒度取消，必须由相应能力负责人改造子进程控制和临时产物清理，再验证恢复与成片一致性，不能用SIGSTOP冒充资源释放。
- 本地桌面及已验证会话上报播放、录音、编辑活动；只存调度必要状态与最后心跳，不记录输入内容。心跳过期不让离线会话无限占用优先级，也不强制取消其已提交任务。没有可靠会话活动来源时不得宣称已实现整机“闲时”，需标记不可用或使用明确指定时段。
- 调度状态给出等待类别、当前执行单元、最后检查点、可用操作、估时来源及更新时间；成员与工作区权限先过滤再返回队列视图。新队列请求成功表示已安排，不能回复为正在渲染。
- 任务媒体作业的资源拒绝回执来自该请求的同一次准入观察，与等待状态在同一事务写入既有TaskEvent；不重采样补数，也不借日志、全局最新值或其他作业解释当前请求。每请求、重试次数与观察时上次许可代只保留首次未知和首次拒绝各一条，重复轮询或同类观察不追加、不改写时点。原请求、作业、成员、输入摘要及基础版本先核验，界面只接收固定原因和白名单数值，不接收路径、凭据或原始载荷。准入后、取消、失效及重启均可回读同请求历史；历史观察不是实时资源或新许可，不改变业务终态和原运行保护。

验收既要求所有入口不能绕过许可，也要求真实设备操作与媒体连续性；安全可恢复但长时间无法让出的实现不等于多人体验合格。先实现本机保守单重活，再根据目标设备的整机压力测试决定是否增加并发。

#### 3.12.1 内存压力、任务预算与平台适配

准入和运行中监测消费同一内存策略，沿现有设备协调者、HostResourceProbe及受许可执行器接入；不新建任务库、调度器或通用资源平台。平台采样、压力判定、任务执行与事实持久化分责，只有必要的直接调用者参与修改。

- 平台采样返回带来源、单位、时点及可用性的事实。macOS核对系统内存压力、可用量、压缩/进程footprint及实际分页语义；Windows核对物理可用量、提交余量、系统低内存通知、分页/IO与进程/显存占用。RSS、footprint、工作集、提交量不能互换；库不支持的指标为unknown，不以0冒充正常。平台差异只在测量和执行适配边界处理。
- 交换/页文件已用总量保留为诊断上下文，退役它在普通任务准入和运行中的普遍独立否决。替代判断须结合当前系统压力、任务新增需求、有效安全余量与持续变化；严重压力及时保护，恢复采用经验证的稳定窗口，不能因单次瞬时值反复启停。不能删除旧比较后以无条件放行或随当前负载不断抬高阈值充当修复。
- 恢复与持续IO窗口由既有HostResourceProbe的同一个基础观察线程推进，分别消费唯一HostMemoryMonitor和既有真实IO累计端点，不得依赖队列长度、owner/身份核验、网络请求或单元执行耗时决定采样节奏，不为每个指标另造线程。准入和运行仍实时检查，不只读后台旧值；采样、窗口写入及许可切换串行，避免倒序误重置，运行IO历史按request/grant generation隔离。生命周期随现有设备运行时启动、停止并回收，暂停派发期间继续观察；测量失败、设备变化、计数回退或真实断档标未知并重新积累，不能补零或放宽窗口掩盖漏采。通用资源等待不能误报为已确认内存不足。
- 任务资源档绑定设备类别、OS、模型/后端与执行版本、输入范围、测量方法和可追溯证据，区分短预览、编码、配音、视觉与人物。启动预留、运行实占和释放证据分别检查；配置能解析不代表已标定，不从文件大小或时长比例猜峰值。实验样本的输入数量、字符数及文件大小只说明已测范围，不能直接当作硬件能力上限或跨操作通用限制；发生冲突先核依据与适用范围，复用已有产物做必要测量，不能仅为守住未经证实的数字增加执行流程。正常运行使用验证过的适用档，不把逐项手填环境变量当作普通用户必经操作；缺档应提供受控能力准备与明确限制。
- 正常故事板准备复用设备准备的原请求、许可、回执及资源档 CAS，仅构建当前授权任务的元数据候选，不采用作品或调用媒体／外部模型。准备记录本进程总 RSS、采样完整性、耗时及完整候选 JSON；取消与超时沿现有元数据执行的安全点生效，不声称可硬抢占单段 Python 计算。发布的 `preparation_basis_digest` 绑定原任务、依赖、完整 manifest 与授权素材集合，正常准入重新计算并匹配该摘要；任务或输入变化须重新准备，不能仅凭数量和字节数沿用一次测量。
- 流式成片检查缺独立资源档时，宿主可在有效 CPU 工程包络和内存策略内显式选择有限首用策略，复用原 quality owner、阶段检查点及设备许可。工具路径、文件摘要和流式缓冲依据独立核实；CPU 只提供申请的进程、线程和时间包络，不充当质检实测。该选择记录为 `declared`、`verification_status=unknown`，不覆盖显式失效的质检档，不发布标定结果或外推整片容量；真实检查仍须完整读取、核对原文件摘要并取得进程释放回执，失败不伪报完成。
- 配音预算明确单次模型调用与父阶段的单位：每段声明正文及该次实际参考文字，串行只在前一进程组确认释放后推进；单段峰值不能以整片文字相加推断，也不能把原整阶段预算偷偷改称单段预算。父阶段累计时间、产物及临时磁盘仍有独立边界，分段不得重置额度；已完成片段沿现有NarrationSegment/Artifact与Job检查点保存，最终组合成功后才发布整体版本。未知标定依据按受控量测处理，不以配置值或代码串行外推生产承载能力。
- 标定复用既有受许可执行链，使用明确的单个受控负载、有限时限/内存/子进程边界、停止条件和隔离数据；保留原始baseline→加载→运行→释放证据，不能直接将观察峰值写回上限或借生产无限重试求绿。首次受控测量与已验证生产档分开，具体实验边界由验收负责人在运行前固定。
- 降压先限制并发/批次、回收本产品空闲缓存和不再使用的模型，必要时在有效检查点让出；不关闭其他应用，不静默降低最终作品质量。紧急终止不能发布半成品或改写已有成功版本；恢复沿原请求/检查点，不重复任务、生成或计费。
- Windows执行适配必须覆盖进程树身份/持有、取消、退出清理和崩溃恢复，不能把POSIX进程组调用直接照搬；模型后端须真实可用，不把MLX模型路径视为Windows推理能力。桌面与CLI/MCP仍共用业务用例和同一资源政策。

迁移必须同时收敛启动、运行、预览/制作和错误回执的旧消费者。历史阈值只可用于解释历史回执，不能暗中恢复为另一条活动否决路径；旧配置的读取/升级行为必须明确。身份、版本、子进程回收、有效CPU/IO及磁盘保护不因本次修复退役。实际接受标准由[产品第12.1节](product-requirements.md#121-同一台主机的任务安排011)拥有。

### 3.13 持续创作的双层 Agent 循环

创作采用外层持久任务循环与内层有限模型回合。外层协调既有 CreationRequest、CreationTask、JobRun、TimelineVersion、依赖与事件，不另建一套从聊天推断的完成事实；内层只在需要理解、创意规划或语义判断时调用 Pi，返回经过校验的行动建议或业务工具结果。一次对话结束不等于制作目标完成。

后台接续从原任务持久归属和[有效任务授权](auth-workspace-boundary.md#5-后台任务)构建受限业务上下文，不依赖进程内保存的用户登录令牌或伪造HTTP Request。原目标所需读取、工具调用及派生产物写入沿同一范围核验；交互式登录和通用内容读取入口不接受该上下文冒充用户。权限范围外的新需求回到正常授权入口，不自动扩大委托。

外层由用户要求、素材接收/索引更新、作业完成、确认或修改、资源条件变化、定时到期与启动恢复唤醒。循环每次：

1. 从可信成员/Workspace及持久对象重新读取当前目标、范围、期望版本、已确认输入、有效产物、能力与执行条件。
2. 检查是否缺少会改变制作结果或授权范围的重要决定；缺少则提出少量具体澄清并保存等待点，不重复询问已明确的信息。
3. 有有效计划且下一依赖就绪时直接调度确定性工作；需要叙事、目标拆解、语义选材或改变计划时构建有限上下文调用内层。
4. 将内层提出的动作编译为受控业务操作，验证权限、输入版本、依赖、能力、确认与资源条件后提交；模型不能修改这些准入事实。
5. 从真实执行结果验证产物与用户约束，保存结果证据和检查点；输入已变的结果只能保留历史，不能覆盖新版本。
6. 依据真实进展继续、局部重规划、等待相关条件、取消或交付。相同输入与同一阻断不无限重跑模型，迭代、时间和执行资源保持有界。

上述是调度决定，投影到既有任务/作业状态；文件生成、技术检查通过、用户接受分别记录，不能合并为一个模型自报成功。

将后台终态回填到已结束的聊天轮次只证明结果送达，不等于完成步骤 5–6；需要后续语义判断的已批准目标必须能在新事实到达后启动有限 Pi 回合。已明确未提交或被拒且无副作用的参数错误可有限纠正；原请求已执行或副作用未知时先按原身份查询，不盲重放。已知失败或质量问题可依据实际结果、当前版本与授权，在已批准目标内提交可追溯的新修订工作。

计划器确定表达目标、素材证据、制作方式、依赖、验收条件和待决定项。执行器只运行类型化能力并写入真实回执；检查器区分确定性媒体检查与内容质量判断。模型用于意图、叙事、语义匹配及内容建议；身份、数值计算、队列、版本、幂等、资源和状态转换由程序确定。失败恢复只处理受影响依赖，安全释放无法确认时保持保护。

既有候选读取必须透传该片段已有的有界证据及确认状态，不能以空默认值丢弃依据。文件名检索为空与内容证据不足分别表达；先查已有素材/知识证据，再决定是否缺少用户输入，不从标签推断未观察事实。最近任务摘要明确截断范围；新建时“保留旧作品”不要求定位或修改旧对象。当前输入尚未提交的空请求查询是正常未创建状态；有提交历史且结果未知时仍保留原请求身份并先对账，不能混为一谈。

目标数量、规划窗口和运行并发独立：总目标可以很大，但只展开有限工作；候选素材、知识、经验记忆与模型输出均有界。每个窗口和执行单元绑定稳定身份、版本与输入摘要，本地任务和提交通过事务与幂等身份避免重复。远端调用超时或回执丢失时，先区分已确认执行、已确认未执行与结果未知；未知结果不得盲目重放或宣称成功，按供应商可核验回执及幂等能力恢复，不承诺无法验证的远端恰好一次执行或费用。有限窗口只是执行机制，不是用户数量上限，也不承诺素材和能力足够完成任意目标。

每轮记录目标版本、当前动作、等待理由、实际进展、观察结果、模型上下文量与可核验用量；按需取对象与工具说明，避免重复注入完整时间线、历史工具结果或媒体帧。上下文显示、实际计费用量和用户等待时间分别测量，不能互相推算或用模型数量衡量 Agent 能力。

任务记录与长期沉淀复用[领域§4.5](domain-model.md#45-creatorprofile-与长期偏好)的唯一事实来源；插件文件、索引和会话摘要仅为可回查投影。记忆纠正/忘记触发相关投影失效，后续检索核验来源版本，不能由旧摘要恢复被否定内容。每轮上下文由当前目标/任务事实、适用用户档案、任务相关证据、少量有效经验及当前能力组成。当前要求、事实来源、人工纠正和偏好按用途分别判断，不通过一个总分混合；检索内容作为数据，不作为系统指令或工具授权。工作状态与跨任务记忆的对象规则由领域文档拥有，检索与素材证据分别沿3.5/3.6，偏好沿3.11。

原声口播、旁白配素材、授权人物生成混剪是同一循环中的不同能力依赖组合，不是另一套事实源。人物参考可登记与人物生成可执行分别判断；露脸目标、实际片段和口型产物按当前音频/人物版本绑定。能力缺失、模型不可用或预算未知是明确条件，不以图片入口、配置存在或旧产物冒充能力通过。

正常制作由结果、修改、失败和预算事件推进；业务巡检只补漏，进程心跳只检查存活及许可恢复，定时触发沿Automation运行身份进入原业务任务。三者不得重复驱动同一工作，也不周期性让模型重读全部任务。运行条件区分关闭窗口、退出应用、设备休眠及后台服务停止；时区、重叠、错过时间与去重由同一持久触发规则决定。通用 Agent 运行优先复用 Pi，业务目标与媒体作业仍由产品内核拥有，具体归属见第3.15节。

用户界面只投影目标、可读方案、真实进度、必要决定、可播放结果和具体修复动作；首次引导建立这一循环所需的最小上下文与实际能力，按所选制作方式补齐条件，不要求一次配置所有模型、人物或内部技术字段。

### 3.14 业务用例、执行契约与组装

HTTP、Pi、CLI、MCP、平台消息适配器与后台作业消费相同的具体业务用例；路由只解析可信输入、调用用例并映射响应。业务/执行不构造HTTP请求、不反射或重入路由函数，不从HTTP响应推定持久结果。

用例边界按用户要完成的业务动作划分，不按一个字段、HTTP接口或单次工具调用划分。制作、改选资源、正文修订、镜头编辑、采用、撤销和恢复分别由现有具体用例组织完整变化；调用方不负责补齐隐含步骤。每个动作明确读取依据、直接变化、受影响依赖、允许复用的结果以及提交后的可执行状态。共享代码只承载确有多个消费者的相同不变量，不建立接管所有对象和流程的万能中间层。

| 业务变化 | 用例必须一起处理的关系 | 不应交给适配器补做的步骤 |
| --- | --- | --- |
| 制作或更换执行输入 | 目标/方案、固定资源授权、作业有效输入、设备请求、原预算与检查点 | 先改方案再分别补授权或排队；重新建作业掩盖原消耗 |
| 正文、镜头或复合编辑 | 实际目标及依赖版本、正文/音画字幕联动、失效与复用范围、操作回执与作品版本 | 只保存可见字段，留旧派生产物继续被当作有效成果 |
| 产物采用 | 产物来源、真实输入摘要、当前目标/依赖、采用版本与未完成关系 | 根据文件存在或作业成功推断作品已更新 |
| 指定修改的撤销/重做 | 原操作变化集、当前依赖、反向变化和新版本，保留无关后续成果 | 以整份旧快照覆盖其他操作，或把历史可播放当作撤销成功 |
| 退出后的接续 | 原请求/作业、授权有效性、累计用量、检查点、有效产物与未知执行对账 | 从当前聊天重建任务、重置预算或重复提交未知副作用 |

表中是同一业务责任，不要求长任务一次完成或一次事务持锁到底。外部核验与文件准备在事务外取得有版本的依据；短事务复核并提交本地关联变化及后续执行意图；耗时执行结束后按原输入登记结果，再按采用条件提交作品版本。准备后撤权、取消或依赖变化须使旧提交失效，不能把实时核验结果当作永久许可。具体对象、版本、撤销和请求语义由[领域§6–8](domain-model.md#6-时间线与产物)拥有，授权范围变化仍遵循[认证§5](auth-workspace-boundary.md#5-后台任务)。

任务、资料、素材和档案类型与模型执行、仓储实例和HTTP对象分离；共享契约只持有实际边界需要的值。具体命令显式传递可信操作者、原请求、期望版本和目标；后台执行使用原持久身份与封存输入，许可来自唯一设备调度者。边界处重新核验身份、源修订与版本，不以调用方自报值授予权限。

内容归属/回执读取的用户身份，与包含工作区、设备、账号的执行身份分别传递，不共用一个含义不定的member字段。涉及原排队作业的修改须核对当前可信执行身份与原作业完整一致，再核对内容用户归属；不能把用户UUID与账号执行元组直接比较，也不能拆字符串或丢掉设备字段来放行。普通内容编辑不因此增加设备执行许可前置；真正重绑定作业仍沿原业务授权与设备身份核验。

固定来源的业务身份与本次打开文件的物理身份分别保存和校验。业务身份绑定工作区、来源/档案版本、实际内容摘要及选取范围；摘要须在所属登记或本次实际采用/封存输入时由宿主核验，不能把元数据JSON摘要当成字节摘要。设备号、inode和打开句柄用于本次准备与执行的替换防护，不能独自成为跨重启的业务版本。物理身份变化后，只有已存在的可信内容锚、当前权限及业务依赖仍一致，才可沿原用例重新验证并替换尚未授予的执行请求；原Job、预算、等待记录和审计保留。没有历史字节证据的旧输入明确保留不可自动恢复，不能现在计算摘要后追认历史；用户实际新选择/采用可建立新的封存依据。已经授予、执行结果未知或带未确认尾部的工作文件不走未执行请求的恢复路径，不放松其物理防护。

配音沿原Job不可变TaskEvent封存本次实际输入：首次创建Job或原未执行Job真实改选声音时，来源内容证据与原start/rebound在同一事务绑定。内容证据注明精确关联的已有采样接收回执，或本次实际采用时核验的完整字节；包含所属任务、可信操作者、来源/声音固定版本、范围、目标和业务输入摘要。它只证明该任务这次采用的来源，不回写全局声音版本、不建立第二份素材事实源。原请求重放读取原封存事件，不能重新读取当前文件后补建旧证据；恢复审计追加原/新请求与重新核验依据，原来源事件保持不变。

预览与正式生成共享必要的媒体编译/执行实现，执行用途及资源配置明确分开。资源需求由实际能力声明，设备协调者消费同一契约；短预览预算依据该用途的本机实测，缺少标定就保持不可用，不从时长比例猜内存或借用整片配置。启动预留、运行占用、全部子进程和临时文件沿第3.12节。

所属仓储是唯一对象写入口；跨对象变化由一个负责人通过同一SQLite事务比较版本并完整提交。文件发布与数据库登记分别保留恢复证据，不能把二者视为一个原子事务；过期产物保留历史，不覆盖新版本。

SQLite写事务不跨网络身份检查、模型/媒体执行或等待式CPU/IO采样。调度先读取候选并排除尚未到时/过期请求，在写事务外完成当前身份和资源核验，再以短事务比较请求、版本、取消状态与唯一许可并提交。观察与提交之间事实变化必须拒绝旧候选；实际执行仍保留当前身份与输入复核。不得以授权缓存、加长锁超时、关闭保护或另一调度器替代；文件许可账本与数据库恢复规则保留。

失败沿原业务错误、工具回执与持久事件传递有限的结构化信息：安全错误码、实际阶段、原请求/对象定位、提交效果（未提交/明确拒绝/结果未知）、可查询结果与允许的修复动作。日志和事件不保存凭据、私有路径或原始上游响应。连接/模型等待/工具调用/业务冲突分别归因；会话总超时不覆盖此前实际业务拒绝。未知写入先核对原请求，确定未写入才允许修订后再次执行；复用现有请求日志与GoalContinuationService，不新建重试循环。

宿主按SDK实际模型调用与工具请求的阶段计时，保留各阶段既定的有限超时，不能让数次合法工具等待耗尽一次模型调用预算；文本输出或心跳不延长同一阶段。业务工具内的多次请求分别沿已有请求超时，不能仅以“工具仍运行”无限豁免。媒体提交获得真实作业身份后沿既有结果事件接续，响应未知则查询原请求；不让30分钟或更长制作占住对话模型调用。超时优先请求SDK取消并收集实际工具结果，无法退出才沿原进程组回收；取消对话或HTTP不等于业务回滚。自动接续与普通对话保存同等具体的安全失败，通用未知异常不得覆盖已经保存的明确回执。

应用组装负责依赖创建、路由/执行器注册和生命周期。认证读取的HTTP连接池由应用拥有，Auth实例只借用；设置重载继续显式绑定，停止全部使用者后再关闭。每次成员/首启状态仍独立请求与核验，不在连接默认配置保存用户headers，也不把传输复用当授权缓存；依赖不可用按[认证边界](auth-workspace-boundary.md#2-信任模型)拒绝并投影。导入纯业务/契约不建数据库、不加载模型、不启动调度；生产运行继续只有一个设备协调者。任务、作业、许可和会话分别拥有自己的既有事实，客户端通过只读投影表达结果。

### 3.15 Pi 复用与视频创作 Agent

Pi 是通用 Agent 运行基础，曜核以视频领域上下文、原子业务工具和 Skills 改造它的用途。选型检查完整 [Pi monorepo](https://github.com/earendil-works/pi) 及实际安装版本、消费者和主动关闭的能力，不能只评估 agent-core。以下为职责及接入原则，不表示这些包均已安装、接通或验收：

Agent应能依据目标读取资料、选择工作方法、拆解并组合能力、编写必要处理程序、观察实际结果，遇到缺口修订方案后继续；不能只给固定流水线填写参数或复述状态。业务阶段描述作品状态，不把所有创作强制成固定调用顺序。程序负责事实、授权、版本、事务、幂等和资源执行；这种确定性约束不替Agent选择创意，也不需要用模型重写。判断Pi是否发挥作用看上述实际行为，不看接入包数量、角色数量或工具调用次数。

| 上游能力 | 曜核复用方向与边界 |
| --- | --- |
| pi-ai | 统一供应商协议、流式响应、工具调用与模型能力；产品仍控制供应商选择、外发数据及业务错误 |
| pi-agent-core、pi-coding-agent SDK/协议 | 复用 Agent 循环、会话、事件、上下文压缩、插话/后续队列、提示词模板、Skills 和扩展机制；去除默认编程任务假设，注入视频创作资源 |
| pi-durable | 优先评估持久会话、输入队列、检查点、恢复及可恢复工具编排；上游标注 Experimental，须固定候选版本并验证后采用 |
| pi-codemode | 复用沙箱内有界工具组合、独立读取并发及中间结果处理，不另写脚本编排引擎；每个业务写入仍经过同一用例 |
| pi-mcp | 有真实外部服务消费者时复用连接、发现、取消及认证协议；不为接 MCP 把内部业务调用绕成网络 |
| chord | 随所选 Pi 宿主复用类型契约、状态观察与传输；不复制产品仓储或替换设备许可事实 |
| pi-telemetry、pi-evals | 复用适合的追踪与评测基础；视频任务样本、实际视听结果、权限和恢复验收由产品定义 |
| pi-env、pi-tui | 前者仅用于明确需要的远程/隔离执行；后者供终端入口，不作为桌面 UI 底座，不强行接入无消费者能力 |

同一生产会话只有一个通用运行 Owner：本产品采用 pi-coding-agent SDK 的 AgentSession，负责模型循环、会话历史、压缩及 steering/follow-up 调度；Python 宿主通过随包运行桥传递可信快照和业务回执，不再启动通用 print CLI 或解析其历史输出。兼容版本由运行桥常量与桌面包资源共同约束。RPC、Durable 等候选后续只有在完成同一闭环验证并退役旧 Owner 后才能替换，禁止长期并存多个会话/重试/队列事实源。不能把删除 `--no-skills` 等参数当成完整迁移：宿主显式加载可信的产品技能、模板和扩展，保持用户/工作区隔离，不扫描加载用户任意目录中的执行代码。编码专用系统提示改为视频创作职责；通用read、write、edit、bash等原生工具保留并复用上游实现，通过其执行适配接口接入第3.15.1节的工作环境，不再以“只做视频”为由一律关闭。任意目录中的执行扩展和项目指令不会因此自动成为可信资源。

运行时拥有模型回合、上下文、工具调度及其持久执行记录；产品拥有 Conversation 的成员/草稿发送事务、CreationRequest/Task、TimelineVersion、业务请求幂等、输入/结果对账、文件权限及 DeviceScheduler。Pi requestId 去重不替代消息/目标/版本一致性检查；Pi abort 不证明媒体进程已释放。启动与恢复由唯一产品组装入口连接两者，真实任务事件触发后续回合，不能保留另一套无条件轮询续聊引擎。

运行中追加输入沿既有 Conversation 输入回执保存消息、模式和固定引用；同一任务的有效steering使旧目标修订失效，新修订只从已消费回执及其真实动作证明建立，并保留前文目标、以后续要求解决冲突。独立新制作目标单独绑定任务与授权，不使原任务目标失效；follow-up按实际目标归属绑定，不能仅凭排队模式判断它属于同一作品。编辑、媒体作业及制作回执保留宿主核验的输入身份；晚请求不能归入新输入，晚结果只能回读原来源。后台领取和结算同时核对目标修订与输入身份，未核验的旧结果不能唤醒新目标。新输入实际读取仍在运行的原制作作业后，可沿同一作业登记只读观察绑定；终态到达后接续当前要求，不重启作业。原请求回放不重复副作用。此修订是业务授权检查点，不另建 Pi 输入队列。

原子能力以实际业务操作及 schema 为唯一来源，描述对象、单位、版本、前置条件、可用性、影响和结果查询方式。先补齐读取→操作→观察→撤销/恢复的闭环，再增加能力数量；GUI、内置Agent、CLI、MCP与消息适配使用同一规则。结构化工具可供 Code Mode 组合，结果未知先查询原请求；模型不能凭能力名称宣布动作已完成。

精细业务操作的发现沿实际[工具目录](../apps/api/app/assistant/catalogue.py)、编辑schema及任务能力查询生成，不另存一份人工维护的全量能力文档。入口先让Agent知道如何查询；随后按当前对象返回可用操作、参数/单位、所需版本、不可用原因与可修复条件。阶段过滤只用于减少无关上下文，不得让合法跨阶段操作无路可达；能力目录只列名称、存在HTTP接口或UI按钮，都不代表模型已能正确调用。按用户要求回查“对象读取→能力发现→执行→原请求回执→结果观察→撤销/恢复”，区分未实现、未接线、当前不可用和已验证。原子粒度按业务不变量划分，不为每个按钮或每种自然语言另造工具；新组合可用既有原子工具、Code Mode和原生程序表达，权威编辑仍回到同一用例。

提示词分层：稳定系统规则只放创作职责、指令优先级和工作方法；每轮注入可信目标/选中引用/版本/必要能力；对象全文、工具说明和 Skills 按任务渐进加载。片段内容、转写、外部网页和素材说明属于数据，不成为系统指令。提示词不复制整份产品文档、完整时间线和全部技能正文。

Skills 描述口播剪辑、旁白配素材、人物混剪、字幕与声音修正等可复用工作方法，包含触发条件、所需输入、工具步骤、可观察结果及停止条件。它们使用适用的业务工具或原生操作，可附脚本和参考资料；宿主提供所需实际依赖，不以说明代替可执行能力，不另建数据模型或以提示词保证事务。第三方扩展采用前核对实际版本、依赖、许可和行为，不以可安装推定适用。成功任务可提出模板/Skill 改进候选；经验记忆、用户创作模板和可信执行扩展分别管理，不由一次满意回复自动改写正在生效的规则。

提示词、工具 schema 和 Skills 按版本组合发布，保留可回退版本。采用真实代表任务评估首次可用预览、连续两轮局部改片、中文指代/多选、声音及特效、插话/停止、冲突/撤权、重启/未知结果；比较操作准确性、实际视听质量、人工干预、等待及上下文开销。先定位失败属于事实、工具、提示词或运行时，再改相应层，不靠加长提示或增加盲重试求通过。上游升级同样按受影响闭环验收；通过后退役被替代的自建解析、循环、恢复或扩展加载消费者。

### 3.15.1 原生工具、业务工具与创作执行

原生read/write/edit/bash保持真实读、写、精确修改和程序执行能力，优先使用[Pi原生工具接口](https://github.com/earendil-works/pi/blob/v1.5.0/packages/coding-agent/examples/sdk/05-tools.ts)，不另造名称相同但只返回说明的假工具。原生工具用于已授权资料读取、任务工作文件、脚本/字幕/图形/媒体处理和结果检查；业务工具用于权威资源、版本、采用、制作、撤销和结果登记。两类互补，不能用任意shell直写SQLite或覆盖素材来绕过业务不变量。

宿主为任务提供可恢复工作目录、受许可输入映射和输出位置。授权范围内允许Agent自行选择和组合Shell命令、编写程序、检查文件与调用可用电脑工具，不把原生能力收缩成几条固定业务命令，也不逐条要求用户批准已委托的操作。通过上游工具operations等适配连接实际文件和进程执行环境；执行边界由[认证§10](auth-workspace-boundary.md#10-climcp消息入口与原生工具)规定，不能把cwd或提示词当隔离。媒体/模型重活仍取得DeviceScheduler许可；轻量文件操作不强迫进入渲染队列。缺少执行边界属于该能力的实现缺口，须补齐实际执行与产物采用链，不能用假工具或永久关闭原生工具交付目标代替。

通用执行通过原生工具operations/宿主钩子复用实际文件与命令能力，不把Shell变成固定命令白名单或为验收另写专用入口。已有PNG程序、受许可进程、Artifact和编辑用例按真实适用范围复用，不能把PNG专用限制复制为全部通用操作的上限。轻量操作与重型模型/媒体执行分开安排；Pi可读错误、改程序、再检查，未知副作用先按原执行身份对账。

执行记录从提交起绑定[领域§7.5](domain-model.md#75-对话会话与轮次)的任务/对话/输入归属、工作目录、授权输入、进程及临时文件。宿主统一登记开始、结果、用量和停止/回收事实；取消请求、进程已退出、资源已释放和检查点可恢复分别表达，不能只改聊天状态。事件按原归属唤醒，恢复前核实进程及已完成结果，不重放未知动作。临时文件按所属执行生命周期回收，原始素材及有效产物不随清理删除。

生成文件先是工作产物，通过既有素材/Artifact登记与编辑命令进入作品；登记核对实际格式、文件摘要、输入与参数版本、来源执行及所属任务。预览、候选和采用分开记录；文件存在不证明采用，采用不证明最终合成完成。修改已入库对象继续走所属公开用例；不要求每条Shell命令变成专用工具，不另建脚本任务库。原生工具真实执行与产物采用须在同一候选验证，随后以未专门适配的相近任务检查自主重组能力。

### 3.15.2 粗剪、多轮精修与创作方法

可编辑视觉模板沿VideoTemplate唯一版本仓储、EditGraphicOverlay和既有媒体采用链执行。模板文档编译由独立媒体适配器拥有，交互预览与逐帧导出共用同一文档和固定源码。桌面复用附带Chromium，作品脚本仅在无Node/预加载/IPC、无同源权限的sandbox iframe中运行；CSP及独立session禁止网络、文件、worker、弹窗、下载和权限请求。可信宿主只传时刻、参数和布局，不把模板代码eval到Electron主进程；错误和缺依赖给出明确结果，不联网补依赖或静默替换。

模板库即时原型仅执行随包核对一致的源码及参数绑定；用户修改的源码或绑定通过作品已有媒体预览/渲染Owner持许可执行，不自动注入工作台页面。源码可编辑不授予无限制的前台执行额度。

动画帧生产、临时文件与所有Chromium子进程持有原画面单元的设备许可，沿既有进程组回收、时限和输出保护；CPU准备显式测量template_count对应的真实绘制与合成，旧静态图层档不能推定可用。native_command准备另外运行真实OS隔离的Python/Pillow/FFmpeg样本并独立记录进程观察，仅给出请求形状下的有限通用执行范围，不承诺任意程序均可完成，也不借CPU编码采样标定通用Shell。

局部创作决策复用现有对象读取、编辑用例和Pi会话：先保存用户输入及所见版本，按需读完整目标段文案、相邻段、时间线、资料引用、能力schema及同版本观察；输出带目标/基础版本、受保护事实与限定、具体动作、依赖影响、采用方式和检查要求的结构化修改。代码负责权限、版本、明确规则、预算及事务校验和机械执行；内容语义由Pi复核，不能用字符串匹配宣称含义不变，用户确认边界见[产品§9.2](product-requirements.md#92-自然语言修改)。已定稿正文按真实锁定范围处理，未知/截断上下文先补读。已有简单参数解析器仅服务明确精确指令，不将模糊创作要求降为固定倍率。

原声半成品精剪复用素材分析、局部媒体工具和上述编辑循环，具体用户结果见[产品§9.1.2](product-requirements.md#912-原声半成品精剪)：

1. **读取证据**：Pi按原请求与所见版本读取目标、原声/正文保护范围、相关Clip、相邻转写、源时间与时间线映射、转写粒度和可用视听观察；分批读取长素材，缺项或截断时定向补读。ASR负责听写、VLM负责画面线索，Pi负责取舍，不能让视觉概括冒充声音分析。
2. **形成取舍**：Pi标出候选口头语、重说组及保留候选，给出简要证据、保留的事实/限定、冲突和未知；例如前一遍未说完、后一遍含“在规定条件下最高可达”，应保留完整限定，不能为了紧凑拼出更强承诺。对重要不确定处申请局部复听/对齐或求证，不要求模型输出私有思考过程。
3. **输出可执行编辑**：提交原任务/输入、基础及依赖版本、原资产及源区间、保留顺序/删除区间、声画字幕联动、受保护内容、候选或直接采用方式和检查要求。精确区间来自可回查分析或工具测量；无需判断的拆分、裁切、拼接、时轴映射与渲染交给现有编辑用例。已有业务工具合适则复用，缺局部分析能力时可沿§3.15.1使用已授权通用工具并登记结果，不为每种口头语新增专用接口。
4. **回读与调整**：复用下述失败回执分支，检查实际采用版本、保留区间及媒体；确定性检查负责越界、遗漏/重复采用、时轴和受保护字段，Pi复核表达及限定是否改变，听感/画面判断仅限取得的证据。切点不准或吞字时只修对应边界并重预览；低证据时保留原候选/原版并说明，不盲删、不整片重做。用户可从同一任务回查结果和修改依据。

修改提交复用原请求回执：明确未提交的参数拒绝可据能力修正；版本冲突重读并判断原意是否适用；未知结果查询原请求；资源或预算等待持久保留成果；执行失败只修受影响单元，不盲目重复。结果回读绑定实际版本和媒体摘要，检查与采用分开，后台消费者与UI使用同一业务入口。

稳定系统提示只包含创作职责、授权/事实/定稿边界、持续推进方法和真实结果判断；不复制编码默认任务、不铺满历史补丁。每轮注入可信任务/语言版本、文案采用及锁定范围、所选对象、未完成要求、预算和最新回执；对象全文与历史按需读取。压缩与会话恢复复用Pi，作品和授权从业务事实回读，不从对话摘要重新构造。长窗口模型按独立工作上下文预算触发Pi原生压缩，不等到模型最大窗口；预算与保留策略由随包运行桥配置，原会话文件和业务事实保留。

主题与文案可执行后，导演/编排职责安排真实粗剪；同一剪辑台可播放后，剪辑职责按用户指代和对象执行局部操作，检查职责用实际画面/声音及文件证据回读。角色是方法与能力分工，不强制每条视频启动多个Agent或不同模型。若引入内部子任务，只用于独立资料/候选/检查，主Agent统一采用和提交写入；不并行改同一作品、不复制队列和历史、不展示私有思考链。

Skills复用现有口播、旁白配素材、局部修改，逐步补目标到粗剪、定稿到粗剪、资料/画面检索、中英本地化、音画/字幕精修、输出检查。成功经验候选与用户模板、长期偏好、可执行扩展分开管理；按真实失败归因调整提示词、schema、Skill或业务用例，不以增加token、角色或盲重试代替工具修复。至少三轮局部精修与人工交替、跨任务新指令、停止/恢复、语言版本和原生工具产物进入作品构成回归样本。

### 3.15.3 证据可达性与结果闭环

Pi运行基础、所选模型的判断能力和产品提供的证据/操作能力分别评估。运行循环存在不证明专业判断可靠；模型判断失败也不能直接归因于模型参数规模。优先核实相关证据是否可读、粒度是否足够、工具是否真实可执行、结果是否回到原任务，再依据可复现失败调整方法或评估模型。目标理解、证据读取、创作取舍、能力组合、可执行规划、结果观察、失败调整及持续协作沿§3.15–3.15.2共用一条链，不新增独立Agent内核或八套能力模块。

观察入口复用已有素材分析与结果检查，允许按当前疑点定位原片或产物的局部时间范围，并返回对象/版本、输入摘要、来源模态、分析方法、覆盖范围及不可观察项。文件可播放、音量测量、OCR、静态采样、语义判断和听感/连续口型质量分别表达；任何一项成功不代替其他项。缺必要证据时定向补分析或保留待用户预览，不能默认重分析全片，也不能以开放Shell推定自动获得视听理解。原始媒体的访问和外发仍遵循既有授权与本地优先边界。

工具执行成功、产物登记、候选可预览、当前版本采用和最终输出采用是不同事实。Pi必须能沿同一请求回查这些既有对象的关系及未完成依赖，下一轮据此继续，不从聊天里的“已完成”推断作品状态；不新增一份可写的Agent完成账本。读取范围在仓储查询、传输、工具响应及模型上下文各层有界，不能先全量拉取作品再截取列表冒充端到端分页；窗口外对象可继续定位，截断和未观察不能解释为空或不存在。长作品的执行与规模验证继续按§3.7.1实施。

同一业务事实由现有所属仓储、任务要求修订、素材/知识来源、TimelineVersion及操作回执拥有；适配层投影与引用，不另建可写的语义中间层或Agent状态库。产品阶段、执行作业类型及能力类别分别有类型归属，转换集中在其实际边界，不强行合并成一个枚举。素材资格由素材领域拥有，各实际消费者传入用途并复用；资格与排序、语义相似度分开。

“有权使用”“适用于本次输入”“能够获得执行许可”和“成果已被作品采用”分别来自所属业务判断，不能合成一个跨层可用布尔值。Pi与界面从同一业务读面取得原请求、目标及依据版本、操作/作业、执行结果、Artifact与采用关系、剩余条件和可用恢复动作；投影可以裁剪显示内容，不能在各自适配器重新定义成功或另存完成状态。候选已生成但采用冲突时仍保留候选及原因，不伪报整体成功，也不抹去实际成果。

对象定位优先复用固定选择、用户所见任务版本、已有对象目录/分页读取及检索，返回匹配依据、范围与歧义；不要求模型猜内部ID，不以增设万能寻址工具代替现有入口接线。身份和请求标识由宿主绑定；对象版本必须保留读取依据，不能自动刷新以绕过冲突。

当前任务事实在每轮上下文只装载一次，与完整人类要求、可信输入身份及接续检查点分开。易变事实不在每条历史用户消息中重复保存为大段快照；完整能力参数沿已有能力读取工具按需取得，初始上下文保留发现入口、当前可用性和必要约束。旧工具回执及人类要求不能为减载而删除；历史记录不成为当前事实源。模型装配必须保留所选模型及实际协议已核实的能力元数据，不能因自定义供应商别名丢失上下文窗口、推理能力等信息后落入不匹配的默认值；复用SDK已有元数据，不把另一协议的输出限制直接移植。SDK压缩继续负责会话压缩，既定阶段超时保持；原回合事件须能区分压缩触发、完成、取消和失败，记录有限原因与估计规模，不保存原始提示或凭据，也不把宿主截止推定为供应商已接收请求。

业务错误沿原请求保留原因类别、提交影响、已保留候选/产物、可执行下一步和重试条件，Pi与UI消费同一回执。协议无效、内容不通过、传输结果未知、身份/资源拒绝分别处理；核查报告无效不能推导内容错误或一律改写为服务不可用。重试必须遵循既有幂等与未知结果对账，不以重跑生成替代报告修复。业务用例组织共同不变量；耗时模型、媒体、网络和文件准备在写事务外，短事务核验输入/依赖并登记采用与检查点，未采用成果仍可回查。

### 3.16 CLI、MCP与平台消息适配

外部入口是产品能力的正式消费者，不依赖GUI自动化。CLI复用现有命令与传输模块并纳入安装交付；产品MCP服务端对外暴露同一能力和受权资源。这与Pi通过pi-mcp连接外部服务不同。自然语言目标/持续会话与类型化精确命令均需支持，调用方可选择让曜核规划或提交确定编辑，不重复运行第二个视频Agent内核。

适配层负责协议协商、参数映射、可信身份、传输回执；具体业务用例负责目标、采用、编辑、制作及版本，仓储负责对象事务，设备调度负责执行许可。外部进程可以消费现有API；应用内业务不得构造HTTP请求重入路由。现有CLI、MCP或平台连接均不能通过shell直写数据库。接口覆盖能力发现/可用性/schema、检索/引用、创建/采用、编辑、制作、状态/事件、取消/恢复、历史与结果访问。

每个副作用请求携带稳定业务请求身份、实际指令、目标及期望版本；可信上下文由适配器解析，不能相信模型自报用户。响应返回原请求、操作/任务/作业、实际版本、状态、修复动作、事件游标与受权产物引用。所有新写入入口必须可按原身份查询，尤其制作开始/恢复与撤销/重做；未知先对账，不能把当前任务HEAD当作原请求成功证明。传输消息ID、外部平台事件ID和业务幂等身份各有归属。

长任务受理后立即返回定位，业务事件持久化供查询和断线续收；通知只是提示，不是第二事实源。MCP按[官方生命周期与能力协商](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)固定兼容版本，按客户端实际支持选择stdio或已明确部署的HTTP传输；不假设所有客户端支持异步扩展，业务task/job查询始终可用。不为桌面MCP自动开放公网端口。连接关闭不隐式取消已经提交的制作。

飞书、钉钉适配分别核验官方请求身份/签名及事件重放，将租户、发送者、会话映射到已绑定成员/工作区，解析附件与作品引用，可靠接收后返回真实进度或结果定位。平台回复失败只重送回复，不重复制作；结果链接按访问权限和有效期处理，不泄露本机路径。群会话、多成员、主动通知和文件外发必须在明确连接授权内，不能把所有群员自动绑定同一拥有者。平台配置/实际租户缺失属于该平台验收阻断，不宣称连接器已交付。

或原生选择器 / 已授权接收目录 / SourceConnector

电脑录音和手机采样共用采样任务/参考文本与 ProfileRepository 接收入口。手机只提交授权任务的音频和来源信息，主机核实归属、完整性及原请求；录制、上传、接收、声音制作和试听分别投影真实状态。传输协议需由真实两端消费者共同确定，不能把本地路径接口包装成手机上传。

### 5.1.1 手机联动的共同接收与回读

Flutter负责设备发现/扫码、用户操作、手机私有草稿、传输和状态展示；桌面入口负责可信连接与邀请呈现；主机已有身份、素材、档案及任务业务负责授权、接收、登记和事实回读。手机不建立第二个素材库事实源、制作队列或视频执行器，业务模块不依赖Flutter或桌面UI。

局域网接入必须使用经核验的设备身份与可信加密连接，不能把匿名loopback API直接暴露到LAN；认证沿[认证边界](auth-workspace-boundary.md#9-主账号邀请与共享授权)。发现只提供候选定位，地址变化后重新核验设备；邀请、登录和长期绑定区分，敏感凭证不进入广播、URL或日志。具体连接载荷、传输与信任实现由两端真实消费者共同冻结，不猜协议或关闭证书检查求联调通过。

素材传输以稳定请求身份、授权工作区、文件长度/摘要和接收回执关联，分片/临时文件不作为已入库素材。接收模块负责临时文件完整性、取消/恢复和原请求对账，完成后调用素材或声音所属的公开入口原子登记；声音同时校验采样任务与参考文本版本。重传复用同一结果，不因两端重启重复建档或启动制作。复用已有本地导入与采样登记规则，只补真实字节传输和必要接收记录，不由手机提交主机本地路径。

进度和结果沿现有CreationTask、作业、事件和授权媒体读取投影；离线缓存显示更新时间和离线状态，不能覆盖新事实。重连后先核验成员/设备/工作区再刷新任务；结果随当前版本回读，未知发送状态先查询原接收请求，不盲目新建任务。

手机连接载荷使用显式`yaohe-companion`类型与`version: 1`，必须带`purpose`（`pair`或`invite`）：`endpoint`（HTTPS根地址）、`device_id`、`token`、`expires_at`、`workspace_id`、`tls_ca_pem`与`auth`（`supabase_url`、`publishable_key`）。`purpose=pair`用于同一已授权账号连接自己的手机，由`POST /api/companion/pairings`生成仅绑定当前成员/工作区/设备的短期一次配对凭证，`POST /api/companion/pairings/accept`在独立JWT身份核验后接受；不新增成员、不占第二个名额。`purpose=invite`继续使用既有正式成员邀请，在接受后建立新成员与空间。主机在相应凭证创建后由原生端组装二维码；不得包含设备proof、CA私钥、账号密码或长期成员token。扫码是用户从自己的可信桌面取得该设备专属CA的动作，手机客户端仅在该主机连接上下文信任它并保留常规证书有效期/主机名校验；不安装全系统根证书，不使用放行所有证书的回调。云登录使用系统信任HTTPS，不接受主机CA覆盖云端信任。主机地址变化需重新取得经核验的定位/证书，不能自动将凭证发往发现的另一主机。

桌面保留核心API/Web的loopback服务，原生端仅在正式身份可用且用户启用手机连接后开放受限HTTPS网关；网关限制接口、HTTP方法和转发头，拒绝local成员凭证，真实JWT、设备及工作区授权仍由主机业务逐次核验。网关随桌面Quit关闭；不把未经验证的任意代理或系统文件入口暴露到LAN。手机带`Authorization: Bearer ...`与`X-Workspace-Id`查询`GET /api/companion/session`，返回经核验的`device_id/workspace_id/member_id/name/role`（`role`来自设备成员关系，不由工作区角色推断）；工作区选择不由客户端自报即生效。原邀请接受入口仍可在未选空间时核验身份；后续请求显式选择其返回的空间。

## 6. 存储

### 6.1 数据库

SQLite 或等价本地数据库保存结构化领域对象、状态、版本、事件、依赖和逻辑文件引用。Repository 是唯一写入口，不允许各模块维护结构不同的旁路数据库。

### 6.2 文件存储

Workspace 文件区建议区分：

- originals：不可变原始资产；
- proxies：预览代理；
- analysis：转写、关键帧和索引派生数据；
- artifacts：配音、字幕、口型、封面和渲染结果；
- outputs：用户可检查的最终输出；
- temp：可回收临时文件。

数据库保存逻辑引用和摘要。真实路径由本地受信任层解析，迁移 Workspace 时可重新绑定。

工程备份包含一致数据库快照及被引用原件/产物清单，保留版本、归属、逻辑引用和摘要；凭据经受保护配置重新绑定，不写入明文包。还原先写入新的根目录并核验引用与输出，缺失原件提供明确重连动作，不静默覆盖旧库。正常重启回读、最终视频导出和可编辑工程备份还原分别验收。

配置外接数据盘时，数据库、模型、派生文件、项目级缓存和临时文件应使用该存储根，应用启动与任务执行前检查磁盘身份、可写性和剩余空间；缺盘不得回退到内置盘。开发源码、依赖及构建缓存同样使用配置的外接位置，具体本机路径由私密配置和当前合同持有。系统交换文件及操作系统自有缓存不属于项目可保证迁移的范围。缓存回收与原始素材/有效产物删除必须区分。旧路径映射可以保留以兼容已有引用，但不能形成第二份可写数据。

### 6.3 任务与事件

长任务状态必须可恢复。进度事件用于界面展示，但最终状态以持久化任务和产物为准。进程崩溃后不能把 running 自动解释为 completed。

## 7. 安全与外部边界

- 所有 API 写入校验 Workspace 一致性。
- Renderer 只能使用 Desktop 或 API 返回的受控引用。
- API 密钥和账号凭据使用系统安全存储。
- 云端模型调用明确展示数据类型、供应商和成本。
- ContentUseState 约束素材用途；它与文件访问权限、账号连接和平台发布确认不是同一概念。
- 删除、覆盖、模型调用和平台发布保留审计事件，不建立产品计费流程。
- 日志不得记录密钥、完整凭据或不必要的用户内容。

## 9. 多空间、知识召回与状态投影

认证层解析设备角色、成员和当前空间；Repository/文件访问/工具调用在对象读取前执行私有或显式共享授权。检索先限定可访问集合，再召回与重排；向量结果、缓存、聚合词云和预览链接不得绕过授权。设备资源许可独立于工作空间，继续遵循第3.12节；授权共享不增加并发许可。

导入接收保存批次背景和来源，后台按资源安排自动分析；观察、人工纠正和索引分别版本化。纠正提交后使相关索引失效并增量更新；用户可见生效/更新状态，制作不得无提示消费过期纠正。知识文件解析与网页快照通过现有来源对象保留出处，召回结果携带证据位置，外部文本始终作为资料输入而非工具指令。

Pi编排与业务写入的边界统一见第3.15节，直接编辑与必要提案采用统一见第3.8节。阶段事件与队列状态持久化后供桌面和手机/消息入口查询；断线重连返回同一任务事实，不依赖聊天是否打开。事件重放与业务命令幂等分别处理。

首页、素材与任务对话复用同一应用会话/轮次持久入口，服务端按当前可信成员和空间核验创建、历史、草稿、恢复及停止；资源浏览保留活动对话；明确切换业务任务时按其scope恢复对应会话，选择历史对话也在该scope内持久化当前指针。历史跨任务会话原样保留，不猜测重绑；业务归属遵循领域模型§7.5。每轮由已核实的发送目标快照进入原home/material/task领域入口，逐轮校验对象权限、片段范围及期望版本，历史会话与前端选择均不代替授权。Pi沿现有执行入口承接该会话上下文，不另建Agent或生产状态库；历史任务聊天事件可作明确只读历史投影，新的对话轮次只有一个写入来源，业务TaskEvent继续记录真实领域结果。Renderer只缓存交互草稿并回读应用会话，不从原始Pi日志推定业务成功。停止按轮次关联当前实际子进程，回执与进程释放后记录终态；HTTP断连与停止、聊天停止与制作取消分别处理。

固定引用生命周期遵循[领域模型§7.5](domain-model.md#75-对话会话与轮次)。应用会话Repository对引用修订与草稿修订分别做原子比较，服务端核验真实引用及当前权限。素材写工具把冻结的素材与片段更新时间传入已有命令，由Repository在同一写事务中比较，冲突返回409且不改变对象。

素材库对话将当前素材/片段作为服务端核实的对象范围，标签等普通属性调用现有对象命令，返回持久结果供工作台刷新；它不创建无关创作任务。CLI、MCP及飞书/钉钉入口统一遵循第3.16节；外部身份绑定遵循[认证边界](auth-workspace-boundary.md#10-climcp消息入口与原生工具)。

首页、发布看板和素材词云由授权范围内事实聚合；主账号与成员使用同一后端授权规则，不能只由前端隐藏。展示任务阶段、等待原因、可用时间估算及估算不确定性；没有样本时显示正在估算，不能固定倒计时假装预测。手机与企业消息入口复用邀请、上传、作业和事件接口；连接器交付范围依产品要求，不由架构接口存在推定已交付。
