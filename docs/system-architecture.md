# 系统架构

本文件定义 AI 视频日记的运行模块、跨进程责任、外部能力适配和关键数据流。产品范围见 product-requirements.md，领域对象与状态见 domain-model.md。

## 1. 架构目标

工程结构约束由 [AGENTS.md 第1.1节](../AGENTS.md#11-高内聚低耦合与代码拆分)拥有；本文件拥有具体模块责任与数据流。短期重构实施范围通过活动合同定位，工作方案不替代本文的活动边界。

系统围绕一个 Workspace 和一条 CreationTask 事实链运行，满足：

- 本地优先，网络能力可插拔；
- 原始资产不可变，派生产物可追溯；
- 自然语言与精确编辑共享同一领域操作；
- 局部编辑按依赖图增量重算；
- 模型可以更换，领域状态不依赖供应商；
- 进程中断后任务可恢复；
- 不可用能力诚实失败，不使用隐藏 fallback；
- Web 不能绕过桌面权限提交任意本地路径。

## 2. 运行拓扑

### 2.1 Desktop Shell

Electron 桌面壳负责：

- 应用生命周期和窗口；
- 选择文件、选择目录和保存成片的原生对话框；
- 把用户选择转换为受控文件句柄或工作区引用；
- 启动、监督和终止 API、Worker 及必要的本地模型进程；
- 安全存储 API 密钥和平台凭据；
- 打开文件、播放器和系统通知；
- 退出时清理子进程、端口和临时资源。

桌面壳不实现产品领域规则，也不接受 Renderer 提交任意源绝对路径。后台HTTP网页服务使用Electron utility process，不以主GUI可执行文件的Node模式重复登记为前台应用；仅主窗口拥有Dock/激活身份。API与模型子进程仍受原生命周期与资源协调者管理，失败由主应用呈现，退出必须回收服务与端口。

原生媒体控件会先于页面消费 Escape。Renderer 仅在顶层对象卡片内的 video/audio 获得焦点且未全屏时登记当前卡片 ID；桌面壳只接受当前窗口的登记，在前置键盘事件中转发一次并阻止同一 DOM 按键重复处理。Renderer 再检查顶层 ID、实际媒体焦点与全屏状态，沿原卡片关闭及还焦流程执行；换焦、全屏、关闭和页面重载取消登记，视频全屏保留默认 Escape 退出行为。

### 2.2 Web Renderer

Web 负责用户界面和短生命周期交互状态：

- 首页目标与预检；
- 素材、内容、人物声音、模板和自动任务管理；
- CreationTask 阶段工作区；
- 播放器、时间线、字幕和属性检查器；
- 自然语言提案选择、普通精确草稿编辑、撤销和重做；
- 运行状态、阻断原因和修复动作。

Web 不把 localStorage、React state 或聊天消息当作业务事实源。

### 2.3 API

API 是同步领域入口，负责：

- Workspace 和对象权限校验；
- Knowledge、Source、Media、Profile、Plan、CreationTask、Template 和 Automation 的仓储访问；
- 命令校验和状态转换；
- 自然语言意图的上下文组装与类型化提案；
- 普通精确命令或用户应用提案后写入 EditOperation 和 TimelineVersion；
- 能力状态、失败证据和修复动作；
- 向 Worker 提交可恢复作业。

API 不执行长时间媒体渲染，也不建立 Episode、Batch 或内存 fallback。

### 2.4 Worker

Worker 执行可恢复的长任务：

- 来源抓取和内容解析；
- 视频转写、分镜和多模态分析；
- 选题、文案、配音、口型、字幕和封面生成；
- 时间线预览、增量渲染和最终编码；
- 平台发布和数据拉取；
- 失败重试、进度和产物登记。

每个作业必须幂等或带明确的重试边界，并把状态、失败原因和产物引用持久化。

### 2.5 Local Model Runtimes

语音、转写、视觉、向量或其他本地模型可以是独立进程。Supervisor 负责：

- 启动和健康检查；
- 模型文件和运行环境检测；
- 并发、显存或内存限制；
- 标准化能力状态；
- 进程退出和资源清理。

本地多模态采用媒体工具与本地模型分工：媒体探测/切点/波形、语音转写、OCR、按时间采样的视觉理解分别形成带来源的结果。按片段增量分析，限制输入帧数、分辨率和上下文；重计算任务统一经过第3.12节的整机准入，不能各服务自行放行。模型文件大小不等于运行峰值内存，选型须通过目标设备实测。调度仅服务本机现有任务，不引入分布式集群或通用平台。

语音转写默认选择本地 Whisper。云端转写仅在用户主动选择对应供应商后执行；保存云端凭据不改变默认路由，失败不跨供应商回退。设置、预检与执行使用同一选择，语言未指定时自动检测。

0.11 的本地 4B 视觉模型仅在后台素材分析链路运行。用户对话和文字创作由外部文字模型驱动，使用独立配置与运行状态；后台模型不可因对话配置变化而改变路由。对话 Agent 使用 Pi 的会话与工具调用机制，通过受控业务工具读取当前 Workspace 的资料、素材和任务，生成 Plan、Script 或 EditProposal，并在用户确认实际文案与要求、明确开始后推进已有 CreationTask。Pi 会话不是新的生产事实源，不能从模型回复推断用户授权。外部请求只携带本次任务所需的文字上下文和筛选证据，不上传原始媒体，供应商失败须显式报告而不自动切换。

## 3. 核心服务

### 3.1 ProductionRepository

ProductionRepository 是 CreationRequest、Plan、CreationTask、Script、Narration、Timeline、Output 和任务事件的唯一持久化入口。旧 Episode、Batch、repo.today 或模板成功 fallback 不得进入新写链路。

### 3.2 ContentRepository

管理 KnowledgeItem、SourceConnector、SourceItem、内容版本和 ContentUseState。知识库与信息源可以共享检索基础设施，但必须保留不同来源语义。

### 3.3 MediaRepository

管理 MediaAsset、Clip、标签、分析结果、代理文件和 UsageRecord。文件系统路径只在受信任的本地进程中解析，对 Web 和领域层暴露逻辑引用。

### 3.4 ProfileRepository

管理 PersonProfile、VoiceProfile、PronunciationEntry 和版本。用户导入的档案默认可在当前 Workspace 使用；能力是否可执行由对应模型和运行环境单独决定。

### 3.5 AssetIntelligenceService

把长视频和多模态内容转化为可检索生产单元：

- 转写、说话人和静音识别；
- 镜头边界和关键帧；
- 人物、产品、场景、动作、物体、屏幕内容和文字；
- 质量、画幅、安全裁切和可复用性；
- 索引、标签、缺口和低置信复核。

分析结果写入 MediaRepository，不能只存在于模型响应或缓存。描述、OCR、转写和推断保留时间锚点与分析版本；抽帧平均向量不能替代动作顺序理解。缓存按源内容、时间区间、模型及分析参数识别；用户纠正与模型结果分开保存。

后台素材接收绑定用户已选择目录和明确 Workspace；全局路径不得自动复制到所有工作区。发现完整新文件后排队分析，周期补扫和重启恢复复用同一资产状态，避免重复分析；复制中的文件、路径越界、缺盘和模型不可用须显式处理。接收与分析不创建 CreationTask，不覆盖原始媒体。资源调度不得因每次扫描重复加载模型或并行写同一资产。

### 3.6 RetrievalService

按任务规模组合：

- 结构化字段和全文检索；
- 时间范围、标签和来源过滤；
- 可选向量索引和语义重排；
- Workspace、ContentUseState 和任务上下文约束。

小规模数据不强制依赖向量模型；启用向量检索时，索引必须可以从权威内容重建。检索先应用内容使用限制，再组合文字/视觉召回；仅对候选执行必要重排。分别评估召回遗漏、排序错误和库内缺失，不把不可校准的相似度显示为准确概率；索引不可用或降级必须可见。

### 3.7 PlanCompiler

把用户目标、模板和当前能力编译为 Plan：

- 读取可用内容、素材、人物声音和模型状态；
- 形成内容、视觉、声音、字幕、封面和平台策略；
- 标记确认节点、缺失条件和可执行步骤；
- 在用户确认前不启动有成本或外部副作用的作业。

自然语言新建请求先固定数量、关系、素材范围和实际用户要求，缺少关键决定时输出澄清。总目标由ProductionRepository持久化；有限规划窗口沿同一事务展开独立子任务，以请求/窗口身份及输入摘要幂等重放。分页和实际状态聚合不随目标总数一次加载全部内容；每条复用现有制作、版本、调度与授权链，汇总只读取真实子任务。客户端、Pi和手动入口共享这一数量与确认语义，不保留写死单条的旁路。

PlanCompiler 的输出是领域对象，不是聊天回答。

### 3.8 EditCompiler

把自然语言与当前任务上下文编译为 EditIntent、EditProposal 和类型化 EditOperation：

1. Web 发送命令、当前阶段、选中对象和播放位置。
2. API 从 ProductionRepository 读取权威任务和时间线版本。
3. 文字模型只负责理解意图、补全约束和生成候选提案。
4. EditCompiler 校验范围、对象类型、ContentUseState、能力和副作用。
5. Web 展示操作、影响范围、失效依赖和预览差异。
6. 用户选择应用提案后，API 写入 EditOperation 和新 TimelineVersion，CreationTask 指向新版本。
7. 更新依赖有效性；只有明确生成动作才向 Worker 调度媒体作业。普通编辑的交互规则引用[产品规则](product-requirements.md#23-自然语言与精确编辑共享同一事实源)。

当前操作目标与已引用资料分别维护；明确选择任务对象不能被旧素材引用暗中改成素材轮次。每轮提供与实际注册工具一致的能力和当前目标，历史工具失败不定义当前能力。原句、任务、阶段及界面默认选择由宿主绑定；模型只选择当前实际候选，不能重写这些身份事实。用户明确的镜头序号在当前任务版本中解析，不要求先多选界面对象。自动选材在有限候选截取前应用使用限制和实际源时长要求，提交时重新核验。

模型可读取业务能力目录及输入/输出 schema，提交类型化编辑候选；阶段只提供默认能力分组，不代替对象权限或执行前置检查。手动编辑、内置 Pi 和外部 CLI/MCP 复用同一动作校验与持久回执；外部入口由可信成员与请求身份绑定来源，不伪造应用助手轮次。原句作为来源保存，不要求模型把所有动作重新转换成固定自然语言语法。

可写对象必须能在当前版本中被发现：镜头、字幕、配音、音轨片段、已采用图层分别提供实际 ID、修订、单位、关系与必要样式。首页摘要可截断，按 ID 与分页读取必须从完整已授权集合取数，返回真实总数与截断信息，不能对先截断的摘要再分页。已有业务动作只有接入共同目录、对象读面和真实执行入口后才向 Agent 声明可用；schema 枚举项、手工按钮或历史回执不单独构成可调用能力。

模型可在受控编排环境中编写程序组合已有业务工具；工具子调用仍经过原成员、版本、用途及许可校验。媒体脚本须封存代码、参数、输入修订、工具链及摘要，通过既有业务 Owner 和唯一设备协调者在具备实证文件/网络隔离的执行环境中运行；资源许可不等于文件或网络隔离。脚本只能读取本作业授权输入、写入本作业输出，其产物经实测、来源登记与类型化提案进入同一版本链。短预览、正式生成与后台用途沿各自工作类别，不让全部脚本占预览优先级。

Codemode 中的图片来源、配方读取和媒体作业工具返回结构化对象，可直接读取 `items`、`media_job` 等字段；CLI 标准输出则是供外部调用方解析的 JSON 文本。明确工具 ID 的只读 describe 可直接调用共同 API，由服务端核验当前成员权限，不要求先列举；调用、更新和停用仍核验实际版本与当前授权。

Python/Pillow 程序的 `parameters` 是参数对象，`inputs[声明名称]` 与 `outputs[声明名称]` 是宿主绑定的可信文件路径。程序使用 `Image.open(inputs["input.png"])` 读取、`image.save(outputs["panel.png"])` 写入；不能把输出映射项替换成图片字节或 `BytesIO`。首包仅支持当前任务登记的 PNG 输入和单 PNG 输出，字段与命令示例见[CLI 协议](cli.md#pythonpillow-图片来源程序)。

成功 PNG 来源须另经图片图层提案与实际采用进入时间线。预览和正式渲染共同读取授权来源事实，声明实际输入字节、尺寸和图层数；获得设备许可后复核文件摘要、PNG 内容及修订，并记录渲染依赖。脚本作业成功、图层已采用和成片已生成是不同回执，不能互相替代。

可信宿主可注册隔离脚本的版本化工具代理；模型生成的扩展代码不直接加载到持有凭据的宿主进程。模型不得通过任意文件、Shell、数据库写入或自报许可绕过上述执行入口；未具备运行时、隔离、资源档或有效产物契约的能力明确不可执行。新持久字段与渲染语义通过正常源码实现和验证，不由扩展声明自动增加。

### 3.9 DependencyGraphService

维护 ScriptSegment、NarrationSegment、SubtitleCue、TimelineItem、PreviewOutput 和 FinalOutput 的依赖。

每次编辑计算：

- 直接变更对象；
- 需要失效的下游节点；
- 可以保持 valid 的已确认产物；
- 需要重新预览或最终渲染的范围。

Worker 只处理 invalidated 节点。输入摘要未变的 valid 产物可以复用。

局部重算的验收须比较实际受影响集、执行作业与产物摘要，证明未受影响段没有再次执行；最终整片编码或拼接单独记录。来源谱系登记、整阶段缓存及完整输出复用不能替代这一证明。

### 3.10 QualityEvaluationService

在预览和输出阶段执行可解释检查：

- 音视频流、时长和文件完整性；
- 音量、静音、字幕时间和遮挡；
- 画幅、安全区、裁切和平台规格；
- 文案事实来源、重复、节奏和语言一致性；
- 模型或媒体能力不可用；
- 用户偏好与模板约束。

检查结果绑定被观察的实际版本与输出摘要，包含检查范围、片段/时间、依据、可执行修复和 unavailable；过期结果只能回读历史。确定性检查与语义判断分别返回，不把已知静态标题卡、无声片等用户要求直接判为失败。Agent 通过共同 API 读取检查事实；观察成片使用实际预览/输出的有限抽样，来源素材分析不代替合成画面检查。媒体访问和外发沿第 7 节及认证边界，观察工具不获得上传原媒体或扩大授权的旁路。

自动评分只能提出问题和建议，不能替代用户对内容质量的最终确认。

### 3.11 PreferenceService

从用户明确选择、接受、撤销和模板保存中提取可解释偏好。偏好用于排序和默认值，不能静默覆盖 ContentUseState、事实来源或外部副作用确认。

### 3.12 整机资源调度

桌面自动化由同一API启动和关闭低负载到期扫描器，以持久Automation/AutomationRun及唯一到期键认领运行；不启动旧Episode循环或第二个媒体执行器。扫描器保存每次固定输入并调用已有来源、预检和生产入口；当前授权、确认或能力不满足时记录该运行的等待/阻断。媒体工作只交给下述唯一设备协调者，重启回读已有作业与输出。自动化定义、运行、确认及暂停入口仍核验原工作区和服务端成员；无令牌身份快照不提供持续授权。

产品策略的唯一来源是[产品需求第12.1节](product-requirements.md#121-同一台主机的任务安排011)。由单一设备级协调者统一受理全部本地重型调用，包括素材自动/手动分析、配音/声音预览、口型、代理生成、剪辑预览、整片渲染和仍保留的单步重做入口。线程池只负责执行，不能作为另一份排队或许可事实源。所选任务配音片段重做仍由现有creation_job业务Owner受理独立narration_edit单元，使用对应配音资源预算与当前任务局部预览分类，不能借用人物编辑许可。排队保留当前时间线和原声音；只有受许可生成成功、输入版本仍一致且检查点提交后才更新版本与下游依赖。外部文字请求使用独立限额；等待网络结果时不占本地重活许可，客户自备模型连接按[产品第2.6节](product-requirements.md#26-本地优先与用户控制)处理。

- 重活先提交持久化请求，再由协调者准入；包含服务端确定的workspace/member、已有作业/素材引用、输入版本摘要、执行类别、时间策略、依赖、资源需求及检查点。复用已有JobRun/TaskEvent、素材处理记录和Repository事务入口，不复制业务任务或建立并行成片状态机。
- 许可是全机共享额度；不能只用各进程的Semaphore或各模块单线程。单个本地协调者串行决定准入，并对重启、重复进程和租约失效作恢复校验；旧进程/子进程仍活着时不能仅因租约超时再次发放同一硬件额度。恢复先核实并回收/接管旧执行，未知时阻断相关重活。
- 统一入口覆盖手动、定时、Agent工具及重试调用；嵌套阶段复用同一个执行上下文，避免持许可的父任务再次等待子任务许可而死锁。父CreationTask不跨整个流水线占许可；每个耗资源单元完成后归还，并重新公平排队。
- 文件发现和小批数据库更新单独限速。全文件哈希、解码、代理生成、转写和模型推理属于需预算的工作，不能把高磁盘读写藏在“轻量扫描”中。稳定文件登记与深度分析分开，部分分析状态不能冒充完整ready。
- 资源尚未获准的文件不得批量标为正在分析；只认领实际即将执行的单元，或把已预取但未开始的记录明确归回等待。素材的场景检测、转写、视觉批次和向量批次分别保存有效阶段结果；整个文件末尾一次写入不能满足中途让出恢复要求。分段大小须实测，所有子进程至少有有限超时与清理路径，不能在超时后放任其继续持有设备资源。
- 模型常驻占用纳入内存/显存预算；归还执行许可不等于内存已释放。复用已加载模型不能覆盖公平性，不能为少一次加载让同一用户无限连做。CPU线程、FFmpeg解码/编码参数、帧批量、缓存及IO预算使用设备配置；禁止拿一个未经验证的固定CPU百分比作为所有硬件上的性能保证。
- 配音的启动准入预留预计新增峰值内存与系统安全余量；进入受许可运行后，按系统安全余量、实际进程占用及交换使用量持续检查，已分配给本次配音的内存不再作为整份新增可用内存重复要求。模型加载与推理均属于同一受许可单元，实际磁盘读取受统一IO观测和进程优先级约束；额外完整预读不作为加载器限速证明。有限超时覆盖启动、加载、推理和输出，预算依据目标设备与固定输入的完整实测确定。
- CPU成片同样区分启动预留与运行占用：启动保留本机已标定的新增峰值及系统余量；运行检查系统实际安全余量、已核身份进程RSS、显式标定的总线程上限、交换使用量和原CPU/IO门。已分配给本阶段的内存不得再作为整份新增可用内存重复要求。当前有限CPU路径的进程RSS上限不得超过本次已声明的新增峰值；总线程不能拿单个编码器的`threads`参数冒充，缺少真实进程边界时不可放行。减少并行媒体解码是渲染消费者职责，不靠降低系统余量、增加未知资源预算或牺牲指定输出质量解决；临时中间片、字幕与混音也须计入同一许可的磁盘和总时限。
- 协作式让出只在已有持久检查点执行；不可中断能力记录边界，不能显示已暂停。要支持更细粒度取消，必须由相应能力负责人改造子进程控制和临时产物清理，再验证恢复与成片一致性，不能用SIGSTOP冒充资源释放。
- 本地桌面及已验证会话上报播放、录音、编辑活动；只存调度必要状态与最后心跳，不记录输入内容。心跳过期不让离线会话无限占用优先级，也不强制取消其已提交任务。没有可靠会话活动来源时不得宣称已实现整机“闲时”，需标记不可用或使用明确指定时段。
- 调度状态给出等待类别、当前执行单元、最后检查点、可用操作、估时来源及更新时间；成员与工作区权限先过滤再返回队列视图。新队列请求成功表示已安排，不能回复为正在渲染。
- 任务媒体作业的资源拒绝回执来自该请求的同一次准入观察，与等待状态在同一事务写入既有TaskEvent；不重采样补数，也不借日志、全局最新值或其他作业解释当前请求。每请求、重试次数与观察时上次许可代只保留首次未知和首次拒绝各一条，重复轮询或同类观察不追加、不改写时点。原请求、作业、成员、输入摘要及基础版本先核验，界面只接收固定原因和白名单数值，不接收路径、凭据或原始载荷。准入后、取消、失效及重启均可回读同请求历史；历史观察不是实时资源或新许可，不改变业务终态和原运行保护。

验收既要求所有入口不能绕过许可，也要求真实设备操作与媒体连续性；安全可恢复但长时间无法让出的实现不等于多人体验合格。先实现本机保守单重活，再根据目标设备的整机压力测试决定是否增加并发。

### 3.13 持续创作的双层 Agent 循环

创作采用外层持久任务循环与内层有限模型回合。外层协调既有 CreationRequest、CreationTask、JobRun、TimelineVersion、依赖与事件，不另建一套从聊天推断的完成事实；内层只在需要理解、创意规划或语义判断时调用 Pi，返回经过校验的行动建议或业务工具结果。一次对话结束不等于制作目标完成。

外层由用户要求、素材接收/索引更新、作业完成、确认或修改、资源条件变化、定时到期与启动恢复唤醒。循环每次：

1. 从可信成员/Workspace及持久对象重新读取当前目标、范围、期望版本、已确认输入、有效产物、能力与执行条件。
2. 检查是否缺少会改变制作结果或授权范围的重要决定；缺少则提出少量具体澄清并保存等待点，不重复询问已明确的信息。
3. 有有效计划且下一依赖就绪时直接调度确定性工作；需要叙事、目标拆解、语义选材或改变计划时构建有限上下文调用内层。
4. 将内层提出的动作编译为受控业务操作，验证权限、输入版本、依赖、能力、确认与资源条件后提交；模型不能修改这些准入事实。
5. 从真实执行结果验证产物与用户约束，保存结果证据和检查点；输入已变的结果只能保留历史，不能覆盖新版本。
6. 依据真实进展继续、局部重规划、等待相关条件、取消或交付。相同输入与同一阻断不无限重跑模型，迭代、时间和执行资源保持有界。

上述是调度决定，投影到既有任务/作业状态；文件生成、技术检查通过、用户接受分别记录，不能合并为一个模型自报成功。

将后台终态回填到已结束的聊天轮次只证明结果送达，不等于完成步骤 5–6；需要后续语义判断的已批准目标必须能在新事实到达后启动有限 Pi 回合。已明确未提交或被拒且无副作用的参数错误可有限纠正；原请求已执行或副作用未知时先按原身份查询，不盲重放。已知失败或质量问题可依据实际结果、当前版本与授权，在已批准目标内提交可追溯的新修订工作。

计划器确定表达目标、素材证据、制作方式、依赖、验收条件和待决定项。执行器只运行类型化能力并写入真实回执；检查器区分确定性媒体检查与内容质量判断。模型用于意图、叙事、语义匹配及内容建议；身份、数值计算、队列、版本、幂等、资源和状态转换由程序确定。失败恢复只处理受影响依赖，安全释放无法确认时保持保护。

目标数量、规划窗口和运行并发独立：总目标可以很大，但只展开有限工作；候选素材、知识、经验记忆与模型输出均有界。每个窗口和执行单元绑定稳定身份、版本与输入摘要，本地任务和提交通过事务与幂等身份避免重复。远端调用超时或回执丢失时，先区分已确认执行、已确认未执行与结果未知；未知结果不得盲目重放或宣称成功，按供应商可核验回执及幂等能力恢复，不承诺无法验证的远端恰好一次执行或费用。有限窗口只是执行机制，不是用户数量上限，也不承诺素材和能力足够完成任意目标。

每轮记录目标版本、当前动作、等待理由、实际进展、观察结果、模型上下文量与可核验用量；按需取对象与工具说明，避免重复注入完整时间线、历史工具结果或媒体帧。上下文显示、实际计费用量和用户等待时间分别测量，不能互相推算或用模型数量衡量 Agent 能力。

每轮上下文由当前目标/任务事实、适用用户档案、任务相关证据、少量有效经验及当前能力组成。当前要求、事实来源、人工纠正和偏好按用途分别判断，不通过一个总分混合；检索内容作为数据，不作为系统指令或工具授权。工作状态与跨任务记忆的对象规则由领域文档拥有，检索与素材证据分别沿3.5/3.6，偏好沿3.11。

原声口播、旁白配素材、授权人物生成混剪是同一循环中的不同能力依赖组合，不是另一套事实源。人物参考可登记与人物生成可执行分别判断；露脸目标、实际片段和口型产物按当前音频/人物版本绑定。能力缺失、模型不可用或预算未知是明确条件，不以图片入口、配置存在或旧产物冒充能力通过。

心跳服务活动/存活与许可恢复；事件和定时服务已批准目标的唤醒，不周期性无条件调用模型。Pi扩展接入受控工具、上下文与生命周期；持久目标、队列、媒体资源和通知由产品运行系统管理。采用何种框架以必要性和实际消费者决定，不因有成熟框架就替换已有效的任务内核。

用户界面只投影目标、可读方案、真实进度、必要决定、可播放结果和具体修复动作；首次引导建立这一循环所需的最小上下文与实际能力，按所选制作方式补齐条件，不要求一次配置所有模型、人物或内部技术字段。

### 3.14 业务用例、执行契约与组装

HTTP、Pi、CLI与后台作业消费相同的具体业务用例；路由只解析可信输入、调用用例并映射响应。业务/执行不构造HTTP请求、不反射或重入路由函数，不从HTTP响应推定持久结果。

任务、资料、素材和档案类型与模型执行、仓储实例和HTTP对象分离；共享契约只持有实际边界需要的值。具体命令显式传递可信操作者、原请求、期望版本和目标；后台执行使用原持久身份与封存输入，许可来自唯一设备调度者。边界处重新核验身份、源修订与版本，不以调用方自报值授予权限。

预览与正式生成共享必要的媒体编译/执行实现，执行用途及资源配置明确分开。资源需求由实际能力声明，设备协调者消费同一契约；短预览预算依据该用途的本机实测，缺少标定就保持不可用，不从时长比例猜内存或借用整片配置。启动预留、运行占用、全部子进程和临时文件沿第3.12节。

所属仓储是唯一对象写入口；跨对象变化由一个负责人通过同一SQLite事务比较版本并完整提交。文件发布与数据库登记分别保留恢复证据，不能把二者视为一个原子事务；过期产物保留历史，不覆盖新版本。

应用组装负责依赖创建、路由/执行器注册和生命周期。导入纯业务/契约不建数据库、不加载模型、不启动调度；生产运行继续只有一个设备协调者。任务、作业、许可和会话分别拥有自己的既有事实，客户端通过只读投影表达结果。

## 6. 存储

### 6.1 数据库

SQLite 或等价本地数据库保存结构化领域对象、状态、版本、事件、依赖和逻辑文件引用。Repository 是唯一写入口，不允许各模块维护结构不同的旁路数据库。

### 6.2 文件存储

Workspace 文件区建议区分：

- originals：不可变原始资产；
- proxies：预览代理；
- analysis：转写、关键帧和索引派生数据；
- artifacts：配音、字幕、口型、封面和渲染结果；
- outputs：用户可检查的最终输出；
- temp：可回收临时文件。

数据库保存逻辑引用和摘要。真实路径由本地受信任层解析，迁移 Workspace 时可重新绑定。

工程备份包含一致数据库快照及被引用原件/产物清单，保留版本、归属、逻辑引用和摘要；凭据经受保护配置重新绑定，不写入明文包。还原先写入新的根目录并核验引用与输出，缺失原件提供明确重连动作，不静默覆盖旧库。正常重启回读、最终视频导出和可编辑工程备份还原分别验收。

配置外接数据盘时，数据库、模型、派生文件、项目级缓存和临时文件应使用该存储根，应用启动与任务执行前检查磁盘身份、可写性和剩余空间；缺盘不得回退到内置盘。开发源码、依赖及构建缓存同样使用配置的外接位置，具体本机路径由私密配置和当前合同持有。系统交换文件及操作系统自有缓存不属于项目可保证迁移的范围。缓存回收与原始素材/有效产物删除必须区分。旧路径映射可以保留以兼容已有引用，但不能形成第二份可写数据。

### 6.3 任务与事件

长任务状态必须可恢复。进度事件用于界面展示，但最终状态以持久化任务和产物为准。进程崩溃后不能把 running 自动解释为 completed。

## 7. 安全与外部边界

- 所有 API 写入校验 Workspace 一致性。
- Renderer 只能使用 Desktop 或 API 返回的受控引用。
- API 密钥和账号凭据使用系统安全存储。
- 云端模型调用明确展示数据类型、供应商和成本。
- ContentUseState 约束素材用途；它与文件访问权限、账号连接和平台发布确认不是同一概念。
- 删除、覆盖、模型调用和平台发布保留审计事件，不建立产品计费流程。
- 日志不得记录密钥、完整凭据或不必要的用户内容。

## 8. 迁移与退役

产品迁移采用有限状态机：

LEGACY_INVENTORIED
→ NEW_AUTHORITY_FROZEN
→ VERTICAL_SLICE_IMPLEMENTED
→ REAL_CLIENT_VERIFIED
→ OLD_PATH_DISABLED
→ OLD_PATH_REMOVED
→ ABSENCE_VERIFIED
→ MIGRATION_ACCEPTED

旧路径只有在入口、消费者、写接口、fallback、样式和保护旧行为的错误测试全部移除后才算 RETIRED。新界面存在、API 可追踪、构建成功或静态测试通过都不能单独证明迁移完成。

当前实现状态不记录在本文。代码、Git、运行服务和活动任务合同分别提供实时证据。

## 9. 多空间、知识召回与状态投影

认证层解析设备角色、成员和当前空间；Repository/文件访问/工具调用在对象读取前执行私有或显式共享授权。检索先限定可访问集合，再召回与重排；向量结果、缓存、聚合词云和预览链接不得绕过授权。设备资源许可独立于工作空间，继续遵循第3.12节；授权共享不增加并发许可。

导入接收保存批次背景和来源，后台按资源安排自动分析；观察、人工纠正和索引分别版本化。纠正提交后使相关索引失效并增量更新；用户可见生效/更新状态，制作不得无提示消费过期纠正。知识文件解析与网页快照通过现有来源对象保留出处，召回结果携带证据位置，外部文本始终作为资料输入而非工具指令。

Pi只编排受控业务工具：绑定身份、任务、选中对象与版本，检索授权候选、创建编辑提案、按用户选择应用到草稿、按明确动作生成预览；不直接改文件/数据库或自行授予权限。阶段事件与队列状态持久化后供桌面和未来手机/消息入口查询；断线重连返回同一任务事实，不依赖聊天是否打开。事件重放与命令幂等分别处理。

首页、素材与任务对话复用同一应用会话/轮次持久入口，服务端按当前可信成员和空间核验创建、历史、草稿、恢复及停止；活动会话独立于页面导航，历史业务scope仅作归属元数据。每轮由已核实的发送目标快照进入原home/material/task领域入口，逐轮校验对象权限、片段范围及期望版本，历史会话与前端选择均不代替授权。Pi沿现有执行入口承接该会话上下文，不另建Agent或生产状态库；历史任务聊天事件可作明确只读历史投影，新的对话轮次只有一个写入来源，业务TaskEvent继续记录真实领域结果。Renderer只缓存交互草稿并回读应用会话，不从原始Pi日志推定业务成功。停止按轮次关联当前实际子进程，回执与进程释放后记录终态；HTTP断连与停止、聊天停止与制作取消分别处理。

固定引用生命周期遵循[领域模型§7.5](domain-model.md#75-对话会话与轮次)。应用会话Repository对引用修订与草稿修订分别做原子比较，服务端核验真实引用及当前权限。素材写工具把冻结的素材与片段更新时间传入已有命令，由Repository在同一写事务中比较，冲突返回409且不改变对象。

素材库对话将当前素材/片段作为服务端核实的对象范围，标签等普通属性调用现有对象命令，返回持久结果供工作台刷新；它不创建无关创作任务。飞书等消息入口本期后置；后续接入将已绑定发送者、会话及明确目标转换为同一业务助手调用，不另建生产事实源、Pi权限或媒体调度器。后续本机通道可使用官方长连接接收事件，结果回到原消息会话；同一平台消息重复投递只执行一次，执行记录与回复结果分开，回复失败不能重做已完成业务。外部身份绑定遵循[认证边界](auth-workspace-boundary.md#9-主账号邀请与共享授权)。

首页、发布看板和素材词云由授权范围内事实聚合；主账号与成员使用同一后端授权规则，不能只由前端隐藏。展示任务阶段、等待原因、可用时间估算及估算不确定性；没有样本时显示正在估算，不能固定倒计时假装预测。未来手机与企业消息入口复用邀请、上传、作业和事件接口；连接器交付版本依产品范围，不由架构接口存在推定已交付。
