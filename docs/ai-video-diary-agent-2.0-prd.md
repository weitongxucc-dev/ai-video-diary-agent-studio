# AI视频日记 Agent Studio 2.0 PRD

版本：2.0 内测版  
日期：2026-06-06  
定位：macOS 本地内容生产 Agent  

## 1. 版本定位

AI视频日记 Agent Studio 2.0 要从“视频日记 Web 原型”升级为“本地桌面内容生产 Agent”。

2.0 不再只解决一条视频日记从选题到剪映草稿的问题，而是围绕个人创作者的真实生产流程，支持多种视频内容类型、语音指挥创作和剪辑、自动剪辑计划可视化、剪映模板化草稿生成，以及可解释的内容偏好学习。

2.0 的一句话目标：

```text
让创作者在 macOS 上用一个本地 Agent，把素材、想法和语音指令推进成可验证、可回滚、可导入剪映的完整视频草稿。
```

2.0 仍然坚持本地优先：

- 本地读取 Obsidian、视频文件和剪映草稿目录。
- 本地运行 API、Worker、ffmpeg、Whisper 或其他本地处理能力。
- 用户关键判断仍需确认。
- 发布仍由用户人工完成。
- 不做多用户 SaaS，不做自动发布平台。

## 1.1 当前代码落地状态（2026-06-07）

当前仓库已经落地的 2.0 功能：

- 经典老 Windows 像素风应用外壳、侧边栏、顶部栏、底部命令台和可视化剪辑计划页。
- 3 个内容类型模板：视频日记、AI 工具测评、教程演示。
- Episode 级内容模板选择，并已进入选题、整篇口播稿和段落重写提示词。
- `preference_memory` 第一版：active feedback 会聚合为 `prefer` / `avoid` 信号，并进入选题、口播稿和段落重写提示词。
- 底部 typed / transcribed command 指令台：支持预览和执行“继续流程、重新生成选题、生成/重生成口播稿、重写口播段落、生成剪映草稿、更新剪辑计划片段决策”等指令。
- 自动剪辑可视化工作台：可浏览处理后视频、查看原片标记、剪辑计划时间轴、剪辑决策卡、剪映轨道预览。
- 剪辑计划片段人工决策：保留 / 删除 / 复核，并可回滚；确认后会生成 `_confirmed` 二次 preview 再进入草稿包。
- 视频处理链路支持多段合并、长静音处理、本地 Whisper 重录检测、字幕和草稿素材包生成。
- 剪映草稿导入目前是兼容桥方案，会自动尝试写入并记录结果，但不声称已支持剪映 10.7 加密草稿原生写入。
- Creator Profile 已落地为可编辑的创作者画像：身份定位、内容领域、表达风格、偏好表达、禁用表达、好/差样本会进入选题、口播和段落重写提示词。
- 顶部菜单已从装饰性“文件/编辑/视图/工具/帮助”替换为真实工作区入口：内容、画像、运行、设置。
- 视频处理、剪辑计划等高密度区域已加入有界列表和 overflow guard，避免无限下拉和长文本挤出面板。
- 内测日志页已提供运行日志分类、最近错误、脱敏配置快照和可下载错误报告包；报告包包含 `runtime_status.json`、`settings_snapshot_redacted.json`、`last_errors.log`、`episode_manifest.json`、`draft_manifest.json`、`edit_plan.json`。
- 首次配置向导已提供 `/setup` 页面，按基础模型、本地路径、转写能力、信息源四组配置关键依赖，并结合运行健康结果展示修复清单。
- 语音指令台已支持页面内麦克风录音：浏览器 `MediaRecorder` 录音后上传到 `/api/voice/transcribe`，复用本地 ASR / 腾讯云 ASR 转写并回填指令输入框；执行仍需用户预览和确认。
- 长期偏好记忆已支持从反馈候选中人工确认，确认后写入本地 SQLite；用户可以禁用、恢复、删除，并查看来源证据数、影响范围和置信度。禁用/删除的偏好会在后续 prompt history 中被过滤。

仍未完成的 2.0 关键项：

- 全局快捷键唤起语音指令台仍需在 macOS 桌面壳阶段实现。
- 发布评论洞察仍未接入，当前仅支持用户手动发布反馈和确认偏好。
- 剪映模板和基础特效仍需从素材包升级为模板结构：标题卡、章节条、关键词高亮、B-roll 插入点、背景音乐、片头片尾。
- 原生剪映 10.7 加密草稿结构写入。
- macOS 桌面壳、后台 API/Worker 进程管理和 DMG 内测包。

## 1.2 当前交付优先级（2026-06-07）

DMG 是 2.0 的最后交付动作，不应早于核心功能闭环。

当前后续优先级：

## 2. 升级背景

1.0 已经验证了“视频日记”链路：

```text
信息摄入
-> 选题生成
-> 人工复核
-> 口播稿生成
-> 视频处理
-> 字幕 / 封面 / 剪映草稿
-> 发布反馈
```

但从用户角度看，1.0 仍存在几个限制：

- 仍然像一个 localhost Web 工具，启动、配置、运行成本高。
- 核心场景偏“口播视频日记”，对工具测评、教程演示、观点短评、复盘类视频支持不足。
- 自动剪辑过程不够可视化，用户难以判断系统剪了哪里、为什么剪。
- 语音是视频生产的天然输入方式，但当前交互仍以按钮和文本为主。
- 剪映草稿只是导入素材和字幕，还没有形成稳定的视频模板和基础特效体系。
- 反馈学习仍需要从赞踩数字升级为可解释、可禁用、可回滚的偏好记忆。

2.0 的核心升级不是“加更多功能”，而是把产品变成一个可给同事内测的桌面端创作工作台。

## 3. 产品原则

### 3.1 本地优先

用户的视频、知识库、剪映草稿、配置密钥默认保留在本机。网络模型和外部信息源只作为能力扩展，不改变本地生产系统的基本形态。

### 3.2 可视化而非黑箱

自动剪辑必须让用户看到：

- 系统准备剪哪里。
- 为什么建议删除或保留。
- 剪完后时长和结构会如何变化。
- 哪些操作等待确认。
- 如何回滚。

### 3.3 语音是指令，不是聊天

语音能力不是做一个聊天机器人，而是把用户的自然语言转成可预览、可确认、可执行的生产指令。

### 3.4 模板化扩展

2.0 不做万能视频生成器。通过内容类型模板扩展视频风格，每种模板都有明确的选题结构、脚本结构、素材需求、剪映样式和发布文案规则。

### 3.5 人机协作

Agent 负责生成、解析、建议、执行重复劳动；用户负责确认内容判断、录制素材、验证剪映草稿和最终发布。

## 4. 目标用户

### 4.1 第一目标用户

项目发起人本人和同类技术型内容创作者：

- 有 Obsidian 或本地知识库。
- 长期关注 AI 产品、技术实践、项目复盘。
- 需要持续产出视频内容。
- 愿意人工确认关键表达。
- 希望减少选题、脚本、字幕、剪辑、剪映草稿处理成本。

### 4.2 2.0 内测用户

内部同事或小范围朋友：

- 使用 macOS。
- 可以安装未上架 App Store 的内测 DMG。
- 愿意配置本地目录、API Key、ffmpeg、剪映等依赖。
- 愿意反馈启动、配置、剪辑、导入剪映过程中的问题。

### 4.3 后续潜在用户

- AI 产品经理。
- 独立开发者。
- 技术型博主。
- 工具测评创作者。
- 教程类内容创作者。
- 顾问型知识博主。

## 5. 2.0 产品目标

### 5.1 用户目标

- 双击 macOS App 即可进入工作台，不再手动启动前后端。
- 选择视频类型后，获得匹配该类型的选题、脚本、素材建议和剪映模板。
- 用语音表达创作和剪辑意图，系统生成可确认的操作草案。
- 看到自动剪辑计划，包括保留、删除、重复录制、长停顿、字幕依据和置信度。
- 确认后生成精剪 preview，并自动生成和导入剪映草稿。
- 发布后记录表现和主观反馈，让 Agent 更新可解释偏好。

### 5.2 产品目标

- 把 1.0 Web 原型升级为可分享的 macOS 内测客户端。
- 建立“内容类型模板 -> Episode 生产 -> 可视化剪辑计划 -> 剪映模板草稿 -> 反馈学习”的 2.0 闭环。
- 支持至少 3 种视频类型模板。
- 支持至少 8 类语音指令。
- 支持自动剪辑计划可视化和确认执行。
- 支持剪映基础模板和固定特效。
- 支持内测问题定位：日志、依赖状态、失败原因、重试路径。

### 5.3 非目标

2.0 不做：

- App Store 上架。
- Windows 客户端。
- 多用户 SaaS。
- 在线协作。
- 自动发布抖音、小红书、B 站等平台。
- 完整可视化剪辑器。
- 任意剪映特效自由编辑。
- 复杂商业化计费。
- 模型 fine-tune。
- 云端素材库。
- 全网无限爬虫。

## 7. 核心用户旅程

### 7.1 首次安装与配置

用户拿到内测 DMG：

```text
打开 DMG
-> 拖入 Applications
-> 首次打开 App
-> 进入配置向导
-> 选择 Obsidian Vault
-> 选择视频待处理目录
-> 选择输出目录
-> 选择剪映草稿目录
-> 填写 DeepSeek Key
-> 检查 ffmpeg / Whisper / 剪映 / Python
-> 进入今日工作台
```

如果 App 未签名导致 macOS 拦截，内测说明提供：

```text
右键 App -> 打开
或 系统设置 -> 隐私与安全性 -> 仍要打开
```

### 7.2 视频日记生产

```text
用户选择“视频日记”
-> Agent 根据知识库和信息源生成选题
-> 用户确认选题
-> Agent 生成口播稿
-> 用户用语音说“开头更像真实经历”
-> Agent 重写开头并保留版本
-> 用户批准录制
-> 用户录制视频并放入待处理目录
-> Agent 自动转写和生成剪辑计划
-> 用户确认删除重复录制和长停顿
-> Agent 输出精剪版
-> 自动生成并导入剪映草稿
```

### 7.3 AI 工具测评

```text
用户选择“AI 工具测评”
-> 输入或同步工具信息源
-> Agent 生成测评结构：是什么 / 实测体验 / 坑点 / 值不值得用
-> 用户补充真实体验
-> Agent 生成脚本和素材清单
-> 用户录制屏幕和口播
-> Agent 根据模板插入标题卡、章节字幕、关键词高亮
-> 自动导入剪映草稿
```

### 7.4 教程演示

```text
用户选择“教程演示”
-> Agent 生成步骤结构
-> 用户上传屏幕录制
-> Agent 按字幕和步骤切分片段
-> 自动生成章节标题和重点提示
-> 用户语音说“第三步太长，压缩一下”
-> Agent 生成剪辑建议
-> 用户确认后输出教程草稿
```

### 7.5 语音剪辑

用户说：

```text
把开头废话剪掉，从“今天这个工具真正的问题”开始。
```

系统处理：

```text
ASR 转写
-> 找到字幕文本
-> 定位时间点
-> 生成剪辑计划
-> 显示将删除 00:00-00:13
-> 用户确认
-> 执行剪辑
```

### 7.6 自动剪辑计划复核

用户进入剪辑计划台：

```text
原始视频：03:42
精剪预计：02:18

删除建议：
1. 00:00-00:12 开头准备 置信度 91%
2. 00:43-00:58 重复录制第一遍 置信度 82%
3. 01:22-01:29 长停顿 置信度 95%

用户逐项确认或修改
```

### 7.7 发布反馈回流

用户发布后回到 App：

```text
填写发布链接
-> 填写播放 / 点赞 / 评论
-> 语音说“这条开头有点慢，下次直接讲冲突”
-> Agent 生成偏好记忆
-> 用户确认写入
```

### 8.2 首次配置与运行健康

- Obsidian Vault。
- 视频待处理目录。
- 视频输出目录。
- 剪映草稿目录。
- DeepSeek API Key。
- 本地 Whisper Python。
- 本地 Whisper 模型。
- ffmpeg / ffprobe。
- 可选：Product Hunt Token。
- 可选：外部信息源 URL。

健康检查项：

```text
DeepSeek：ready / missing / invalid
Obsidian：ready / missing / empty
ffmpeg：ready / missing
Whisper：ready / missing / invalid_model
视频待处理目录：ready / missing
输出目录：ready / missing
剪映草稿目录：ready / missing / incompatible
```

每个失败项必须提供：

- 失败原因。
- 影响哪个流程。
- 修复动作。
- 最后检查时间。

### 8.5 脚本、分镜和素材建议

2.0 不只生成口播稿，还要根据内容类型生成生产结构。

- 开头 3 秒。
- 主要经历。
- 观点反思。
- 结尾行动建议。
- 标题候选。
- 封面文案。
- 发布文案。
- 评论引导。

AI 工具测评输出：

- 一句话结论。
- 工具介绍。
- 使用场景。
- 实测体验。
- 坑点。
- 推荐人群。
- 不推荐人群。
- 标题候选。
- 工具链接。
- 产品截图需求。

- 教程目标。
- 步骤列表。
- 每步口播提示。
- 屏幕录制需求。
- 重点提示字幕。
- 常见错误提醒。
- 结尾总结。

所有脚本必须支持：

- 编辑。
- 保存。
- 整体重新生成。
- 分段重新生成。
- 版本历史。
- 恢复旧版本。
- 批准录制。

### 8.6 语音指令工作流

2.0 每个核心页面提供语音输入入口。

基础流程：

```text
按住说话 / 快捷键唤起
-> ASR 转写
-> LLM 解析意图
-> 生成操作草案
-> 展示确认卡
-> 用户确认或取消
-> 执行
-> 写入操作历史
```

支持意图：

```text
topic_feedback
script_rewrite
script_shorten
script_tone_change
timeline_cut
retake_remove
silence_tighten
subtitle_edit
keyword_highlight
effect_apply
template_switch
draft_regenerate
publish_feedback
preference_update
```

语音示例：

```text
这个选题太泛，换成更像真实经历的角度。
开头别那么官方，改成我昨天真实遇到的事。
第二段压缩到 20 秒。
从我说“今天这个工具”那里开始。
把重复讲的第一遍删掉。
所有 AI 工具名都高亮。
这条用工具测评模板。
背景音乐小一点。
这条已经发布了，开头太慢，下次直接讲冲突。
```

风险分级：

- 低风险：生成候选、改写建议、记录反馈，可直接执行并保留历史。
- 中风险：修改脚本、字幕、模板，执行后必须保留版本。
- 高风险：剪视频、覆盖 preview、导入剪映，必须先预览和确认。

### 8.7 自动剪辑计划可视化

2.0 必须提供“剪辑计划台”。

目标：

```text
让用户看懂系统准备剪哪里、为什么剪、剪完会怎样，并可以确认、调整、回滚。
```

剪辑计划台包含：

- 生产链路状态。
- 原始视频时长。
- 预计精剪时长。
- 时间轴概览。
- 删除 / 保留 / 待确认片段。
- 字幕依据。
- 重复录制对比。
- 长停顿检测。
- 置信度。
- 用户确认状态。
- 预览 / 执行 / 回滚按钮。

时间轴颜色：

```text
绿色：保留
红色：删除
黄色：建议删除，等待确认
蓝色：字幕重点
紫色：贴纸 / 特效 / 标题卡
灰色：静音 / 空白
```

片段详情：

```text
时间：00:43 - 00:58
类型：重复录制
原因：与 01:03 - 01:18 内容相似，后一版表达更完整
置信度：82%
字幕：这里不是功能不够，而是...
建议：删除前一版
操作：预览 / 删除 / 保留 / 取消
```

剪辑计划必须先保存为结构化数据，不能直接改源文件。

### 8.8 视频处理能力

2.0 支持以下输入模式：

```text
planned_single：计划内单条视频
planned_batch：计划内多段拼剪
ad_hoc_single：临时单条视频
ad_hoc_batch：临时多段拼剪
screen_demo：教程屏幕录制
```

视频处理链路：

```text
source clips
-> ordered merge
-> audio extract
-> ASR transcription
-> subtitle alignment
-> silence detection
-> retake detection
-> edit plan generation
-> user confirmation
-> conservative cut
-> speed / loudness pass
-> final subtitle generation
-> cover generation
-> template effects
-> draft package
-> Jianying import
```

必须保留：

- 源视频。
- 转写字幕。
- 剪辑计划。
- 精剪 preview。
- 草稿包 manifest。
- 导入剪映状态。

不得自动删除源文件。

### 8.9 剪映模板和基础特效

2.0 不做任意特效编辑，只做固定模板。

至少支持 3 个模板：

```text
diary_minimal：日记简洁版
tool_review：AI 工具测评版
tutorial_demo：教程演示版
```

基础元素：

- 标题卡。
- 章节字幕条。
- 关键词高亮。
- 重点句大字贴纸。
- 封面。
- B-roll 插入点。
- 简单转场。
- 背景音乐音量。
- 片头。
- 片尾。

剪映导入前必须展示草稿结构：

```text
轨道 1：主视频
轨道 2：字幕
轨道 3：标题贴纸
轨道 4：关键词高亮
轨道 5：背景音乐
轨道 6：封面
```

导入策略：

- 自动尝试导入剪映草稿箱。
- 成功后显示草稿路径。
- 失败后保留素材包和 manifest。
- 提供重试导入。
- 提醒用户打开剪映人工验证。

### 8.10 可解释偏好学习

2.0 的学习对象不再只是赞踩数字。

偏好记忆字段：

```text
id
类型：topic / script / edit / title / template / publish
内容
来源操作
置信度
影响范围
启用状态
创建时间
最近使用时间
可回滚
```

偏好示例：

```text
喜欢真实经历开头。
不喜欢太官方的表达。
标题需要有冲突感。
教程类视频要步骤清楚。
工具测评要先讲实际体验。
重复录制时倾向保留后一版。
```

用户可以：

- 查看偏好。
- 禁用偏好。
- 恢复偏好。
- 删除偏好。
- 查看偏好来自哪次操作。
- 查看偏好如何影响下一次生成。

### 8.11 内测日志和问题反馈

内测版必须让问题可定位。

日志模块展示：

- API 启动日志。
- Worker 启动日志。
- 视频处理日志。
- ASR 日志。
- 剪映导入日志。
- 最近错误。
- 配置快照，隐藏密钥。

错误报告包包含：

```text
runtime_status.json
settings_snapshot_redacted.json
last_errors.log
episode_manifest.json
draft_manifest.json
edit_plan.json
```

不得包含：

- API Key 明文。
- 用户完整 Obsidian 内容。
- 未经用户选择的视频文件。
- 剪映私有配置原文。

### 8.12 UI 和交互设计系统

2.0 必须继续坚持 1.0 已经形成的老 Windows 像素风、点阵字体和复古电脑控制台气质，但需要从“页面风格”升级为“桌面 Agent 设计系统”。

详细 UI 规范以根目录 `WINDOWS_PIXEL_UI_GUIDE.md` 为准。本文档描述产品需求，视觉落地、禁用色、组件规范和新增页面检查清单由该规范约束。

UI 的核心目标：

```text
看起来像一台可信的复古生产机器，
用起来像一个高信息密度的现代创作工作台。
```

#### 8.12.1 视觉定位

视觉关键词：

```text
老 Windows
像素风
点阵字体
桌面软件
创作控制台
高信息密度
可解释 Agent
```

2.0 的 UI 不做现代 SaaS，不做游戏首页，也不做纯聊天界面。它应该像一个“复古电脑里的视频生产控制台”：

- 有窗口标题栏。
- 有菜单栏。
- 有工具栏。
- 有左侧模块导航。
- 有中间生产工作区。
- 有右侧 Agent 状态。
- 有底部语音指令台。
- 有清晰的表格、时间轴、状态灯和操作历史。

#### 8.12.2 设计原则

1. 像素风必须服务信息，不做无意义装饰。
2. 所有自动行为必须可视化：状态、原因、进度、失败、重试路径。
3. 页面内部必须有明确分区，避免大空白面板。
4. 点阵字体用于品牌、标题、状态、数字、按钮、表格标签；长段正文必须保持可读。
5. 所有控件遵循硬边框、硬阴影、零圆角。
6. 交互反馈要像桌面软件：按下、选中、禁用、处理中、失败都要明确。
7. 语音不是聊天窗口，而是“命令输入 + 解析结果 + 等待确认”的指令台。
8. 自动剪辑不是黑箱，而是“剪辑计划 + 时间轴 + 字幕依据 + 可回滚操作”。

#### 8.12.3 视觉规则

基础规则：

```text
border-radius: 0
border: 2px solid black
box-shadow: 3px 3px 0 black
spacing: 4 / 8 / 12 / 16px
```

颜色建议：

```text
主背景：复古米白 / 浅灰米色
面板背景：系统灰 / 淡奶油色
主文字：近黑
边框：黑色硬边框
主按钮：Windows 蓝
成功：小面积状态绿
警告：小面积状态橙
危险：小面积状态红
处理中：Windows 蓝 / 小状态芯片
待确认：灰白系统面板 + 状态文字
```

禁止：

- 大面积渐变。
- 玻璃拟态。
- 现代圆角卡片。
- 软阴影。
- 胶囊按钮。
- 大面积紫蓝科技风。
- 营销式 hero。
- 过度卡通游戏化。
- 黑绿终端控制台风。
- 大面积彩色统计卡片。

#### 8.12.4 字体策略

2.0 坚持点阵字体，但需要分层使用。

字体层级：

```text
品牌标题：点阵字体
模块标题：点阵字体
状态标签：点阵字体
按钮：点阵字体
数字和计数器：点阵字体
表格列名：点阵字体
长段脚本正文：清晰中文 UI 字体或更高可读性的等宽字体
字幕文本：优先可读，不强制点阵
```

原因：口播稿、字幕、剪辑理由会出现大量中文长文本，如果全部使用低分辨率点阵字体，内测用户长时间编辑会疲劳。风格可以保持点阵，但正文阅读不能牺牲。

#### 8.12.5 页面框架

2.0 桌面 UI 使用统一应用外壳：

```text
┌──────────────────────────────────────────────┐
│ 标题栏：AI视频日记 Agent Studio v2.0          │
├──────────────────────────────────────────────┤
│ 菜单栏：文件 编辑 视图 工具 Agent 帮助         │
├──────────────────────────────────────────────┤
│ 工具栏：返回 / 今日 Episode / 搜索 / 运行状态 │
├──────────┬───────────────────────┬───────────┤
│ 左侧导航 │ 中央生产工作区          │ 右侧状态  │
│          │                       │ Agent 面板 │
├──────────┴───────────────────────┴───────────┤
│ 底部语音指令台 / 当前命令 / 最近操作历史       │
└──────────────────────────────────────────────┘
```

左侧导航：

- 今日工作台。
- 内容模板。
- 选题池。
- 脚本 / 分镜。
- 剪辑计划。
- 视频处理。
- 剪映草稿。
- 素材库。
- 反馈学习。
- 运行健康。
- 设置。
- 日志。

右侧 Agent 面板：

- 当前 Agent 状态。
- 依赖健康。
- 正在运行的任务。
- 失败原因。
- 下一个动作。
- 偏好学习摘要。

底部语音指令台：

- 按住说话。
- 转写文本。
- 解析出的意图。
- 风险等级。
- 等待确认的动作。
- 最近 5 条命令历史。

#### 8.12.6 核心页面 UI 要求

今日工作台：

- 保留 STAGE 关卡式流程条。
- 每个节点是独立像素卡片。
- 当前阶段突出显示。
- 中央任务面板使用老 Windows 灰色系统面板。
- 任务面板内部必须分栏：任务提示、今日队列、Agent 下一步。
- 四个统计卡片必须有辅助信息和像素进度条。
- 统计卡片主体统一系统灰，颜色只用于小状态条或小芯片。

内容模板页：

- 使用“模板卡带 / 软件盒”式卡片。
- 每个模板展示：适合场景、推荐时长、素材需求、剪映样式。
- 不用现代营销卡片。
- 当前选中模板像旧 Windows 列表选中态。

脚本 / 分镜页：

- 左侧为脚本段落树。
- 中间为可编辑脚本文本。
- 右侧为发布素材、封面文案、版本历史。
- 语音修改后显示“修改草案卡”。
- 每次 AI 重写都生成版本，不覆盖旧稿。

剪辑计划页：

- 顶部展示生产链路。
- 中部展示视频浏览窗口、原片标记和剪辑计划时间轴。
- 下方展示删除 / 保留 / 待确认片段列表。
- 右侧展示当前片段详情。
- 高风险操作必须有确认弹窗。
- 原片标记只负责浏览跳转，不显示剪辑动作。
- 剪辑计划时间轴只用小动作芯片表达删除、保留、复核、字幕，不使用红绿紫黄大色块。

视频处理页：

- 清楚区分单条精剪、多段拼剪、临时处理、屏幕录制。
- 每个视频文件显示来源、状态、处理链路、输出结果。
- 不能只显示文件名列表。

剪映草稿页：

- 展示素材包、导入状态、草稿路径。
- 成功显示“已自动导入”。
- 失败显示“重试导入剪映”。
- 展示剪映轨道结构：视频、字幕、标题贴纸、关键词高亮、背景音乐、封面。

运行健康页：

- 使用三列表格：依赖 / 状态 / 修复动作。
- 状态使用像素灯或块状进度。
- 每个失败项必须可跳到设置字段。

日志页：

- 像旧 Windows 日志查看器。
- 支持按 API、Worker、视频处理、剪映导入筛选。
- 错误行使用红色像素标记。
- 支持导出错误报告包。

#### 8.12.7 自动剪辑可视化组件

剪辑计划时间轴是 2.0 的核心 UI 组件。

剪辑计划页必须区分两层：

```text
原片标记：用于浏览源视频和跳转片段，不代表剪辑动作。
剪辑计划时间轴：用于展示 Agent 准备如何剪辑和导入成片。
```

时间轴必须支持：

- 原始时长。
- 精剪预计时长。
- 保留片段。
- 删除片段。
- 待确认片段。
- 语音指令定位片段。
- 字幕高亮片段。
- 特效 / 贴纸片段。

结构示例：

```text
源视频：M1 00:00 开头 | M2 00:07 冲突 | M3 00:28 案例
剪辑计划：[开头 删除] [冲突 保留] [卡顿 复核] [结尾 字幕]
```

视觉要求：

- 原片标记使用灰色 Windows 小按钮，不使用动作色块。
- 剪辑计划轨道使用灰色凹陷面板。
- 片段块主体使用灰色系统控件。
- 动作通过小的 `timeline-action-chip` 表达。
- 不允许整块片段使用红、绿、紫、黄大面积背景。

片段卡片必须显示：

```text
时间范围
动作：保留 / 删除 / 待确认
原因类型
字幕依据
置信度
用户决定
预览 / 保留 / 删除 / 回滚
```

#### 8.12.8 语音指令 UI

语音指令不使用聊天气泡作为主界面，而使用“命令台”。

命令台是 Windows 工具栏，不是黑绿终端。

命令台结构：

```text
> 用户原话
转写：把开头废话剪掉，从“今天这个工具”开始
解析：timeline_cut
目标：删除 00:00-00:13
风险：高
状态：等待确认
操作：预览 / 执行 / 取消
```

语音确认策略：

- 脚本改写：可以直接生成新版本。
- 字幕修改：生成修改草案，用户确认保存。
- 时间轴剪辑：必须先生成剪辑计划。
- 剪映导入：必须展示导入状态，不静默失败。

#### 8.12.9 像素 Agent 形象

像素机器人继续作为产品主角色，但 2.0 要让它承担状态表达功能。

机器人状态：

```text
idle：空闲
thinking：生成中
listening：正在听语音
processing：处理视频
warning：发现问题
success：任务完成
failed：处理失败
```

动画原则：

- 只做轻量像素动画。
- 可以有眨眼、屏幕发光、天线闪烁、加载点阵。
- 不做大面积动效。
- 不能影响信息阅读。
- 支持减少动画设置。

#### 8.12.11 可读性与响应式

2.0 是桌面优先，不追求移动端完整体验。

桌面目标尺寸：

```text
主目标：1440 x 900
最低可用：1280 x 800
宽屏优化：1920 x 1080
```

要求：

- 文本不能溢出按钮。
- 表格状态不能换行导致行高失控。
- 右侧状态面板不能挤压主工作区。
- 点阵字体不使用负字距。
- 不用视口宽度缩放字体。
- 所有固定格式控件要有稳定宽高。

#### 8.12.12 UI 验收标准

2.0 UI 完成时必须满足：

1. 老 Windows 像素风一眼可识别。
2. 点阵字体成为品牌气质的一部分。
3. 页面不是空面板，而是高信息密度控制台。
4. 用户能在今日工作台 10 秒内知道下一步要做什么。
5. 用户能在剪辑计划页看懂系统准备剪哪里和为什么剪。
6. 用户能看到语音指令被解析成什么动作。
7. 高风险操作都有确认和回滚。
8. 剪映导入成功或失败状态明确。
9. 所有核心页面视觉一致。
10. 内测用户不需要理解技术细节也能完成流程。

## 11. 技术架构

建议结构：

```text
apps/web       Next.js 前端 UI
apps/api       FastAPI 本地 API
apps/desktop   Tauri macOS 客户端
apps/worker    可选：独立后台任务入口
```

macOS App 负责：

- 启动本地 API。
- 启动 Worker。
- 管理进程生命周期。
- 展示 WebView。
- 打开本地目录。
- 发送系统通知。
- 管理菜单栏状态。
- 提供麦克风输入入口。
- 打包 DMG。

API 负责：

- Episode 状态。
- 内容模板。
- 选题和脚本生成。
- 语音指令解析。
- 剪辑计划生成。
- 视频处理。
- 剪映草稿生成和导入。
- 偏好学习。

Worker 负责：

- 定时信息摄入。
- 文件夹监听。
- 视频处理任务。
- 剪映导入任务。
- 失败重试。

## 12. 安全与隐私

2.0 必须遵守：

- API Key 不在前端明文展示。
- 配置导出时隐藏密钥。
- 日志不得包含完整密钥。
- 默认不上传视频文件。
- 默认不上传完整 Obsidian 内容。
- 错误报告需要用户确认后导出。
- 剪映草稿写入前检查目标目录。
- 不自动删除源视频。

## 13. 成功指标

内测阶段指标：

- 3 名以上同事能成功打开 macOS App。
- 80% 首次配置项能在 15 分钟内完成。
- 至少 3 种内容模板可生成脚本。
- 至少 5 类语音指令可成功解析并生成操作草案。
- 至少 1 条视频可以走完：导入 -> 剪辑计划 -> preview -> 剪映草稿。
- 剪辑计划中每个删除片段都有理由和字幕依据。
- 剪映导入失败时能看到明确原因并重试。
- 发布反馈能生成至少 1 条可解释偏好记忆。

## 16. 风险与应对

### 16.1 macOS 安全拦截

风险：未签名 App 被 macOS 拦截。  
应对：内测说明提供右键打开和隐私设置路径。后续可考虑开发者签名和 notarization。

### 16.2 Python / ffmpeg / Whisper 依赖复杂

风险：同事机器环境不一致。  
应对：先做依赖检查和修复引导，不在 2.0 首版强行完整内置所有依赖。

### 16.3 剪映草稿结构变化

风险：剪映版本升级导致导入失败。  
应对：保留素材包 fallback，记录 manifest，支持重试和人工验证。

### 16.4 语音指令误解析

风险：错误理解用户剪辑意图。  
应对：高风险操作必须生成操作草案并等待确认，不直接剪视频。

### 16.5 自动剪辑不被信任

风险：用户不知道系统为什么剪掉某段。  
应对：每个删除建议必须展示字幕依据、理由、置信度和可回滚操作。

### 16.6 多模板导致范围膨胀

风险：产品变成泛化视频工具。  
应对：2.0 只做 3 个模板，每个模板聚焦明确内容结构。

## 17. 待确认问题

1. 2.0 首个内测包是否必须内置 API 和 Worker，还是允许用户先通过本机 Python 环境运行。
2. 语音 ASR 首版使用本地 Whisper，还是允许外部 ASR 作为 fallback。
3. 剪映模板首版优先做哪 3 个特效：标题卡、章节条、关键词高亮是否足够。
4. 是否需要支持全局快捷键唤起语音，还是先只在 App 内按住说话。
5. 内测同事是否都使用同一版本剪映。
6. 是否需要在 2.0 中支持屏幕录制，还是只处理用户已有录屏文件。

## 18. 2.0 总结

2.0 的重点不是把产品变得更大，而是让它变得更像一个真实可用的创作者桌面 Agent。

它应该做到：

```text
能启动
能配置
能理解不同视频类型
能听懂用户的语音创作意图
能把自动剪辑过程讲清楚
能生成可验证的剪映草稿
能从发布反馈中学习用户风格
```

最终形态：

```text
一个 macOS 本地 Agent Studio，
帮助个人创作者把知识、素材、语音想法和视频文件，
变成可确认、可回滚、可导入剪映的视频草稿。
```
