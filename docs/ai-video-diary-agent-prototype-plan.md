# AI视频日记 Agent Studio 原型规划

## 1. 原型目标

原型要验证三件事：

1. 用户每天打开系统后，能立刻知道当前需要做什么。
2. 用户能信任 Agent 给出的选题，因为每个选题都有来源依据。
3. 用户能从选题一路推进到剪映草稿箱，而不是在多个工具之间迷路。

原型不是营销官网，也不是聊天机器人。第一版应该像一个内容生产控制台。


## 3. 全局视觉方向

风格关键词：

```text
像素风
工作台
清晰
可信
克制
信息密度适中
产品经理/创作者友好
```

视觉基调：

```text
像素风 Agent Studio
浅色桌面工作台
像素图标导航
像素机器人助手
流程状态仪表盘
高信息密度卡片
```

界面应参考“像素风 AI 工作台”方向：左侧是像素图标菜单，中间是今日生产流程和任务卡，右侧是像素 Agent 状态面板。整体要像一个认真可用的创作者控制台，而不是游戏首页。

不采用：

```text
大面积营销式 hero
过度科技感渐变
聊天机器人占满首页
卡片堆砌但没有流程
花哨动效
传统企业 SaaS 模板感
```

建议色彩：

- 主背景：浅灰白。
- 主文字：深灰/近黑。
- 强调色：青色用于 Agent 状态，橙色用于人工待办。
- 成功状态：绿色。
- 风险状态：红色。

像素风设计要求：

- 图标使用像素风或像素化处理，保持边缘清晰。
- Agent 形象使用像素机器人，作为右侧状态面板和空状态的核心角色。
- 可加入小型像素装饰，例如星光、纸飞机、剪刀、文件夹、灯泡、上传云朵，但不能喧宾夺主。
- 卡片使用 1px 边框、浅色底、轻阴影或无阴影。
- 按钮可以更实用，主按钮用高饱和蓝色，状态按钮保持清晰。
- 流程节点必须一眼可读，不能因为像素风牺牲信息识别。
- 字体仍使用清晰中文 UI 字体；像素字体只用于小装饰或品牌标题，不用于正文。

品牌元素：

```text
产品名：AI视频日记 Agent Studio
主角色：像素机器人 Agent
辅助角色：可选像素宠物/桌面小物，用于空状态和鼓励提示
品牌感：温暖、聪明、有行动力，但保持专业
```

## 4. 页面原型规划

### 4.1 今日工作台

页面目的：让用户一眼知道今天的视频进度和当前动作。

布局：

```text
顶部：
AI视频日记 Day 001
日期
主题状态

中部：
横向流程进度条

下方左侧：
今日候选选题摘要

下方中间：
当前任务卡

右侧：
Agent 活动流
```

视觉要求：

- 顶部显示产品名和像素 Logo。
- 流程进度条每个节点配像素图标，例如信息摄入、灯泡、剪贴板、上传、机器人、图片、剪刀、纸飞机。
- 右侧 Agent 状态面板使用大号像素机器人插画，展示“今天我已读取多少笔记、同步多少产品、生成多少选题”。
- 当前任务卡可以加入小型像素人物或桌面插画，但信息优先级必须高于装饰。

流程进度条：

```text
信息摄入
选题生成
选题复核
口播稿
视频等待
AI 处理
封面
剪映草稿
发布反馈
```

当前任务卡示例：

```text
当前需要你做：
确认今日选题

Agent 已生成 5 个候选选题，其中 2 个和你的 Obsidian 笔记强相关，1 个来自 Product Hunt 今日新品。

按钮：
查看选题池
重新生成
暂停今日任务
```

关键交互：

- 点击流程节点进入对应页面。
- 当前人工任务必须突出。
- Agent 自动任务显示进度，不要求用户理解技术细节。

空状态：

```text
今天还没有创建视频任务
按钮：创建今日任务
```

错误状态：

```text
Product Hunt 同步失败
按钮：查看原因 / 重试 / 暂时跳过
```

### 4.2 选题池

页面目的：让用户选择今天拍什么，并理解推荐原因。

布局：

```text
左侧：选题卡片列表
中间：选题详情
右侧：来源依据和反馈操作
```

选题卡片字段：

```text
标题
一句话观点
推荐指数
来源标签：Obsidian / Product Hunt / 观猹 / 手动链接
状态：待确认 / 已踩 / 已选中
```

选题详情字段：

```text
核心观点
为什么今天值得拍
适合受众
3分钟结构
可能争议点
Agent 判断
```

来源依据区：

```text
Obsidian:
- [[AI产品留存问题]]
- [[用户习惯比功能强更重要]]

Product Hunt:
- Food tracking AI product

观猹:
- 某 AI 健康管理工具

历史反馈:
- 你曾点赞“功能强但没人每天用”的产品判断类选题
```

操作：

```text
通过并生成口播稿
踩这个选题
换一个角度
更适合企业老板
更像真实日记
更犀利
手动编辑标题
```

交互重点：

- 通过后进入口播稿生成。
- 踩时弹出轻量原因选择：太泛、没新意、和我不相关、表达太营销、已经讲过。
- 反馈写入偏好库。

### 4.3 口播稿复核

页面目的：让用户高效检查并修改 AI 生成的脚本。

布局：

```text
左侧：脚本结构导航
中间：分段稿件编辑区
右侧：标题/封面/发布文案素材
```

脚本结构：

```text
开头 3 秒钩子
为什么今天聊这个
原因 1
原因 2
原因 3
我的判断
结尾金句
```

每段组件：

```text
段落标题
预计时长
正文
赞
踩
重写本段
更口语
更短
更犀利
手动编辑
```

右侧素材：

```text
标题候选 3 个
封面文案
抖音发布文案
评论区引导
剪辑提示
```

确认按钮：

```text
确认脚本，等待录制视频
```

重要状态：

```text
脚本已确认
下一步：请录制视频并上传，或放入监听文件夹
```

### 4.4 视频处理

页面目的：展示视频从上传到处理完成的状态。

布局：

```text
顶部：视频输入方式
中部：处理流程
下方：preview 和字幕
右侧：处理日志摘要
```

视频输入方式：

```text
上传视频
或
监听文件夹：
/Users/Zhuanz/Movies/AI视频日记/01_待处理视频
```

处理流程：

```text
检测视频
提取音频
语音转写
生成字幕
检测长停顿
基础剪辑
视频加速
音量标准化
生成 preview
```

字幕编辑：

- SRT 列表按时间显示。
- 支持直接修改错字。
- 支持合并/拆分字幕。

preview 区：

- 播放处理后视频。
- 显示原始时长和处理后时长。
- 显示加速倍率。

操作：

```text
重新转写
重新生成字幕
重新处理视频
确认进入封面和草稿生成
```

### 4.5 封面生成

## 5. 关键用户路径

### 5.1 每日选题路径

```text
打开今日工作台
-> 查看当前任务
-> 进入选题池
-> 查看来源依据
-> 选择一个选题
-> 点击通过并生成口播稿
```

### 5.2 脚本复核路径

```text
进入口播稿
-> 浏览结构
-> 对不满意段落点踩
-> 选择“更口语”
-> Agent 重写本段
-> 用户手动改一句
-> 确认脚本
```

### 5.3 视频生产路径

```text
录制视频
-> 上传或放入监听文件夹
-> 系统自动转写和处理
-> 用户检查字幕
-> 用户确认封面
-> 用户生成剪映草稿
-> 打开剪映发布
```

### 5.4 反馈回流路径

```text
标记已发布
-> 输入播放/点赞/评论数据
-> Agent 更新偏好
-> 次日选题引用这些反馈
```

## 6. 原型阶段计划

### Phase 1: 低保真线框

目标：验证信息架构和每日流程。

页面：

- 今日工作台
- 选题池
- 口播稿复核
- 视频处理
- 剪映草稿

交付：

- 页面线框。
- 关键用户路径。
- 主要状态。

### Phase 2: 中保真交互原型

目标：验证人工复核是否顺手。

增加：

- 赞/踩反馈交互。
- 来源依据展开。
- 脚本分段重写。
- 视频处理进度。
- 草稿失败重试。

### Phase 3: 高保真 MVP 原型

目标：指导前端开发。

增加：

- 视觉规范。
- 组件状态。
- 空状态。
- 错误状态。
- 表单和按钮文案。
- 响应式桌面布局。

## 9. 原型验收标准

原型完成后，应能用点击路径演示：

1. 用户从今日工作台进入选题池。
2. 用户查看选题的 Obsidian、Product Hunt、观猹来源依据。
3. 用户确认选题并生成口播稿。
4. 用户对脚本段落点踩并触发重写。
5. 用户确认脚本后进入等待视频状态。
6. 用户上传视频后看到处理进度。
7. 用户确认封面并生成剪映草稿。
8. 用户标记发布并看到偏好学习记录更新。

## 10. 需要后续确认的问题

1. Product Hunt 第一版是否需要完整 OAuth，还是先使用用户手动配置 developer token。
2. 观猹/Watcha 是否有可稳定调用的接口；如果没有，第一版先做手动链接解析。
3. 剪映草稿技术 Spike 采用 CapCut Mate 还是 pyJianYingDraft 先行。
4. 第一版是否需要移动端适配；建议先只做桌面端。
5. Obsidian 是否只读；建议第一版只读，不写回用户笔记。
