# AI 视频日记 Agent Studio 产品需求

状态：当前主线基线
更新：2026-08-25
阶段：macOS 小范围内部测试

## 1. 产品目标

为由一名操作员负责出片的知识内容团队提供一台本地优先的 AI 内容生产工作站。系统从团队维护的信息源自动找选题，使用授权克隆声音和已审核素材库，批量生成抖音优先的 9:16 旁白+B-roll 初版成片。新建内容默认以 90 秒为目标，但时长是工作区级可配置项，不得将 90 秒写死；用户可生成 5 分钟及更长的视频。

系统可自动推进到最终成片审核，但不自动发布。事实无来源、声音无授权、素材未审核或本地模型未就绪时必须阻断，不允许静默降级或伪造成功。

## 2. 目标用户

产品用户是知识口播、AI 工具观察和教程类内容团队中的单操作员。一个工作区对应一套品牌规则、多个已授权声音和一个本地素材库。当前不建设多人实时协作、多客户项目管理或云端渲染集群。

## 3. 主生产链

```text
配置品牌、授权声音库、默认成片时长与来源池
→ 扫描原始素材并分析镜头
→ 确认版权和品牌安全，形成可用素材库
→ 创建批次
→ 自动选题和事实门禁
→ 自动文案和授权声音配音
→ 根据文案语义、旁白时长和镜头画面从可用库选片
→ 固定品牌模板编排与渲染
→ 最终成片集中审核
→ 导出 MP4、字幕和剪映兼容草稿
→ 人工上传发布
```

每个阶段必须保存当前 Episode 状态；失败时说明原因、影响和修复动作，不允许用虚假成功或静默回退掩盖失败。

### 3.1 声音库与选择

- 一个工作区可保存多个经授权的声音档案，每个档案包含参考音频、参考文字、授权状态、模型状态和版本信息。
- 工作区必须有一个默认声音；创建 Episode 时默认继承它。
- 用户可在单个 Episode 中临时选择其他声音，不改变工作区默认值。
- 配音缓存必须按“文案+声音档案版本+模型”隔离，避免更换人声后误用旧音频。

### 3.2 文案与成片时长

- 默认目标时长为 90 秒，工作区可修改可接受的最短和最长时长，当前产品边界为 5–1800 秒。
- 文案生成、配音、镜头数量、时间线与渲染必须使用同一个目标时长，不能只改 UI 而下游仍按 90 秒处理。
- 单个 Episode 允许覆盖工作区默认时长，用户制作 5 分钟或更长视频时不应被短视频预设阻断。

### 3.3 画面理解与素材治理

- 长素材必须先按画面变化分段，再对多帧画面、台词/转写和时间信息进行联合理解；仅凭文件名或单帧不能作为最终选片依据。
- 系统为每个片段生成系统标签，至少覆盖人物/环境/物体/动作/景别/镜头运动/用途/质量；标签必须可搜索、可筛选、可解释。
- 用户可新建、重命名和组织自定义标签夹，也可将任意片段手动放入标签夹；用户分类与系统标签并存，不互相覆盖。
- 素材库必须展示各类片段数量、可用时长、历史使用次数和最近使用时间，并提示素材过多与缺口。
- 自动混剪默认惩罚近期高频使用的片段，在语义、质量和版权门禁满足时优先扩大镜头多样性；不允许为了去重选用不相关或未审核素材。

### 3.4 闭环与可验收性

- 一条生产任务必须串联选题、事实核验、自动文案、可选声音配音、画面选片、混剪渲染、人工审核和导出，不以孤立 Demo 代替端到端成功。
- 系统必须保留每次选片原因、使用记录、人工修改与失败原因，使用户能够追溯、重试和回滚。
- 批量模式必须可恢复：单条任务失败不得污染其他任务，断电或移动硬盘移除后必须从可确认状态续跑。

## 4. 当前产品能力

- Next.js 工作台、FastAPI API、后台 Worker 和 Electron 桌面壳。
- 工作区级生产档案、原始/已审核素材库、ffmpeg 镜头分段、批次就绪门禁。
- 工作区级多声音档案、默认声音和 Episode 临时声音选择。
- 可配置 5–1800 秒的目标时长，文案生成默认以 90 秒为目标。
- 片段系统标签、用户标签、自定义标签夹、使用记录、素材覆盖与缺口提示。
- 基于镜头描述、台词和文件名的文案匹配、低置信确认、可持久化时间线。
- 9:16 FFmpeg 初版成片、旁白音轨和 SRT 字幕渲染。
- 本地来源型选题与文案降级，云端文案增强仅在用户自带密钥后启用。
- LangGraph Episode 工作流与 SQLite 持久化。
- DeepSeek 选题、脚本、段落改写和模板化提示词。
- Obsidian、Hermes、Product Hunt、外部链接信息源。
- Creator Profile、可撤销反馈事件和跨 Episode 偏好记忆。
- ffmpeg、本地 Whisper、腾讯云 ASR 和多阶段视频任务。
- 可解释、可人工覆盖和可回滚的剪辑计划。
- 字幕、封面、发布文案、素材清单与剪映兼容草稿包。
- 运行健康、配置预检、错误恢复和本地自动化。

## 5. 身份与数据边界

产品支持两个明确模式：

- `local`：仅内部 macOS 构建启用，面向可信测试者；不要求登录，所有记录属于保留的本地 workspace。
- `supabase`：后续分发模式；产品界面只使用账号与密码，JWT、workspace membership 和首启门禁属于内部实现。

本地视频、Obsidian 原文、剪映草稿和 AI Key 默认留在本机。任何云端同步都必须有明确的数据范围，不能把本地目录或秘密值上传到 Supabase。

## 6. 设计与交互要求

所有 UI 以根目录 [`DESIGN.md`](../DESIGN.md) 为唯一视觉与交互规范。核心要求是：一个视图一个主任务、Agent 状态可解释、下一步动作唯一、1024/1180/1440 三种桌面尺寸可完成核心流程。

构建成功不能替代视觉验收。业务页应覆盖适用的空、加载、错误、运行中、等待确认和完成状态。

## 7. 当前非目标

- 自动发布到内容平台。
- 原生写入剪映 10.7 加密草稿。
- 无限制爬取外部网站。
- 多人实时协作、计费或公开注册。
- 商品广告、泛娱乐混剪、数字人、横屏模板和完整专业剪辑器。时长超过 90 秒不属于非目标。
- 未经确认自动删除素材或覆盖历史输出。

## 8. 发布门禁

内部测试包必须：

1. 从精确的最新主线构建 arm64 与 x64 包。
2. 通过 Web、API、桌面契约、生产构建和打包 API 健康 smoke。
3. 在真实 Electron App 验证首次启动、配置、主要流程、失败恢复、退出和再次打开。
4. 保存不含秘密值的测试结果；构建产物必须带校验和。

公开发布还必须：

1. 启用并验证账号密码模式及跨 workspace 隔离，产品界面不得依赖邮箱邀请或邮件链接。
2. 通过独立安全审核。
3. 使用 Developer ID 签名并完成 Apple 公证、Gatekeeper 和 stapler 验证。
4. 验证自动更新和可执行的回滚方案。

## 9. 已知缺口

- Chinese-CLIP 画面语义索引和 Qwen3-TTS 授权声音克隆的独立运行时接口已经接入；模型下载器、真实素材阈值校准和公开测试安装流程仍待完成。
- 画面理解仍需从当前的基础多帧语义提升到物体、人物、动作、景别、镜头运动和质量的结构化联合理解，并用真实长素材校准分段与检索准确率。
- 元数据/向量匹配、真实配音时长回填与时间线渲染已经接入，但整个批次的无人值守执行器和固定品牌图层仍待完成。
- 直接发布率门禁尚未跑完 20 小时素材、50 条成片的真实基准。
- 真实麦克风采集尚未接入命令台。
- 腾讯 ASR 大文件仍缺 COS/URL 模式。
- 剪映兼容桥必须在剪映中人工打开确认。
- 当前内测构建是 ad-hoc 签名，不能当作正式发行包。
