# OpenFilm 对话栏行为规格（参考包）

> 来源：OpenFilm 桌面端聊天栏的一段 103 秒录屏，逐帧分析所得。
> 本包不含视频本身（视频无法被代码助手可靠理解）。请按下面顺序阅读：
> 1. 本文件 SPEC.md
> 2. `frames/` 里的 10 张截图（只含对话栏），索引见 §7
> 3. `replay-fixture.json`：把这段录屏还原成"事件剧本 + 检查点"，用于回放和验收

标记说明：
- **[观察]** 录屏里直接看到的事实
- **[决定]** 录屏看不出规则，由本规格替你做的设计决定（可改，但要说明）
- **[未确认]** 不要当成事实，遇到要问人

---

## 1. 任务性质（最重要，先读）

这是**重建对话栏的数据模型和渲染层**，不是给现有聊天界面"修补样式"。

- 允许并要求：重写或删除现有消息列表组件；修改消息的数据结构；新增事件处理层。
- 如果现有组件的数据结构是"消息 = 一段文字"，它**无法表达**下面的规则，只改 CSS 或文案一定达不到效果。
- 验收以 §8 的清单为准，不以"能运行""看起来差不多"为准。
- 与现有代码冲突时，以本规格为准，并在汇报里写明冲突点。

## 2. 核心模型

对话栏是一条**按事件顺序排列的时间线**（有序 Part 列表），不是"问—答"气泡对。

Part 类型：
| 类型 | 说明 |
|---|---|
| `user_text` | 用户消息 |
| `assistant_text` | 助手的一段文字（旁白或最终回答），一轮里可以有多段，夹在工具调用之间 |
| `tool_call` | 一次工具调用：`{id, kind: command \| read_file \| …, title, status: running \| done \| error, startedAt, endedAt}` |

两条硬规则：
1. **渲染顺序 = 事件到达顺序，不重排。** 助手先说话、再调工具、再说话，界面就是这个顺序。
2. **"工具组"和"状态行"是渲染时派生出来的视图，不是存储的数据。** 不要把"组"存进数据模型。

## 3. 各块的规则

### 3.1 用户消息 [观察]
右对齐，浅灰底圆角气泡，无头像。

### 3.2 助手文字 [观察]
左对齐，**无气泡**，普通正文字号。支持 markdown：加粗、圆点列表。**不使用大标题、表格。** 一段文字结束后才可能出现工具行；工具行之间的文字把工具切成不同的组（见 §3.4）。

### 3.3 工具行 [观察]
一行小字，灰色：`[终端图标] 已运行命令 <命令摘要>`。
- 命令摘要用**等宽字体**，超长用省略号截断。
- 运行中：文案变为"正在运行命令"，**行右侧显示该工具自己的秒表**（`1s`、`2s`…）；完成后秒表消失。
- 读文件类：文案为"已读取文件 <文件名>"，图标不同于终端。
- 多个工具可以**同时运行**，每个一行、各自独立计时（见 `frames/08`）。

### 3.4 工具组 [观察 + 决定]
- 连续的、**已完成**的工具调用合并成一行摘要：`已运行命令 ×N`。 [观察]
- 摘要里 N **只数命令类**；组里含读文件类时，追加 ` · 已读取文件`。 [观察：`×5 · 已读取文件` 对应 6 个子行：5 条命令 + 1 次读文件]
- 助手文字会**打断**分组：第一个孤立的工具行（`openfilm`）后面跟着一段文字，所以它没有并入后面的组。 [观察]
- 单个工具调用不成组，直接显示为工具行。 [观察] 两个起成组还是三个起，**[未确认]**，本规格取 ≥2。 [决定]
- **运行中的工具不在组里**：它单独成行显示在组的下方，完成后才并入组，N 加一。 [观察：`frames/05` 组为 ×3，下面一行 `正在运行命令 rg… 1s`；之后组变成 ×4]
- 展开状态下，子行缩进显示，每行 `已运行命令 <摘要>` 或 `已读取文件 <文件名>`，字体与工具行一致。 [观察]
- 摘要行右侧有 chevron：展开时向下，收起时向右；收起状态下 chevron 在悬停时出现。 [观察，细节可能有偏差]
- **何时展开/收起：[未确认]**。录屏里的事实是：组首次形成时是展开的（`frames/05`、`05b`、`06`）；到 72 秒时同样的组已收起且鼠标不在其上（`frames/07`）；而 51 秒时同样处于"空闲"状态它却是展开的（`05b`）。无法从录屏推出触发规则。
  **[决定]** 先实现：最新一组默认展开；用户点击可手动切换，并记住用户的选择；本轮结束后全部收起；用户手动展开的不被自动收起。

### 3.5 状态行 "正在处理 Ns" [观察]
- 灰色文字，右侧一个秒数。
- **出现条件**：本轮运行中，且**当前没有正在运行的工具、也没有正在流式输出的文字**。（`frames/03`、`05b`、`07` 有；`frames/04`、`05`、`08` 没有）
- **秒数含义**：自"上一次可见活动"（文字输出、工具结束）起的秒数，每次新活动后归零。 [观察：72 秒时 `3s`，75 秒时 `2s`，期间有新工具完成]
- 提交后第一次输出之前，它独自占据整个时间线约 25 秒。 [观察]

### 3.6 模型徽标与页脚 [观察]
- 运行中：时间线最后一项下方始终有一行小灰字：`[图标] 模型名 · 推理强度`（录屏里是 `6.2 Sol · High`）。
- 本轮结束后变为页脚：`[复制图标] [图标] 模型名 · 推理强度 · 现在`，"现在"是相对时间。

### 3.7 输入框 [观察]
- 空闲：`+` 按钮；占位文字"描述你的影片。输入 @ 可加入文件或 skill"；右侧发送键（空输入时置灰）；左下角：模型 + 推理强度选择器。
- 运行中：发送键变**停止键（■）**；占位文字变为"说说要改什么。输入 @ 可指向文件、skill、某…"。即：运行中仍可输入追加指令。
- 点击停止 → 本轮结束，状态为"已取消"。 [决定]

### 3.8 顶栏与空状态 [观察]
- 左上角是会话标题 + 下拉箭头；新会话叫"新对话"，发送首条消息后标题自动取自该消息。
- 空状态：垂直居中的标题"你想做什么？"、一句引导语、两个胶囊按钮（社区、素材库）。
- 项目标签页上出现一个小圆点，运行中出现、结束后仍在，含义 **[未确认]**，不要实现。

### 3.9 滚动 [观察 + 未确认]
- 内容变长后出现滚动条，右下方出现圆形"↓"回到底部按钮。 [观察]
- "↓"在内容尚未超出一屏时就已出现（`frames/08`），触发条件 **[未确认]**。
- 流式输出时是否自动跟随到底部 **[未确认]**。 [决定] 用户在底部时自动跟随；用户上滚后停止跟随并显示"↓"。

## 4. "思考"的处理 [观察 + 决定]
- 录屏里**没有展示任何思维链原文**。所谓"思考"只有两样东西：①状态行 + 计时；②助手在动手前写的一句旁白（如"我先看当前项目里的素材和时间线，再告诉你……"）。
- **[决定]** 本产品同样不展示思维链原文。思考类增量事件只用来保持"正在处理"状态。

## 5. 这些效果有一半来自 agent 的行为，不是 UI

下面这些写在界面里是做不出来的，必须写进 agent 的系统提示 / skill：
1. **动手前先说一句人话**说明要做什么；工具调用之间也有旁白。
2. **先查真实状态，再回答**：录屏里 agent 先跑了十几条命令查项目，才说"当前是个空白横屏项目，时间线和素材库里都没有素材"。
3. 最终回答：短段落 + 加粗关键词 + 三条要点，**最后一句诚实说明现在做不到什么**（"自动转写、AI 配音需要先连接相应服务"）。

## 6. 本产品与 OpenFilm 的差异（面向非专业用户）[决定]
1. **工具行不显示原始命令。** 每个工具注册时同时提供 `labelRunning`（"正在分析素材"）和 `labelDone`（"已分析 12 条素材"）。原始命令放进折叠的详情里。
2. **三个人工确认节点**（开始生产、确认剪辑、确认发布）渲染为时间线里的**确认卡片**：标题 + 一句说明 + 主按钮/次按钮；用户未响应时 agent 等待。OpenFilm 录屏里没有这种块。
3. **长任务进度**：素材分析、渲染耗时长，工具行在运行中可显示进度条（由工具执行过程中的进度事件驱动）。

## 8. 验收清单（Given / When / Then；每项都要有证据：测试通过或截图）

对应 `replay-fixture.json` 里的检查点 C0~C8。

- **A1 沉默期**：提交后 0~25 秒无任何事件 → 只显示用户气泡 + "正在处理 Ns" + 模型徽标，秒数每秒递增（C0、C1）。
- **A2 旁白在前**：第一段助手文字出现 → 状态行消失；文字流式出现、无气泡（C2）。
- **A3 单工具不成组**：旁白之后只有一个工具 → 显示为独立工具行，文案"已运行命令 openfilm"（C2）。
- **A4 分组与运行行**：连续 3 个已完成工具 + 1 个运行中 → 组 `已运行命令 ×3`（展开）+ 下方独立运行行，右侧秒表（C3）。
- **A5 并入**：该运行中工具完成 → 并入组，N 加一，运行行消失（C4）。
- **A6 空闲计时归零**：组 ×4 之后无活动 → "正在处理 Ns"；有新工具完成后秒数从 0 重新计（C4、C6）。
- **A7 混合摘要**：组内出现读文件 → 摘要为 `已运行命令 ×5 · 已读取文件`，N 不计读文件（C5）。
- **A8 并行**：两个工具同时运行 → 两行各自独立秒表（C7）。
- **A9 展开/收起**：点击摘要行可切换；用户手动展开的组不被自动收起；本轮结束后所有组收起（C8）。
- **A10 输入框状态机**：`agent_start` → 发送键变停止键、占位文字改变；`agent_end` → 恢复；点停止 → 本轮取消（C0、C8）。
- **A11 页脚**：本轮结束 → 页脚出现 `复制图标 + 模型 · 推理强度 + 相对时间`，状态行消失（C8）。
- **A12 滚动**：内容超出一屏且用户上滚 → 新内容不抢滚动位置，显示"↓"；点击回到底部。

## 9. 明确不要做

- 不要只改 CSS、颜色、间距、文案就声称完成。
- 不要保留"消息 = 一段文字"的数据结构作为渲染来源。
- 不要把工具组存进数据模型。
- 不要在渲染组件里写死录屏里的文案（命令、旁白、回答）。
- 不要展示思维链原文。
- 不要用"最接近的现有样式"替换本规格描述的样式；做不到就说明。
- 不要自行补全 [未确认] 项的规则而不说明。

## 10. [未确认] 项汇总（遇到请询问负责人，不要擅自当成事实）
1. 工具组的自动展开/收起触发规则（§3.4）
2. 成组阈值是 2 个还是 3 个（§3.4）
3. "↓"按钮的出现条件和流式输出时的自动跟随（§3.9）
4. 项目标签页小圆点的含义（§3.8）
5. 文字的流式输出速度（录屏未能测量）
