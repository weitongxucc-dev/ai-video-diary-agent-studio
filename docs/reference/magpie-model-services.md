# 曜核模型服务与用量 · Magpie 借鉴评估

2026-11-20。对象为本机 Magpie 0.1.4573、对应开源 tag v0.1.4573 和曜核已交付候选 b6de5a12。以下是产品与研发建议；实际兼容性按服务端点、模型及验收环境记录。

## 用户入口

在“设置 → AI 服务”管理多个连接、刷新每个连接的可用模型、测试工具调用并选择工作区默认模型。在“设置 → 高级诊断 → 对话用量与诊断”查看总览、模型比较、会话与调用明细。现有按轮次的查询入口继续可用，普通对话保留用户看得懂的工作过程。两处从同一条调用记录解释实际执行结果。

## 借鉴取舍

| 能力 | 本机或源码观察 | 曜核采用方式 |
|---|---|---|
| 供应商与模型目录 | Magpie 支持预设、多个连接、启停、优先顺序和刷新模型。供应商名称、连接端点与可提供的模型各自独立 | 保存多个命名连接，区分官方直连、聚合中转、自定义和本地；旧的单连接配置迁为默认。目录保留最近刷新时间，支持手工模型 ID，目录失败保留已验证项。模型清单、连通、流式、工具调用分别显示验证结果 |
| 覆盖主流服务 | 曜核已有 MiniMax、DeepSeek、OpenAI、OpenRouter、Gemini、Ollama 和自定义入口，设置主要提供静态候选。当前 Pi 宿主配置的自定义接口为 openai-completions | 优先验证 OpenAI、Anthropic Claude、Google Gemini、DeepSeek、通义千问、Kimi、智谱 GLM、MiniMax，以及 OpenRouter、Ollama 和自建兼容端点。按服务能力采用 Pi 支持的原生协议或经验证的兼容协议。模型名称以实际账号返回或明确配置为准。文字、视觉理解与工具调用分别验收 |
| 每次请求明细 | Magpie 路由页展示所选连接和原因，以及首字节、首段可见文字与流式阶段。公开记录可区分请求模型与上游响应声明的模型；响应声明无法独立证明背后的权重身份 | 在 Pi 发起模型调用的边界记录每次尝试，关联工作区、成员、作品、对话、轮次和请求。保存请求模型、响应声明模型、连接别名、状态、耗时、首字延迟、重试关系及脱敏错误类别。流已中断时记录部分完成，即便 HTTP 是 200 |
| 可比较的用量 | Magpie 用量页按 Agent、模型、账号浏览调用量、失败、重试、吞吐与缓存；曜核已有按轮次查询的 trace 与来源标记 | 请求按稳定标识去重，一轮可有多次调用，重试是独立尝试，已产生的用量仍保留。按日期、模型、供应商、会话和作品汇总，可下钻到轮次及尝试。模型已知但渠道未知时单独列出。展示实际覆盖率、缺数请求数、成功率分母、延迟样本数。缓存读写与输入输出按供应商口径归一，保留原始计量单位，禁止二次相加 |
| 费用、预算与质量 | Magpie 支持基于价格估费、余额和请求级支出；金额的来源影响可解释性 | 分开显示“账单实收”“按当时价目估算”“未提供”，保留币种、计费单位、价格版本。订阅配额、本地算力与按量 API 各自统计。账单与预估对账后保留差额。比较质量使用同一企业样片的工具成功、文案采用和重做情况，附样本量 |
| 路由与上下文诊断 | Magpie 可解释一次调用为何选某连接，展示缓存命中和上下文构成 | 默认固定连接与模型，可选经用户授权的备用连接。已开始输出或已执行编辑工具时先核对原请求及作品版本。切换模型须保留原因和实际结果。上下文占用和缓存命中分开显示；细分文案、字幕、工具结果的占用只在有证据时显示 |
| 企业权限与运行方式 | Magpie 支持面向多应用的本地网关；其请求视图基于可重建的派生索引 | Pi 继续执行 Agent 会话和工具。曜核的请求账和权限归工作区；默认只存计量及脱敏元数据，普通成员只看授权范围。可选把已配置的 Magpie 网关作为一条连接做兼容验证。首期不随包启动另一套常驻网关，也不导入其他应用的账号、调用日志或原文 |

## 接入方式与开发次序

1. **连接、协议与验证。** 复用曜核设置和 Pi 模型注册入口，先打通官方原生服务、OpenAI 兼容中转和本地服务三类代表。校验模型发现、流式响应、真实工具往返、超时、鉴权失败和重开后的默认选择。列出各厂商与模型实际验证范围，无法获得凭证的记“待验证”。
2. **逐次记录与设置报表。** 在模型调用边界写账，从已有轮次 trace 回链；总览只读汇总。旧轮次仅有合计时按历史合计展示，不生成虚构的调用明细。测试“同一轮两次调用、一次失败重试，另一个轮次切换模型”，从请求到模型、对话和作品可逐级对账。缺失用量、流中断、缓存、重启后重复回执以及权限隔离均须覆盖。
3. **路由、成本与运营。** 增加显式备用路由、脱敏导出、预算提醒与估算成本；再评估可选 Magpie 网关。用同一条双语企业片核对中英文阶段的用量、耗时、失败和实际采用结果。分别记录 Mac、Windows 与各供应商的实测状态。

- 本机只读检查了供应商、路由与用量界面，并对最近 1,000 条本机用量记录统计字段存在性。请求模型、响应模型、状态均有字段，999 条有首 Token 延迟。字段存在并不保证值有意义，也不代表账单已核对。评估未发起模型调用。
- 曜核入口为 [供应商设置](../../apps/web/src/components/LlmProviderFields.tsx)、[Pi 注册模型](../../apps/api/app/assistant/runtime_context.py)、[运行时组装](../../apps/api/agent_runtime/session.mjs)、[Pi 结果计量](../../apps/api/agent_runtime/result.mjs)、[轮次 trace](../../apps/api/app/assistant/trace.py) 与[设置详情](../../apps/web/src/components/AssistantUsageSettings.tsx)。
