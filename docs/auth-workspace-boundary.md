# 认证、首启与工作区边界

状态：安全不变量权威
职责：定义账号、workspace、首启和本地资源的信任边界。公开端点、表结构和环境变量的当前集合以代码、迁移和 .env.example 为准，不在本文复制清单。

## 1. 身份模式

交付配置必须显式声明一种模式：

- local：只用于本机开发或受控诊断；不显示登录，只操作保留的 local workspace，不具备多用户隔离能力。
- supabase：用于交付给独立测试者或用户；使用经过验证的独立身份，成员可接受主账号邀请进入授权工作空间，不能把邀请二维码当永久登录凭据。

Web 分发配置与 API 认证配置必须一致。API 只有在 Supabase URL 和 publishable key 成对有效时才能启用 Supabase 校验；声明为 supabase 但配置缺失时，构建或首启预检必须阻断，不能静默降级为 local。开发者未声明分发模式且没有 Supabase 配置时可以运行 local，但不得把该行为包装成账号分发版。

身份配置入口以 apps/api/app/config.py、Web 认证配置和实际构建 workflow 为准。

## 2. 信任模型

- 账号交互API信任通过Bearer JWT验证的身份；外部适配使用第10节的可信绑定及受限凭据，不把平台字符串当用户身份。所有入口不信任客户端自报的user_id、workspace_id、ready或completed。
- JWT 只接受配置允许的非对称签名算法，并校验 issuer、audience、过期时间和 subject。
- 后端使用已验证的用户身份解析 workspace membership；客户端不能选择一个自己不属于的 workspace。
- 产品数据端点默认需要有效身份、工作区成员关系及最小工作区初始化。登录前健康检查与修复端点采用显式 allowlist，当前列表由 apps/api/app/main.py 和对应测试拥有，本文不复制。
- 资源不属于当前 workspace 且没有有效共享授权时返回404，避免泄露存在性；共享访问也必须核验操作权限。

HTTP 语义：

- 401：令牌缺失、格式错误、过期或无法验证；
- 403：身份有效，但没有可用 workspace、最小工作区初始化未完成或操作不被授权；
- 404：对象不存在，或属于其他 workspace；
- 409：当前状态不允许该命令，或幂等键与已有请求冲突。
- 503：身份/成员关系或首启状态依赖暂时不可核实；仍拒绝业务访问，但不得误报无成员权限或强制退出账号。网络超时、远端服务不可用和无权访问分开投影，不缓存成员许可或静默降级为local。

## 3. 首启门禁

客户端只能请求初始化，不能提交可信 ready 结果。服务端核实身份、成员关系及工作区最小存储可用后幂等建立工作区；首次设置的完成/跳过记录与功能就绪分离，不自动创建视频任务。人物、声音、素材扫描及偏好均可跳过，流程见[产品首次使用](product-requirements.md#41-首次使用与按需设置)。

素材入库时检查授权源和存储目录，录音时检查麦克风，媒体预览/制作时检查相应 FFmpeg、模型及输出条件；失败只阻断所依赖的能力，仍可使用不依赖它的浏览和对话。已指定外接数据根但缺盘时不得偷偷改用内置盘；该工作区无法读取时显示重连/修复，不能伪造可用数据。

可选的 ASR、知识库连接、剪映、外部模型、图片模型、人物服务和平台连接不作为全局首启硬门禁。它们在对应功能入口做能力级预检，并清楚说明影响范围和修复动作。

未建立可信身份和工作区的用户只能访问登录、初始化及修复的显式允许入口；可选向导的跳过不是绕过权限或功能级检查。软件的“稍后设置”不能代用户批准系统权限。

## 4. Workspace 分区

- 所有任务、模板、人物、偏好、来源、素材元数据、自动任务、发布和监控记录都属于一个明确 workspace。
- Repository 的每个查询和写入必须从已验证的活动 workspace 上下文取得范围；不能接受调用方随意传入 workspace 绕过上下文。
- 认证模式中如果活动 workspace 上下文丢失，操作必须失败，不得回退到 local。
- 历史上没有 workspace_id 的本地数据只归入保留的 local workspace；认证账号不能自动继承或看见这些数据。
- 实际表和迁移由 apps/api/app/repository.py、models.py、schemas.py 与 supabase/migrations 共同证明；修改时必须有跨 workspace 负向测试。

## 5. 后台任务

- 已合法提交的账号作业可由本机后端使用可信设备凭据持续复核原设备、账号与工作空间的许可关系，避免依赖已退出或过期的登录令牌。该核验只返回必要的许可结果，不授予登录能力、成员名册或私人内容读取权；设备凭据不暴露给渲染进程，也不写入作业事件。交互式命令仍先验证用户 JWT，后台身份只取原作业的持久归属。事实源不可用时保留作业并停止新执行或成功提交，不降级为 local。
- 后台许可可复用应用拥有的HTTP连接池，但不能缓存许可判定；原设备、账号和workspace随每次RPC独立传入，连接池不保留用户Authorization。传输的创建与关闭归应用组装，先停止使用者再释放连接，不能因复用连接跳过撤销或unknown处理。
- Worker、视频任务和自动任务在提交时固定 workspace、用户或明确的 local 作用域。
- 任务恢复、重试和定时触发继续使用原 workspace，不能从当前登录用户或全局变量重新猜测。
- 缺少身份或 workspace 上下文时不读写登录账号数据。
- 缓存、模型结果和配音键如果包含私人内容，至少按 workspace 和决定结果的模型/版本隔离。
- 进程级缓存不得产生跨用户命中；任何 membership 缓存必须以已验证用户和 workspace 为键并有有界有效期。

## 6. 本地文件与云端边界

本地视频、音频、图片、草稿、模型、缓存和密钥不会因为有 Supabase 账号就自动上传。workspace 隔离也不等于操作系统用户隔离：同一 macOS 用户下的不同产品账号可能获得相同目录的系统权限。

因此：

- 每个本地文件引用还必须经过工作区授权根目录和用途检查；
- 云端模型或发布平台需要上传内容时，界面说明发送范围并取得相应授权；
- 密钥不进入数据库普通字段、日志、截图、构建变量或安装包；
- 删除本地文件前解析精确目标并说明影响与可恢复性。

本地成员的原生媒体请求使用同一已验证成员令牌，不另建媒体身份。浏览器现有成员令牌保存/清除同步同源会话cookie，按当前端口区分、限`/api`、`SameSite=Strict`，HTTPS使用`Secure`；其可见性沿用当前JS令牌存储。Next只在local模式的实际媒体GET/HEAD请求、原成员头缺席时将该cookie转为原`X-Local-Member-Token`；明确无效或空的成员头不能被cookie替代，缺cookie不授予私人内容访问。Supabase请求仍只沿原服务端认证会话，不继承本地成员。后端对每次媒体请求继续核实名册、Workspace和对象权限，令牌不进入URL或日志，Range与流式读取保留。

整机扫描须由当前成员主动开启，受主机系统权限约束；可信本地层执行发现，Renderer 不提交任意绝对路径越过文件边界。候选清单属于当前成员/工作区，授权扫描不授权入库、共享、模型外发或声音克隆；选中并成功接收后才成为素材库资产。撤销目录权限/新增排除项阻止后续读取，不自动删除既有入库资产。扫描不申请绕过操作系统保护，链接目标重新核实可访问范围和排除规则。

手机声音传输复用可信设备连接和成员身份，绑定采样任务、工作区、参考文本版本与原请求；不能仅凭二维码、文件名或局域网来源决定归属。完整接收后登记，重试查询原结果并去重；手机本地保存不等于主机接收。麦克风与相册权限按实际动作请求，取消不改变已有档案。

## 7. 管理员账号

以下命令仅用于受控测试账号准备，不是正式成员加入流程。测试者不接触 Supabase 管理密钥。运维管理员在受信任终端临时设置项目 URL 和管理员 secret，然后运行：

    cd apps/api
    SUPABASE_URL=https://your-project.supabase.co \
    SUPABASE_ADMIN_SECRET_KEY=your-secret-key \
    uv run python -m app.account_admin tester01 --generate-password

管理员 secret 只供该命令调用 Supabase Admin API；不得写入仓库、应用环境文件、GitHub Actions 普通构建变量或安装包。应用运行时只使用 URL 和 publishable key。

## 8. 最小安全验收

任何认证或 workspace 改动至少证明：

1. 无令牌、坏令牌和过期令牌不能读取产品数据。
2. 用户 A 不能读取、修改、推断或触发用户 B 的对象。
3. 客户端伪造 user_id、workspace_id、ready 或 completed 无效。
4. 声明 supabase 但配置缺失会阻断，不会进入 local。
5. 最小工作区初始化由服务端核验；跳过可选设置可进入工作台，缺少特定能力只阻断依赖动作；越权与缺盘不得借跳过而降级。
6. 后台任务、重试和缓存不会丢失或切换 workspace。
7. local 历史数据不会暴露给认证账号。
8. 两个真实测试账号在登录、session 恢复、退出和再次启动后仍保持隔离。

## 9. 主账号、邀请与共享授权

主账号是设备产品角色，不能与 Supabase 运维管理员混同。使用名额按有效使用者计数，包含主账号在内上限五人；角色改变不增加名额，空间不是名额。创建邀请和接受邀请均由服务端核验权限、名额与状态，接受过程原子占位，重复接受幂等，过期/撤销/错设备不能绑定。邀请只携带短期凭证，不携带密钥；0.11桌面接受与0.12手机扫码在本轮共同验证同一正式邀请协议；开发成员令牌或设备发现结果不替代正式身份与设备核验。

私有对象保留原属空间和上传者；共享通过显式授权关系获得读/引用等允许操作，不借伪造 workspace 或无条件跨库查询。共享库有明确的团队归属；只有有权操作者可发布到公共范围，不能自动公开他人私有内容。撤销共享后停止新的检索和引用；既有任务使用的版本与派生产物保留可追溯关系，其可继续使用条件必须由有效授权判断，不能静默删任务或继续无限共享。

历史本机数据没有上传者登记时，只能在本人明确确认归属、目标本机成员和私有范围后接入。接入限定于经核对的原工作区对象与固定来源，逐项核验原记录和文件修订，并保存原归属、授权依据、接入结果与幂等回执；不能认领已有他人成员归属或其他工作区的内容。素材保留原标识、分析、标签、用途及排除状态；缺少稳定来源的声音保留旧版本，登记原文件来源并创建明确的新版本，不能静默改写旧引用、默认声音或人物授权。接入是显式本机维护操作，不是启动、登录、正常读取或制作预检的自动权限回退，也不使 Supabase 身份继承本机私有数据。

主账号可管理成员、共享配置、设备任务安排并查看全部发布统计；不因此默认读取私人素材、语音、文案。普通成员看整机匿名汇总和自己的详情；词云、聚合、缩略图、通知、缓存、检索/重排、文件URL和助手工具均必须执行相同权限。共享声音同时满足使用授权和可见范围，管理员不能代替声音提供者授权克隆。

外部消息身份须明确绑定设备、成员与工作空间；解绑、离职或邀请撤销不得通过旧会话继续操作。暂停成员访问保留其任务与资产的原始归属；交接另走显式授权。登录关闭和界面退出不取消已合法提交任务，后续查询重新鉴权。

新增负向验收：并发接受邀请不能超五人；跨空间搜索/词云不泄露私有内容；共享撤销后新引用失败；主账号可看全体发布统计但不能越权读私有原件；已失效外部身份不能继续触发任务。

## 10. CLI、MCP、消息入口与原生工具

CLI/MCP连接必须有明确的本地成员或已认证账号/受限服务身份，能力和资源按实际权限过滤。飞书/钉钉的应用、租户、发送者、群/会话标识经平台官方验证和已授权绑定，映射到本产品成员/工作区；平台字符串、被@、转发消息或MCP客户端自报用户不能创建访问权。服务身份仅有授权作用域，不能共享一个全权令牌给所有群成员；撤权在读取、执行和结果访问时生效。认证模式不能为连接方便降级local。

平台附件接收使用授权来源、大小/类型与工作区接收边界；已鉴权且已绑定发送者的直接制作指令可在既有授权范围内创建或指挥任务；指令引用的正文、附件、网页和转写属于内容数据，不能自行扩充工具、shell、网络或新任务权限。平台重放去重与业务幂等分别检查。受限结果引用只向有权调用者返回，群内通知不得包含其他成员私人素材、任务名、密钥或本机路径。连接授权包含指令接收、进度回复与结果发送的范围；发布平台或新的外部接收人仍按相应授权处理。

Pi原生read/write/edit/bash是产品应保留的能力，但宿主必须提供真实执行边界：授权的任务工作目录及输入、受控输出、工具进程的取消/时限/回收；cwd和系统提示不构成隔离。不得直写产品数据库、覆盖原始资产、读取密钥或越权访问其他工作区。用户明确授予的额外目录与外发范围按实际授权扩展，不以“原生工具”一概禁用，也不以“自主创作”扩大到整机。重型媒体/模型调用遵循唯一设备许可，执行生成文件通过业务登记后才可作为作品输入。

必要验收包括：合法CLI/MCP读取/编辑/恢复；错误绑定、跨空间、撤权、重复平台事件、断线及回复失败；原生工具实际读写/执行和产物采用；路径/符号链接越界、私有文件/密钥、数据库直接写、未授权网络外发被真实阻断；取消后所属进程释放。当前安全机制不足时记录该能力受阻，不靠提示词或静默无限shell伪装通过。
