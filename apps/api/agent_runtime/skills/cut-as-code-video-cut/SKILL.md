# Cut-as-code video-cut（曜核受控适配）

这是对外部 `WhiteTowerAI/cut-as-code` `/video-cut` 方法的受控适配。它只借鉴“先共享证据、再写 keep/drop 决策、最后核对边界”的编辑方法，不导入外部脚本或运行时。

## 触发与边界

用户要求把原声口播、访谈、播客或 vlog 压缩成第一版/粗剪，或明确删除停顿、重复和离题段落时使用。它只处理当前曜核任务中的局部可编辑时间线；不下载 URL、不连接外部服务、不运行 FFmpeg/Python/Whisper、不读任意路径、不生成新的时间线事实源，也不替代配音、字幕样式、调色或最终媒体验收。

## 受控流程

1. 用 `read_current_task`、`read_task_object`、`read_task_edit_capabilities` 核对当前任务、镜头/音轨/字幕对象、基础时间线版本和真实可用编辑 schema。
2. 对候选片段用 `read_material_evidence` 读取源时间、文字/词级证据；用 `read_task_observations` 和必要的 `observe_task_output` 定向检查已有产物。没有证据的停顿、黑帧或画面问题保持未知，不凭经验删除。
3. 形成按当前时间线排序、互不重叠的 keep/drop 候选。每项写明源/时间线区间、保留或删除、简短证据、保留的事实/限定和未知。句子或语义边界优先；不把“相似”当成可删除，不重排或复制片段。
4. 用户要先看方案时沿现有预览入口提交候选，使用 `preview_typed_edit` 或当前 `read_edit_control_context` 返回的真实提案；预览不是采用。
5. 只有用户明确授权且能力声明允许时，才用 `apply_typed_edit` 提交一次可撤销的局部编辑。沿原请求回读真实版本、影响对象、采用状态和媒体作业；响应未知先查询原请求，禁止换 request_id 重放。
6. 交付时分别报告：取舍依据、实际保存版本、是否有可播放预览、观察覆盖范围和仍未验证的听感/画面质量。需要整组恢复时提供现有 `read_edit_history`/撤销入口，不另建恢复逻辑。

## 停止条件

缺少当前任务/版本、词级或句级时间证据、编辑能力、真实对象定位或用户授权时停止在读取/提案阶段；不以外部 Skill 的脚本、模型、服务或“粗剪完成”文字替代曜核业务回执。
