# 手机与电脑版连接联调要求

接入目标为电脑上的曜核软件与 Flutter 手机 App 在同一局域网连接；不依赖蓝牙配网或实体机箱屏幕。

这是手机接入的依赖与待确认项，不是产品、安全或 API 的第二份权威。长期范围见 [产品需求](../../docs/product-requirements.md#11-版本交付边界)，账号和空间约束见 [认证边界](../../docs/auth-workspace-boundary.md#9-主账号邀请与共享授权)；协议决定应落到现有架构/安全权威和真实代码。

## 第一轮共同结果

电脑版打开曜核；手机与电脑同网；手机扫描主账号生成的短期邀请；服务端核验身份、设备、邀请和空间；手机读取自己的真实进度。手机重启和电脑重启后可恢复同一绑定；邀请过期/撤销、成员停用、证书不可信或错设备不能建立或恢复连接。

## 电脑版需实现并反馈的项目

1. 安全局域网入口：提供手机实际可达的 HTTPS 服务及证书信任方案；不要把当前匿名 local 开发 API 直接开放为交付入口。先明确开发诊断与正式账号模式的边界。
2. 短期二维码：主账号管理界面生成/撤销/刷新邀请；请确认载荷版本、设备身份、连接定位信息、邀请凭证、到期时间与认证配置取得方式。二维码不是永久成员凭证，不携带主机密钥。手机不得自行猜字段和端点。
3. 设备发现：确认 DNS-SD service type 与公开 TXT 字段；候选 `_yaohe._tcp`。仅发布最小设备/协议/定位信息，不广播邀请、账号 token 或私人空间信息。发现结果仅为定位提示，不能作为设备可信或成员授权的证明。
4. 账号与空间：复用现有经过验证的身份及 `/api/device-invites/accept` 正式邀请入口，确认手机登录/刷新、接受邀请后核验设备与授权空间的接口和最小响应。当前手机 `/api/members/join` 与 `X-Local-Member-Token` 仅为既有开发模式，不可冒充正式身份。
5. 进度：提供按当前成员/空间授权的任务读取、更新时间、失败与失效语义；确认 `/api/creation-tasks` 可否直接复用。离线缓存不是当前完成事实。
6. 素材与声音接收：沿[架构导入流程](../../docs/system-architecture.md#51-内容与素材导入)确定两端真实协议，声音采样绑定同一任务与朗读文本版本，区分手机保存、发送和主机完整接收；幂等、续传与归属由共同业务入口校验。主机本地路径导入不能伪装手机上传，收到素材不自动创建视频任务。
7. 用户已选择“登录正式账号后统一设置资料”：请提供同一正式账号的注册/登录入口、昵称与头像的读取/修改和头像接收方式。手机不另建本机账号或把昵称当成员身份；个人资料编辑不改变设备角色、空间授权或使用名额。请确认头像权限与地址取得方式，手机不能自行猜测存储桶或用户表。

## 写入分工和验收

实施文件归属遵循当前活动合同，不沿用旧工作树的写入授权。手机实现前先确定连接载荷、认证方式、发现字段和可联调入口，再据此接入；没有确定的协议不增加猜测式兼容分支。

手机独立验收相机扫码/图片识码、权限拒绝、无效内容、安全存储与离线状态；两端共同验收真实邀请、真实成员进度、重连、地址变更、错设备/跨空间/撤销拒绝。隔离测试输入必须显式区别于真实主机和真实账号，不能用模拟成功替代联调通过。
