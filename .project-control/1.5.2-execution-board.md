## 验收顺序

1. 回收并审核 OBS-1 的 DG-1 消费者接线，确认资源采用、任务/时间线、Job 与输出观察都能通过同一 Trace 关联回查。
2. 在真实或可回放 Agent 回合中覆盖成功、失败、压缩、重试/嵌套工具和三类 Token 状态，分别保留 API、Web、手机端和 CLI 证据。
3. 主控复核 DG-1、AG-1、AS-1 的 canonical 代码和证据，再进入真实设备/真实素材验收；验收稳定后才执行 CLN-1 清理。
4. 为 SET-1 绑定已有可见执行线程，先吸收 OBS-1 的状态层级和诊断入口，再做视觉与交互检查。
5. 只有 OBS-1、DG-1、CLI-1、MOB-1 的接口和证据稳定后执行 CLN-1：先保留安全快照和清单，再处理过期 worktree、缓存、临时测试目录和 stale refs；模型、真实素材、成片、数据库和验收证据必须逐类确认后再动。
6. GitHub 清理按“已合并/已废弃/仍有价值/当前未发布”分类；远程删除和默认分支调整必须在具体清单可审查后再执行。
