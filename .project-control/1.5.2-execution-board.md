# Agent-first 产品纵向执行板

> 本文件只组织当前施工，不拥有产品规则。稳定规则沿 `docs/README.md`；实际完成状态以代码、GitHub Issue/PR、CI 和真实运行回执为准。旧的日期、周次和九阶段施工记录由 Git 历史追溯。

## 当前目标

先完成一条真实作品的完整闭环：用户从自然语言目标开始，Agent 读取素材和知识证据，选择并执行当前动作，生成可播放粗剪，用户继续对话完成局部精修，保存作品版本，再按授权接入一个真实发布平台和反馈回读。其他能力围绕这条闭环补齐，不能把参数表单或固定阶段重新设为入口。

## 纵向切片

| 切片 | 主责 | 用户结果 | 验收门 |
| --- | --- | --- | --- |
| 新建与作品台 | Web/工作台 | 点击新建后立即进入对话和空作品区，用户不先填统一表单 | 新建、自然语言输入、刷新恢复、切回旧作品、跨任务隔离 |
| Agent 事件流 | Assistant/Pi | 人话说明、真实动作、结果、失败和恢复形成连续时间线 | OpenFilm C0–C8 回放、真实 Pi 回合、停止、追加、重试和持久回读 |
| 证据驱动创作 | 素材/知识 | 选材、写稿和替换带来源、版本、片段和用途证据 | 固定样本命中、原片定位、候选采用、撤销和权限负向 |
| 粗剪与局部精修 | 媒体/编辑 | 粗剪可播放，局部修改只影响必要版本和依赖 | 真实媒体提交、观察、局部重算、版本冲突、输出回读和播放 |
| 多分支创作 | 作品/Session | 多个方向可并行比较，采用后才成为正式版本 | 两个以上真实候选、预览比较、采用、回滚、分支取消隔离 |
| 发布与反馈 | 发布/数据 | 一个真实平台完成发布回查，并产生下一次创作依据 | 账号授权、用户确认、平台内容编号、真实回查或明确未知状态 |

主控维护作品、语言、选区、版本和事实源的共享约定。Windows、手机、打包和其他平台单独验收，不能由本机浏览器或单元测试外推通过。真实设备、Provider、媒体、最终播放和平台反馈都必须有自己的证据。

## Agent 与 Pi 审查重点

- 系统提示只保留创作职责、事实边界、授权边界、持续推进、真实结果判断和失败恢复。不要把九阶段写成调用顺序，不要要求用户先填技术参数。
- Agent 先理解用户结果，再读取相关素材/知识/人物/声音证据，选择当前动作，执行后回读真实结果。查询、建议和局部修改不能自动创建新任务或覆盖正式版本。
- Pi 不拥有任务、作品、版本、授权、队列和资源事实。宿主负责事务、幂等、CAS、运行状态和事件持久化，Pi 只通过受控业务工具和原生能力完成当前动作。
- Skill 按创作结果组织，优先补齐目标到粗剪、证据选材、局部修改、粗剪观察、发布前准备和反馈回流。Skill 缺少真实工具时必须保持不可运行。
- 需要真实媒体或 Provider 的验收必须在对应运行时进行，不能用目录状态、回放、预览或静态测试代替。

## 验收顺序与阻塞

1. 集成分支与 PR 收口。
2. 设备资源准备和真实媒体闭环。
3. 真实 Provider 回合和 usage。
4. 桌面/Pi 组合验收。
5. 按下文的工作台与对话工单推进页面级信息架构和作品台。
6. 素材、人物、声音和知识资源工作区。
7. 多 Session、多分支、候选比较和采用。
8. ffmpeg-skill、CreatorHub、跨端、发布和生产化。

设备档、Provider key、真实平台账号或真实媒体样本缺失时，保持对应验收为未知或阻塞，继续推进不依赖它们的工作，不改代码伪造通过。
