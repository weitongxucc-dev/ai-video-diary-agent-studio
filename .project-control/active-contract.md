## 3. 写入归属与代码边界

2026-11-11 用户进一步要求依照候选、Linear 和当前设计原则彻底修正顶部与全产品界面细节。UI 线程及其子代理已确认停写、无未交接差额；本批由总控在 codex/ui-craft-refinement 独占 apps/web、必要 DESIGN 和本合同写入，负责共享外壳、动作层级、编辑空间、对话输入、资源及任务页同根缺陷的整批实现、桌面验收和 main 集成。UI 线程仅提供只读设计对照，不新派代理；旧 dirty 工作树仍受保护。不改变业务事实、既定字号或削减功能。

按包所需沿既有职责模块修改：第一包以 agent_tools/diary、creation/editing、能力读取及直接 UI/CLI 消费者为主；第二包以素材/资料/文案、局部剪辑与观察/质量用例、Skills 为主；第三包以模板业务、媒体执行适配及必要图层/关键帧为主。具体新增路径随真实调用链定位，不预设万能模块。

- main.py、Pi host/session、工具注册入口及前端 Workspace 只承担组装、生命周期和接线，不承载新增业务分支。
- 业务用例组织音画字幕联动、版本/采用及跨对象短事务；所属仓储保存唯一事实；DeviceScheduler 管执行许可；Pi 管模型回合、会话与工具调度。
- 优先复用已有职责模块；新模块须有真实变化原因。涉及大文件时在同包抽出相关职责并迁移消费者，不机械按行数拆分，不另起全仓重构。
- 不新增第二套 Agent 循环、作品状态库或万能服务；被替换的规则/入口随实际消费者迁移退役。pi-durable/chord/远程执行等未列为本次前置迁移。

## 4. 按整包实现、集成和验证

开工前只短对齐用户结果、业务入口、事务/事实负责人和本包风险，复用现有规范。连续完成实现与必要消费者适配后，冻结集成候选，集中进行相关最小检查、适用 CI 与真实用户流程验收；不得停在计划、派工、源码接线或单测通过交回。

小问题不单独触发全量测试、完整打包、模型/媒体运行或逐问题人工确认。语法/类型检查可按需运行；真实失败才提前定向复现，先查首因。同候选未受影响证据跨问题/批次复用；有新改动、失败或未覆盖风险才补相应验证，不重复已通过机制。新 UI 行为和真实出片仍须对应可见证据，不能降低必要验收等级。

真实模型/媒体验收串行，保留原请求、Job、预算、产物与失败；unknown 先对账，不新建作业清零或放宽资源保护求通过。每包检查实际 diff、旧消费者及代码职责，报告结果/未验范围后同步 main。Git/CI/Release 与原回执为实现和运行事实源，Issue 关闭须链接对应候选与证据。
