### 1.1 顺序、责任与退出条件

当前主控只围绕电脑端真实用户链推进：目标委托/聊天定稿→资料素材匹配→生成配音和中英粗剪→剪辑台对话精修与人工交替→局部重算、撤销、真实输出→Quit/重启恢复。手机配对、账号准备和跨端验收暂停，已有源码/安装/证据保留；不再用这些旁支替代桌面能力验收。桌面核心通过后再恢复手机联调，Windows仍在下一阶段。

P0/P1先解决基础正确性；P2准备可并行，P3在引用/命令契约固定后与P2并行；P4/P5贯通中英文粗剪精修；P6做独立任务和故障；P8的业务契约和原生工具边界早于新消费者冻结、实现随对应业务用例推进，P9依赖P8；P7在相关能力后统一收口。模型/媒体/打包串行，轻量独立工作可并行。

每包一个纵向负责人，主控管共享文档、跨入口契约、唯一写入、审核和同候选验收；具体路径见活动合同。脚本可执行、界面存在或子线程完成均不是用户闭环通过。真实资源压力、缺真实素材/设备/平台租户明确标在该验收项，其他已授权工作继续；不合理准入、未做预算标定和未实现的平台适配归为待修复/待实现，不归为环境阻断。

2. 同批独立补齐安全错误回执与原请求查询：首个拒绝能定位具体原因和提交效果；文案核查已收集的多项有效问题在原有上限内完整交给Agent，字段位置和有界依据随持久事件回读，不只逐项暴露或丢弃修订所需语义。冲突不得相同参数盲重试，总轮次超时不能伪称模型故障或抹掉此前拒绝。未证实的六次409根因仍需实际回执确认。
   - 核查上下文明确本条交付与脚本计划阶段，报告契约限定本段候选及允许的资料；验证中英两条分别通过、未来图层计划不被当成缺少实际产物、跨段/无效引用仍拒绝。沿既有SDK事件与HTTP期限分别计时，合法多次核查不能耗尽单次模型预算；单次失活、并行请求互相续期和取消后未知写入均有反例验证。自动接续的具体安全失败必须持久回读，不被通用中断覆盖。
3. 同批独立移出调度写事务中的网络核验与采样等待；慢身份核验时并行普通编辑能提交，观察后取消/输入变化不得获许可，授权未知不执行，唯一许可和崩溃恢复不退化。
4. 集成后尽早用一次目标自动新建中英作品，沿真实首个缺口补齐输入来源、匹配、采用与任务接续、严格时长和输出。复用已有子任务/文案/声音/编辑/媒体能力；不人工填内部ID、代写成片文案、手工通过镜头审批或补尾段凑验收。
   - 派生任务须沿采用回执回到真实用户输入，不能将内部目标根与真人轮次直接比较。随后多轮精修必须覆盖“自动派生回合中消费新输入→保存新目标修订→收到业务结果后继续”的完整链；只放行提交、不登记新修订仍为未完成。沿现有会话仓储和输入回执修复，不增第二套目标状态。
5. 同一候选真实输出中英各30秒，再连续不同类型精修、撤销重做、正常Quit重启并核对任务/版本/文件与实际播放。保留来源署名和许可，公开素材只称演示，不外推成用户工厂。

长时长按[架构§3.7.1](../docs/system-architecture.md#371-长内容的有界执行)纳入设计。当前基线创建schema与工具上限600秒，仅说明接口限制，连10分钟也不能据此称已验收；不直接删上限。30秒闭环后扩展30分钟真实样本，覆盖分段配音/渲染、跨段音画字幕、只改单段、在途取消与重启、峰值内存/临时空间/总耗时；3000分钟（50小时）先做有界规划/分页/恢复和空间不足的规模验证，最终支持仍须独立全长真实组装/播放定位/修改恢复证据。合成规模测试不算50小时制作完成。每阶段给出实测能力范围，不以统一超长超时或线性抬高内存预算求通过。

长内容规模验证还须覆盖调度成本：每轮候选与昂贵核验次数保持有界，既有公平性与撤权检查保留；不得用“没有长写锁”替代长队列响应验收。

30秒出口之后的最小接线按实际执行单元推进：

- 初次配音复用既有NarrationSegment和Artifact，将段产物、输入摘要与恢复点逐段提交；生成前核验已完成段，合并作为独立有界单元。验收中断后只补未完成/失效段，局部重配保留其他段摘要，并分别测单段模型峰值和最终合并开销。
- 镜头渲染复用既有Job/Artifact，把可恢复产物绑定具体段及依赖，最终组装与可重建临时文件生命周期分开。验收不能只命中旧整片输出；须中途退出后复用已完成段，实测全程临时盘峰值与空间不足保护，不让全部无损中间片无界累积。
- 时间窗预览与版本对象分页复用既有读取入口；分页须同时约束后端读取/解析、返回内容及前端缓存，不能仅截取已全量构造的响应。验收跨段字幕/转场、远距离播放定位及局部修改，再与上段的有界队列测量共同决定30分钟及50小时的实际开放范围。

Windows适配按实际消费者依次交付：调度账本的平台互斥锁及持久化（退役直接导入`fcntl`）；素材/声音接收的目录同步与文件发布；受许可进程树的启动、登记、管道读取、取消及回收；进程提交内存与作业成员聚合；Windows可运行的模型后端；最后是`.exe`路径、构建和安装。复用现有调度器、许可账本、事务及业务回执，不另建执行平台。每段在Windows验证异常退出和原请求恢复；硬链接与目录同步按实际支持的文件系统验证，不能简单吞掉错误或跳过持久化。原生内存采样存在不代表这些消费者已适配，Mac的MLX模型可用也不代表Windows后端可用。

内存恢复验收须覆盖慢owner/身份核验与多队列交错：同一基础观察线程推进内存恢复及IO持续窗口，不随串行派发漏采；慢身份核验下的单个排队任务也能积满原10秒内存/3秒IO窗口并推进真实工作，critical/余量不足/测量失效仍立即保护，退出后无残留采样线程。依[架构§3.12.1](../docs/system-architecture.md#3121-内存压力任务预算与平台适配)执行，不以扩大gap或缩短恢复期修复。

CPU保护验收同时覆盖整机峰值反例、系统优先级核验失败和持续前台负载：保留真实累计端点/进程归因，验证Mac各任务所声明的系统优先级、主动成片非BG状态及子孙继承、未核验不执行重任务、准入限流，以及实际配音推进、取消/释放和前台输入/播放连续性。实验参数和轻量系统状态回读只作为候选，须完成同候选真实工作后才进入设备生产档。

每次实机验收在开始前固定候选、模型/后端、输入、正常基线、压力施加上界、终止条件、交互/媒体连续性标准与清理方式。对比同输入的等待、加载、有效运行、恢复与总耗时，不以CPU满载或内存用满为绩效。不能通过关闭用户其他应用、关闭保护、反复抬值、减损最终质量或以模拟代替实机达标；轻量反例仅证明规则缺陷。

### 1.1.4 P7桌面与手机联动的联合交付

本节为保留的后续跨端工作包；当前暂停M1–M4联调，不能阻止桌面核心闭环验收。恢复前由主控重新绑定现有线程，不恢复旧手机写权。

本节落实[产品§1.1](../docs/product-requirements.md#11-版本交付边界)及[架构§5.1.1](../docs/system-architecture.md#511-手机联动的共同接收与回读)，不是独立0.12计划。复用主线Flutter的素材草稿、录音/试听、扫码/设备发现、安全存储与现有主机邀请、素材/声音登记和任务读取；代码已存在不表示正式链路可用，不整分支盲合并历史原型或路演资料。

| 顺序 | 补齐与集成结果 | 真实接受点 |
| --- | --- | --- |

M1/P7还须验证首次主账号准备和忘记密码后的恢复：产品账号名的内部邮箱映射不是可投递邮箱，不能让普通用户依赖给该地址发找回邮件。沿[受控账号准备边界](../docs/auth-workspace-boundary.md#7-管理员账号)补合法初始化与管理员重置操作及明确交接，普通用户不接触云端管理员密钥或数据库控制台；账号恢复不能自动认领设备、改变原工作区归属或暴露其他成员数据。本轮手动管理后台准备测试身份只算验收前置，不算普通安装账号流程通过。

### 1.4 检索和场景样本

知识固定至少20条真实问题，覆盖精确型号/参数、同义/中英、长文/表格、版本冲突和无答案；视频固定至少20个画面需求，覆盖同型号/相似错误型号、进料/运行/出料、短暂动作、不同机位、解说/无声、无关车间和缺镜头。事先标注正确出处及时间范围，运行后不换题求过。

核心参数及设备身份不得错配，私有/撤权泄漏为0；有答案的语义样本前5候选命中率至少90%，无答案不编造。记录文字基线、向量增量收益、排序错误和实际缺内容，不能把有结果或相似分数当质量。指标只用于固定样本接受，不外推所有用户库；最终作品逐句看片试听。

还须覆盖：直接用户事实/无知识条目、只有视频/只有文案、定稿过长、术语混读、只改字幕/只改声音、一版失败、整组/单版指令、手动与AI冲突、重复文件/重命名/失联、分析中接制作、资料指令注入、撤权/索引失效、断网/限流/未知结果、关闭窗口/Quit/强杀/睡眠、磁盘满/导出覆盖与取消、旧项目/模板、外部消息重放。手机配对/上传/同文采样按§1.1.4保留后续独立真机验收。

| D、G / P4：字幕与分镜独立 | 同一英文文案段含多条短字幕与单词尾段，按[产品§8](../docs/product-requirements.md#8-制作方案与模型)核对真实配音段到镜头区间；字幕重新分行/改字号不新增切镜点。局部重配音时只按受影响真实段时长调整，保留其余声音/字幕/人工镜头；再撤销核对原版本。现有计划须经明确重算才替换，不能因算法更新静默覆盖人工编辑。 |
| H / P3、P5：三轮精修与手动交替 | 同一作品依次只改字幕文字、改一句配音、替换一个镜头，中间加入一次手动音量或裁剪；每轮核对直接变化与应保留内容，记录实际调用/作业、复用产物及摘要、原/新版本。字幕修改不重新生成声音/口型；配音变长时按真实依赖检查后续位置；换镜头保留无关声音。最后撤销/重做并真正Quit重启，核对可播放版本和用户选择。 |
| G / P4：独立语言版本 | 只修改英文文案/声音，比较中文版的采用版本、时间线、有效产物与执行记录；中文版不应新增无关制作作业。双语字幕同片的联动按原用例G另验，不能混为两条独立交付。 |
| H、L / P0、P5：修改等待与观察 | 分开记录排队、模型加载、有效执行、检查、最终编码和修改到可用预览耗时；同机同输入比较冷启动与已就绪情况。局部预览、最终文件和实际检查范围分别留证；抽查修改处、剪辑点、转场、字幕和音频衔接。硬件编码只在固定画质/时基条件下比较，不能用编码提速冒充配音或全链路提速。 |
| I / P5：成功经验复用 | 保存认可任务的模板或Skill候选后换产品/主题和资料；检查结构/风格复用、旧型号/价格/客户/素材未泄漏、事实引用重新取得，不通过复制旧输出凑成片。 |

每次记录实际复用与实际执行，最终文件重新编码不自动判为“全量重生成”，缓存键存在也不自动判为“局部重算通过”。以上样本先建立真实基线，不照搬竞品速度数字或承诺固定秒数；人工投入、失败/放弃和首次建库的统计沿[产品§3.2](../docs/product-requirements.md#32-用户核心结果)与[§15.2](../docs/product-requirements.md#152-用用户结果衡量推进)。竞品对照须使用同一输入和接受标准并区分官方声明与实际测试，不能把未试用产品的能力表当作性能证据。

以下交叉场景沿A–N及E01–E18验证，不以原型替代：

1. 一人启用到四人、第五人加入、超额并发邀请失败、撤销/过期/重复绑定；停用不丢内容。
2. 私有素材/声音/资料与共享内容正确召回；主账号不能越权读私有原件，成员不能从词云/缓存/助手泄露他人内容。
3. 混合批次无说明可分析，有说明提高理解；红烧肉纠正影响真实检索和替换，重分析保留人工事实。
4. 完整文件自动分析、复制中跳过、补扫/重启幂等，导入不自动制作；素材可用阶段准确可见。
5. 知识文件/链接有结构参数和来源快照，矛盾参数不混用，文案引用可回查，恶意资料指令不执行。
6. 03镜头换更好素材：定位对象→相关候选→保持配音/锁定约束→直接编辑→真实预览→版本/撤销。
7. 本人电脑录音试听应用；声音克隆、英文/混读、人物口型分别验证，不合格明确缺口。
8. 模板创作的文案按本次委托采用；定时触发不新增授权，保留已设审核和发布确认边界；错过夜间窗口和关客户端不丢任务。
9. 五个真实会话同机：预览/录音、导出、局部预览、导入、编辑排队；按PRD12.1测响应/连续性/峰值/公平/解析推进，不能以模拟互斥代替。
10. 发布/数据逐平台验证真实结果和权限；外接盘故障、重启、恢复、导出及同候选测试包均留证。

Pi 与脚本还需覆盖：完整对象/schema发现，明确单位与省略/清空语义；Code Mode有界复合调用及失败后原请求查询；授权媒体脚本实际视听、文件/网络隔离和完整进程释放；成功配方在另一输入和新会话复用；后台结果接续、插话/停止/重启及晚回包；外部CLI与GUI同版本回读、撤权/跨空间和未知结果恢复。已具备的节点复用有效证据，新增媒体类型不由单PNG实测外推。
