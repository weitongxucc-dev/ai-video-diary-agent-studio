用途：版本范围已获授权，实际实施范围以活动合同和最新用户指令为准；历史工作包记录不恢复已释放或暂停的 lease。2026-10-12 的 Pi 开放能力、脚本、扩展、细粒度编辑与外部 CLI 改造方案见第 4.2 节；用户已批准实施，运行权限与功能可用性仍以实际实现和验证为准。当前完成度以代码和验证证据为准。产品品牌为曜核1.0，`0.11` 是内部版本范围，本文件不修改应用版本或创建发布标签。

#### 第一波的具体开发顺序

1. 主控先冻结 AG1 最小字段/API 及事件/确认语义，并定位 AG0 已知 driver 停止；这是共享文件的单一写入队列，不能让多个 Agent 同改 main.py、production.py、schemas.py 或迁移文件。
2. 素材负责人同时补 AG2 的观察→标签→检索消费者；优先复用已有 ASR、OCR、CLIP、人工 CAS 和未提交候选。AG3 在档案及证据引用契约定稿后接入同一回合上下文，不等扩容工程结束。
3. AG1 先落地单请求、首窗和恢复入口；总数量机制从第一天有界，不先做“五条特例”再重写。AG2 将合格候选接入同一方案/故事板。已有基础可达时立即开展 AG4 小样集成，随后升到新两分钟目标。
4. 首启/品牌和发布可行性调查在共享身份/产物接口稳定后并行；手机协议交接不要求先重做手机 UI。真实多成员、三平台发送和真机联合验收使用独立的实际条件，不挤占第一条成片的迭代。

首波结束门禁为 AG4 的新目标闭环、最小有界请求机制及旧消费者退出，不是“所有底层模块分别完成”。AG5–AG9 按依赖继续，三平台与 0.12 联合验收分别保留交付门槛。

#### 实施前必须定稿的共享接口

- CreationRequest：可信原句、总数量、输出关系、时长作用范围、明确素材范围/接收时间与发送者、共同要求、澄清/确认身份和版本。只保存有限展开项；单片 Plan 不再承载请求总数。
- 外层驱动：稳定窗口身份、序号/游标、输入摘要、事务展开、等待原因及相关唤醒条件；读取现有任务/作业/依赖结果，不增设从聊天推断的完成字段。分别定义总目标、窗口、文案、开始制作及发布的确认范围，复用已经明确的决定。
- 素材/知识引用：对象、版本、源时间/段落位置、观察模态、推断及人工纠正分别表示；只为实际查询和检查需要补字段，不预填无消费者的评分。
- 档案/经验：沿既有 Workspace profile/偏好存储明确唯一 owner；user.md 优先作为可读投影/受控导入接口，不能任意加载文件或成为并行事实源。新经验绑定 CreationTask 和实际采用/拒绝证据，旧 Episode 经验保留历史、不默认成为新任务完成事实。
- 工具清单：按可信对象、权限和实际能力发现与选择，阶段只提供默认分组；具体编辑字段、代码编排、脚本和扩展机制见第 4.2 节。建议、提案、应用和执行分别返回真实结果。四个已接应用命令复用；其余 Pi 命令逐项核对 GUI 适用性，不直接转发任意 TUI 命令。
- 重型检索计算：受许可故事板接语义前，将文案向量推理纳入真实设备资源声明/可复用缓存与检查点；不能只给 MontagePlanner 加 provider 后在 metadata_only 阶段偷偷运行模型。
- 外部回执：本地事务幂等与远端执行分别处理。已执行、未执行、未知结果区别保存；无法核对的远端结果不盲重放，不许承诺无法证明的恰好一次执行或费用。

#### 4.2.1 目标、能力判断与审阅证据

Pi 支持自定义工具、SDK/RPC，以及模型编写 JavaScript 来组合工具的 codemode；陌生接口可以通过文档/schema/源码学习。它是否能写文件、运行媒体脚本或加载扩展取决于宿主开放的入口。新字段只有在服务端或扩展的实际 schema 与执行实现中存在才可调用；生成字段名或工具说明不等于实现了能力。参见 [Pi 扩展](https://pi.dev/docs/latest/extensions)、[codemode](https://pi.dev/docs/latest/codemode)、[SDK](https://pi.dev/docs/latest/sdk)、[RPC](https://pi.dev/docs/latest/rpc)。ChatCut 的[桌面本机 Agent](https://chatcut.io/docs/desktop-app)与[托管 Agent Plugin](https://chatcut.io/docs/agent-plugin)是两个接入方式，可借鉴共享可编辑项目的结果，不推定其闭源实现或执行权限适合曜核。

| 动作依赖原句固定语法 | 模型提交类型化动作和可核验的目标/参数，原句保留为来源；确定性编译器校验动作与影响，不承担所有自然语言理解 | 模型不重写可信身份/用户原句；目标解析与授权在服务端完成 |
| 模型不能编程组合工具 | 显式接入受控 codemode，允许循环、计算、筛选和独立读取并行；相互依赖的修改按版本顺序执行 | 子调用经过同一 API；不让并行写覆盖版本或让失败掩盖已提交动作 |
| 一个回合只能一个预览、失败即止 | 支持有界复合提案或回读结果后的下一步；已确认未产生副作用的参数错误可依据明确回执修正；异步结果未知先查询 | 同一请求幂等、版本冲突和实质确认保留；不得无依据重写用户要求、重跑未知执行或增加资源预算 |
| 不能编写媒体处理脚本 | 新增任务内脚本草稿、验证及受许可运行入口，产物回到现有登记/预览/应用链 | 运行输入、文件/网络隔离、资源测量、产物实测和进程释放；不得只删除启动禁用项 |
| 不能扩展工具或载入领域知识 | 提供版本化扩展配方与受管理的剪辑 Skills/接口说明；允许从成功脚本生成可复用工具 | 自建代码在隔离执行环境运行，宿主只加载可信代理；不自动加载个人目录、任意第三方扩展或赋予模型密钥 |
| 等用户再说“继续” | 已批准目标的提案采用、作业完成/失败等持久事件触发接续，先重读状态再决定是否需要模型 | 复用现有外层循环与事件；同一事件有界消费，未变化阻断不反复调用模型 |

不把“安全”泛化为每个参数都要用户手填或每个内部步骤都要再次批准。普通表达由模型推导，关键歧义展示候选；实际文案、提案应用、删除、外发等决定沿[产品 §2.3](../docs/product-requirements.md#23-自然语言与精确编辑共享同一事实源)及对应对象规则。技术校验检查媒体和执行事实，内容质量仍需实际看听与用户采用，不能用模型自评代替。

#### 4.2.3 字段要足以完成动作，读写协议共用一个定义

先盘点后端已支持动作与 GUI 消费者，补齐 Pi 和 CLI 的映射；不先堆大量新工具。由业务动作 schema 导出工具声明、CLI JSON 输入及能力说明，实际 validator 为同一来源，不分别手写三套参数范围。

| 协议层 | 最小字段和语义 |
| --- | --- |
| 能力发现 | 能力名称/版本、输入/输出 schema、适用对象、前置条件、是否可执行及原因、可用运行时/依赖、允许的资源档；副作用提示来自业务实现，不信任模型自报 |
| 镜头读取 | 稳定对象引用与版本、素材/片段引用、源起止秒、时间线起止秒、画幅/尺寸、速度、裁剪位置、转场、锁定、关联旁白/字幕/人物和已知失效依赖 |
| 配音/字幕读取 | 音轨/片段/cue/track 引用及版本，文本、起止秒、实际时长、声音版本、已有速度/音量与关联；正文/逐词信息按需要分页读取，不把短截文当全文 |
| 动作写入 | `operation_type` 判别的参数分支、`target_refs`、期望时间线版本/序号；替换源区间、裁剪、倍率、位置、转场、字幕文字/时间/样式、音频范围等只在相应分支出现 |
| 复合编辑 | 有界 `actions`、明确依赖/顺序、共同基础版本与保持旁白等约束；先验证整份提案，应用到草稿为一次领域事务。媒体生成可能部分完成，回执保留各真实结果，不能承诺进程副作用可原子回滚 |
| 提交回执 | 实际提案/作业/操作标识、输入/结果版本、输入摘要、已修改对象和字段、失效/保留依赖、产物引用、警告及明确错误。接受、排队、运行、产物提交、版本应用分别描述 |
| 错误与恢复 | 区分 schema 错误、能力缺失、授权/状态拒绝、版本冲突、未执行失败与结果未知；带实际错误字段、允许值或能力说明定位。只有失败事实支持的修正才继续 |
| 长作业 | 作业标识、输入版本、阶段/进度、等待原因、结果种类、产物/提案引用、取消与终态；用现有状态词，不由模型增加一份完成状态 |

单位沿现有业务 `_seconds`、播放位置 `_ms` 约定，在 schema 中明示；速度是有限无单位倍率，裁剪坐标沿现有 0–1 含义。必须区分省略、清空和设置值；不得把任意 `null` 当删除，不以自由 `dict` 承载无验证的全部动作。陌生字段先查询定义；确实没有的能力走脚本或开发提案，不能静默忽略或让 `additionalProperties` 绕过业务规则。

模型可读 ID、版本与参数来完成定位，用户界面显示镜头序号、内容、时间和实际变化。初始摘要保持有界，返回 `truncated`、游标或具体遗漏数量，并提供授权范围内的片段/时间区间/字段按需读取。schema 通过不等于真实模型能稳定调用，必须用当前配置模型验代表动作、单位和错误修正。

#### 4.2.4 自写脚本、创建工具与可信宿主的分工

分两类程序，不以“全部开启 Bash”替代接入设计：

1. **编排程序**：显式启用 Pi 官方 codemode 候选，模型写 JavaScript 调用已授权工具、查询 schema、做计算和组合动作。其 QuickJS 环境通过工具访问外部；副作用仍在工具外部执行，脚本失败不会撤销已经提交的调用。工具需要结构化输出，修改串行回读。接入时同时核对官方 `models.*` 直连能力，不让它绕过曜核的模型路由、媒体外发与设备排队；若无法限制该通道，本版只接入等价的工具编排环境，不能宣称仅凭 QuickJS 就已满足产品边界。
2. **媒体程序**：模型通过任务内草稿入口写 Python/媒体处理脚本，读取已授权输入并生成本作业产物。实际进程仍由既有 JobRun/DeviceScheduler/受许可子进程启动。首包仅复用 TaskMediaJobs 的短预览，当前它固定使用 `preview_dependency`；正式生成与后台处理须由已有业务 Owner 按执行用途映射对应调度策略，不能给全部脚本预览优先级。脚本可以调用受支持的 FFmpeg/ffprobe/Pillow 等工具链；工具链与运行时按本机实际发现，不自动安装依赖或假设 Python 已随安装包交付。

首个媒体脚本工作包先实现以下契约，名称是待实施接口设计：

| 层次 | 字段与责任 |
| --- | --- |
| 模型提交 | `script_source`、`language`、`parameters`、带版本的 `input_refs`、`target_refs`、期望基础版本、`requested_outputs`、执行用途 `purpose`（短预览/正式生成/后台处理）；代码可以自由表达算法，持久字段和产物类型仍由契约约束，用途经 Owner 核验后才确定调度类别 |
| 宿主封存 | 可信成员/空间/任务、请求身份、脚本摘要、运行时及工具链版本、输入修订、已批准目标和输出契约；代码/参数/输入/工具链改变必须改变摘要，重放读取已封存输入 |
| 资源事实 | 从唯一输入源实际测量字节、时长、尺寸等，复用可对应的已测资源档；脚本声明不能授予许可。新处理算法补具体资源政策与标定，不伪装成旧渲染类型借用预算 |
| 运行输入 | 仅授权输入的映射路径、必要参数及固定输出目录；不传模型密钥、成员令牌、Cookie、数据库路径或许可对象。脚本读取接口/schema 使用单独的无秘密投影 |
| 候选输出 | 有界清单描述相对文件名、种类、格式与诊断；路径、符号链接、实际媒体流/时长/尺寸/大小、内容摘要均由宿主核验。退出码 0 和自报结果不能代替实测 |
| 产物与应用 | 临时产物→ArtifactStore→ArtifactRecord/TransformRun/DependencyEdge→按输出种类登记可编辑来源及源区间→可检查预览/类型化提案；应用后沿现有 EditOperation/TimelineVersion。脚本不得直接覆盖源素材或当前版本 |

产物登记和可编辑素材来源是两个接续步骤。视频、音频和图形分别映射既有 MaterialAsset、音源或图形来源契约，保留派生关系、源区间、输入修订及继承的可见性/使用限制；确需扩展引用解析时在同一业务入口实现并验收。不能假设 ArtifactRecord 自动成为普通镜头来源，或将任意 artifact 路径填入替换候选。对应产物校验与预览验证要认识该输出种类，才能进入镜头/音轨/图形，重启后仍可解析。

当前 `run_granted_command` 尚无文件/网络隔离。因此任意媒体代码正式开放前，须实证输入只读、作业目录可写、其他工作区/私库/凭据不可读、未授权网络不可达、子进程受同一回收与资源控制。`cwd`、删环境变量、提示词、代码黑名单或 `node:vm` 都不能单独作为该证明。macOS 和其他目标平台的隔离实现/随包运行时在此工作包选型并真实验证；未验证时保持该项未可用，编排程序与类型化编辑仍可独立交付。

自建工具的首版采用**扩展配方**：名称、说明、输入/输出 schema、版本、源代码摘要、依赖的已有能力、已验证运行配方及适用范围。工具声明由可信宿主生成代理，代码在上述执行环境中运行；不把模型新写的 TypeScript 直接加载进持有令牌/密钥的 Pi 宿主进程。宿主重算真实副作用和权限，工具自报 `readOnly` 不能免检。成功脚本可登记并在后续回合发现/复用；失败候选保留诊断，修改生成新版本；保存工具不授予未来所有任务的素材权限。

已存在接口可以读说明后自行写适配程序；缺少专用按钮的要求可组合工具或生成产物；软件本身缺少的持久字段/渲染语义则形成源码开发提案，按正常开发、验证、集成进入软件。运行中的剪辑 Agent 不自动修改安装包、中央 API、数据库 schema 或产品权威。受管理 Skills 用于剪辑知识和调用范例，不能成为第二份业务约束或秘密配置；未知依赖返回缺口，已有可用能力先继续。

#### 4.2.5 执行结果驱动继续完成剪辑

每次动作返回真实机器可读结果；异步提交立即返回既有作业标识，任务不会因为当前模型回合结束而丢失。提案采用/拒绝、作业终态、相关资源改变等沿持久事件唤醒同一目标，宿主先重新读取当前版本和已批准范围，再确定性接续或启动下一有限 Pi 回合。应用会话保留触发来源与提案/作业关联，不伪造一条新的用户指令或沿过期选择继续。

接续必须区分：继续已批准生成、提出待应用修改、等待必要决定、真实不可用与目标完成。普通状态查询不反复调模型；相同未变化错误不无限重试。参数验证已明确未执行的失败可以按回执修正；已执行或结果未知先回读已存作业/产物。停止当前聊天、取消制作和撤销已应用版本保持不同对象语义。回读/落盘成功后才能声称保存，完整预览可播放后才能声称已生成；HTTP/SSE、UI 轮询与重启恢复均投影同一持久事实。

近期保留现有 print/JSON 会话方式，把工具发现、编排和持久事件接续先接通。需要长驻控制时再依据实际消费者评估 SDK 或 RPC；采用 RPC 也不会自动补齐目标、授权、结果回传和重启恢复，不为使用框架重建队列或生产状态机。

#### 4.2.6 CLI/MCP 与 GUI 共用剪辑能力

CLI 是正常业务 API 的薄客户端，支持能力发现/说明、任务与素材读取、类型化预览/提案应用、脚本提交、工具登记、作业查询/取消及成片导出。外部 Agent 使用自身模型决定动作，曜核负责编辑与执行；可选委托内置助手完成整个目标，但不强制形成两层模型转述。MCP 后续封装同一适配协议，不另造动作 validator 或状态库。

已落地的源码 CLI 命令、配置和已知边界统一见[CLI 协议](../docs/cli.md)。本节不再维护另一份命令示例；桌面随包安装、导出命令及 MCP 包装分别按实际消费者验收。

成功/失败统一 JSON 回执和退出码；排队/运行中是异步状态，不伪装成成片成功。有界等待与查询沿现有作业接口，取消返回真实终态/释放；输出文件通过现有导出与路径授权入口处理。认证凭据经已有本地成员/Supabase 机制或受保护配置取得，不放命令参数、示例 JSON 或日志。没有 GUI 选中状态时，CLI 显式提交对象和期望版本，由服务端核验。

应用提案的幂等覆盖草稿提交与可能生成的作业：绑定稳定请求身份、原提案及输入摘要，相同请求返回原 EditOperation、结果版本或作业；相同身份携不同内容须拒绝。第一次应用成功但回执丢失时，按请求/提案查询真实结果；不能把“已不是 proposed”的 409 当作未执行，也不能重试时替换为最新基础版本。PI-01/04 共同补齐这一契约，CLI 不自行缓存一份业务成功事实。

抽取现有业务校验为共同受理入口，Pi 从应用会话绑定来源，CLI 从可信成员会话绑定来源和请求身份；共同生成提案/执行回执。CLI 不伪造 `assistant_turn_id`，也不删除 Pi 原句绑定来规避版本检查。已存在的 GUI 精确编辑语义保持；CLI 的提案应用沿同一实际决定，本版不新增默认“全部自动允许”。外部 Agent 在自身环境直接运行 Shell 不属于曜核受许可作业，不得把其文件当成本软件已经登记保存的结果。

#### 4.2.7 开发顺序、代码入口与退役目标

各包负责人是用户结果的纵向 owner。以下是实施拆分，不恢复源码 lease；主控在开包时冻结共享协议和互斥文件。首先完成稳定类型化闭环，编排、CLI 和脚本在同一接口上推进，不等九阶段全部重做。

| 包 | 用户结果与具体改动 | 直接入口 / 依赖 | 完成与退役条件 |
| --- | --- | --- | --- |
| PI-01 完整读写闭环 | 先以换镜头保留旁白为样本，补有界对象读取、已有动作字段、应用请求幂等和完整回执，原句保留来源 | `schemas.py`、`main.py`、`assistant_pi.py`、`diary_tools.ts`、`types.ts`；API/schema 单一 writer | 同一候选模型提出→实际预览→应用→保存→撤销；回执丢失可查询原应用，已有精确编辑仍可用。删除“通用工具只能两个替换字段”的旧表达路径，必要原句入口转为同一动作编译消费者 |
| PI-02 编排与发现 | 可信能力目录、按需 schema、受管理 Skills 与 codemode；已实现后端动作可跨阶段发现，模型自己计算参数、组合程序 | `assistant_pi.py`、`agent_tools` 及对应测试；依赖 PI-01 的最小共同协议 | 有用户要求但没有专用组合工具时，模型写程序完成现有动作组合。退役阶段作为唯一能力门、隐藏已可用工具；保留真实权限/前置拒绝 |
| PI-03 事件接续 | 回执保留提案/作业/版本关联，采用/终态触发同一目标下一有限回合，界面可看到持续完成与具体等待 | `conversation_repository.py`、`main.py`、`task_audio.py`、现有 driver/对话组件；依赖 PI-01 | 预览异步完成和应用后无需用户重复说继续；重启/重复事件不多次提交。退役一次预览后固定停住与仅 UI 轮询的接续路径，保留明确决定等待 |
| PI-04 CLI 首版 | 先发现、读取、编辑、应用和作业观察，再接脚本/扩展；同一后端协议与认证，CLI 用例说明供外部 Agent 学习 | 现有 HTTP API/动作 schema；新增 CLI 入口只因有真实外部消费者；与 PI-02/03 可并行 | 外部 Agent 与 GUI 看见同一版本/产物并支持撤销；无数据库、FFmpeg 或第二调度旁路。CLI 已登记范围与实现一致，未接入能力明确不可用 |

#### 4.2.8 真实验收与方案未决项

1. **细粒度动作**：当前配置模型从真实读取推导镜头裁剪/速度、字幕时间和替换候选，单位与范围正确；未填写 ID 的自然表达可定位，关键歧义才询问。服务端未支持字段给明确错误，模型不会凭空制造成功。
2. **编排程序**：没有专用复合工具时，Pi 写程序选择候选、计算参数并生成有界复合提案；独立读可并行，依赖写不覆盖；脚本中途失败能回读已提交结果。
3. **媒体脚本**：用一段明确授权的五秒素材，模型自行编写裁剪/叠加或音频处理程序；实际看听、媒体规格、持久产物与可编辑来源解析通过后，应用到同一草稿、导出、撤销并重启回读。画面/听感与技术校验分别记录；后续正式生成/后台脚本另验用途分类与公平排队，不以短预览证明。
4. **扩展复用**：把上例保存为有参数 schema 的工具，新会话在另一明确授权输入上调用，版本/代码摘要可定位，真实输出可用；保存代码和注册名称不算通过。
5. **连续完成**：异步排队→完成→必要提案采用→后续生成均沿已批准目标接续，不再靠重复“继续”；拒绝、修改、停止、资源等待与重复事件保持真实状态，不无限调模型。
6. **外部调用**：至少一个外部 Agent 通过已安装 CLI 完成同一改片/脚本任务，GUI 回读一致；重放、过期版本、双成员/空间、输入修订、结果未知查询、取消/超时后进程释放分别核验。
7. **执行隔离**：实际尝试越界文件读写、私库/凭据访问、未授权网络和派生进程逃逸，验证拒绝；测量脚本执行的 CPU/RSS/线程/IO/输出和时限。资源许可、目录约定或静态代码审阅不能替代该项。

未决项只保留有实际消费者的选择：目标平台脚本隔离方式与随包运行时、官方 codemode 的模型直连限制、代表脚本资源档，以及动作 schema 导出和实际模型兼容。由对应工作包提交实测证据后定案，真实验证按PI-OPEN合同执行。SDK/RPC、MCP、跨平台与专业编辑器的全功能对齐均按实际需求后续验证，不把它们当作首个闭环的前置。

### 4.4 Pi 对象、观察与接续的实施接口

本节描述源码接口及后续容量验收方法；实际交付与运行证据仍归 [#118](https://github.com/weitongxucc-dev/ai-video-diary-agent-studio/issues/118)、[#119](https://github.com/weitongxucc-dev/ai-video-diary-agent-studio/issues/119)、[#120](https://github.com/weitongxucc-dev/ai-video-diary-agent-studio/issues/120)，不以接口存在判定端到端完成。业务、授权与媒体边界沿[架构 §3.13](../docs/system-architecture.md#313-持续创作的双层-agent-循环)。

- **对象读取**：`read_task_object` 从完整授权集合分页，支持镜头、字幕轨/条、配音段、已确认文案段、音轨/片段及已采用图层。摘要截断不截掉底层可读取对象；响应给出稳定 ID、父关系、真实计数、单位、当前时间线与修订。选中对象只定位要求，不限制发现同任务的其他授权对象。
- **动态知识**：`find_knowledge` 在普通任务中调用认证的 `/api/knowledge-items/search`，在数据库内过滤当前可引用内容、权限和版本，再返回有界页和摘录；文案阶段仍限定实际允许来源。旧引用保持原版本，执行时重新检查使用状态及授权。当前检索算法是 SQLite 子串扫描，不能由 1000 条功能验证推定百万条性能或语义召回质量。
- **实际结果观察**：`read_task_observations` 返回当前/历史技术检查和可观察目标；`observe_task_output` 绑定本任务登记成片或媒体作业产物，以同一设备许可最多抽取三帧，保存版本、产物摘要、实际尺寸/时长及有限测量。原请求用 `read_task_observation_request` 查询。OCR 必须有本地 worker 摘要和独立实测预算；未配置时明确不可用。像素、OCR、内容理解、听感分别报告，不能互相代替。
- **自动接续**：复用原对话消费回执与结果检查点；真实业务事件被原子消费后建立空 `user_message` 的后台回合，Pi 获得原真人要求与新的已核验事实。普通界面显示“继续完成原要求”；用户实际采用后才推进依赖采用的下一步。普通制作作业与媒体作业均须有真实终态观察消费者，不能只等待一条永远不会产生的事件。

持续增长的素材库还要单独验证：当前素材搜索已有服务器过滤和分页，而素材状态汇总仍逐页读取；跨页期间同数量的内容替换不能仅靠总数识别。下一容量实验先测实际搜索/汇总耗时、返回大小及新增/更新/排除/撤权的可见性，再按测量选择数据库汇总、检索索引或可重复分页版本。索引属于可重建派生物，不能取代原记录及授权判定；没有容量或召回证据时不先引入通用向量库。

实施按三个纵向包推进，root负责共享权威与最终集成：

1. **已有精细动作接入**：API/编辑Owner独占共同 schema、音频/视觉 preview编译与能力目录；Pi/CLI Owner在协议发布后接消费，不同时写 schema。验收“第二段音乐降低6dB、结尾淡出→试听→实际采用→渲染→回读”，保持其他轨及历史可撤销。优先补已存在执行内核，未定义的字段不先画开关。
2. **结果检查与文字修复**：观察Owner提供本地真实字体目录/字符覆盖及字幕/图层有效显示时间映射；使用已许可且有实测预算的检查能力。Pi沿当前目标定位对象、提出修复、采用后再观察；未完成OCR/语义/听感时清楚报告。验收中文缺字案例，不以模型自评成功结案。
3. **中栏与通用时间线**：Web Owner先复用真实工具/业务事件展示“当前在做什么、已完成哪些动作、等待什么决定、产物及检查范围”，展开可看对象、版本、实际时长及错误。计划中的步骤与已执行动作分开，不显示假百分比/未经执行的完成勾。随后视频轨、链接、独立retime和必要关键帧由纵向Owner单独定稿领域契约，再贯通同核读取、编辑、撤销、渲染与CLI。

每条能力须同时交付对象ID/关系、单位和范围、真实动作语义、实际可用条件、版本/请求绑定、预览与输出、错误和可观察结果；加一个字段或工具名不是完成。失败原因须够定位：类名、结果未知、输入错误、运行时变更不可混为一个可重试提示。脚本运行时的可信摘要需要有稳定的维护生命周期，不能通过忽略可执行字节或放宽校验消除拒绝。

## 5. 本地多模态技术方案与选型门禁

### 5.1 处理链

1. 文件探测：复用FFmpeg/ffprobe识别音视频流、时长、方向和格式；保存源指纹。
2. 初始片段：镜头变化与静音提供候选切点；结合转写和动作边界修正。先引用源时间区间，不默认复制大量切片文件。
3. 听觉：优先复用现有本地Whisper，识别真实语言，保存转写时间；字幕精确对齐另做验证，不把粗略ASR时戳当逐词真值。
4. 文字：本地OCR候选优先评估macOS原生能力；中文、英文、小字和屏录用例分别验证。OCR不能靠“VLM大概读出来”替代。
5. 视觉：静态片段少量代表帧，动态片段按时间有序抽帧；疑难区间增加采样或局部分析。画面描述必须保留证据帧/时间。
6. 融合：合并可追溯的观察，不把声音提及的产品自动标成画面真实对象。输出未知和疑点，不要求模型填满所有标签。
7. 索引：结构化过滤、文字和视觉索引协作，沿现有资产和存储；模型/参数变化时可增量重建。
8. 反馈：用户纠正事实与本次/长期偏好分开；再次分析不覆盖人工纠正。

### 5.2 4B设备实验

同一批授权本地短样本比较4B量化与2B量化，记录：模型精确版本/校验值、输入帧数与尺寸、加载耗时、逐片段分析耗时、内存峰值、交换压力、持续运行温度/性能表现及错误输出。质量核查覆盖主体、动作顺序、屏幕文字、产品身份与不知道时的表达。量化版本与运行时锁定后才能形成可复现基线。

样本至少包含：静态产品、接口操作、人物口播、屏幕教程、光线差或快速动作、中英文字画面。先验证离线下载后的运行，再在应用中验证资源让行。4B若无稳定质量收益或明显影响剪辑，提供实测取舍；不自动增加云调用。该实验尚未执行，不给出未经测量的速度或内存承诺。

### 5.3 检索与重排实验

对人工标注的“文案需求—合适片段/缺素材”样本记录候选召回、首选保留和错误类型。先对比当前算法与多路召回，再只对候选评估本地重排；另验整片重复与节奏。缺素材样本必须入集。重排方案仅在改善用户选片且耗时可接受时接入，不能强制所有片段反复运行VLM。

### 5.4 对话模型与后台模型分工

0.11 用户对话、文案和编辑意图使用外部文字模型；MiniMax-M3 为首选，DeepSeek 保留主动切换。对话 Agent 优先复用 Pi 的会话和工具调用，不另写通用 Agent 循环；产品业务工具仍走现有 Plan、EditProposal、CreationTask 和版本路径。后台本地 4B 只负责素材解析。对话请求仅发送必要的文字上下文与筛选证据，不发送原始媒体或整库；界面展示服务、数据类型和费用边界，不自动切换供应商。模型下载、依赖安装与外发/付费是不同动作，实际收费调用仍按授权边界执行。

## 9. 自然语言执行与预览协议

模型只产生结构化意图/操作计划，不直接提供可执行shell。每个工具有适用对象、参数边界、成本/耗时信息、可取消性和失效关系。明确范围不重复提问；含糊且影响不同结果时展示候选。

真实预览策略：构图/图文提供画面预览；调色/美颜/转场提供短片段前后对比；音轨提供选区试听；多轨时间变化提供同步视听片段。预览是派生产物，取消后不改变当前有效版本。正式输出使用同一参数和执行语义，预览的低分辨率必须明确标记。

“刚才那段”“再弱一点”绑定当前对话中的具体对象与操作，不只依赖最后一条字符串。切换任务重建当前目标引用，保留活动会话和草稿；发送时固定目标快照，晚回包不随选择漂移。旧提案遇到新版本需重新核查，不能自动覆盖。未支持指令应说明缺的能力与可执行替代，不伪造成功。

### 12.2 验收场景补充

既有A–K及E01–E18全部保留，下列为新增交叉验收，不可用原型替代：

1. 一人启用到四人、第五人加入、超额并发邀请失败、撤销/过期/重复绑定；停用不丢内容。
2. 私有素材/声音/资料与共享内容正确召回；主账号不能越权读私有原件，成员不能从词云/缓存/助手泄露他人内容。
3. 混合批次无说明可分析，有说明提高理解；红烧肉纠正影响真实检索和替换，重分析保留人工事实。
4. 完整文件自动分析、复制中跳过、补扫/重启幂等，导入不自动制作；素材可用阶段准确可见。
5. 知识文件/链接有结构参数和来源快照，矛盾参数不混用，文案引用可回查，恶意资料指令不执行。
6. 03镜头换更好素材：定位对象→相关候选→保持配音/锁定约束→真实预览→确认→版本/撤销。
7. 本人电脑录音试听应用；声音克隆、英文/混读、人物口型分别验证，不合格明确缺口。
8. 模板与定时任务生成新候选，文案/发布确认仍需人；错过夜间窗口和关客户端不丢任务。
9. 五个真实会话同机：预览/录音、导出、局部预览、导入、编辑排队；按PRD12.1测响应/连续性/峰值/公平/解析推进，不能以模拟互斥代替。
10. 发布/数据逐平台验证真实结果和权限；外接盘故障、重启、恢复、导出及同候选测试包均留证。
