# Agent-first 产品验收索引

本文件只保留版本覆盖、用户结果和验收样本，不复制产品规则、动态完成状态或线程派工。产品范围由[产品需求](../docs/product-requirements.md)，对象和状态由[领域模型](../docs/domain-model.md)，界面由[设计规范](../DESIGN.md)，当前工作包由[活动合同](active-contract.md)。

## 1. 用户结果覆盖

| ID | 用户结果 | 最小真实验收 |
| --- | --- | --- |
| R01 | 用户从自然语言目标开始，Agent 在同一作品中理解、执行、回读和继续 | 新建入口、首次输入、空作品区、对话时间线和真实任务绑定 |
| R02 | Agent 可以从素材和知识证据中找到可用内容并说明依据 | 固定样本检索、原片区间、来源/版本/权限回读和候选采用 |

| R04 | 复杂创作可以有多个方向并比较采用 | 两个以上独立 Session/分支、预览、比较、采用、回滚和隔离取消 |
| R05 | 作品发布后能回查真实平台状态，并把反馈带入下一次创作 | 一个真实平台账号、用户确认、平台内容编号、真实数据或明确未知 |

| R08 | 跨端和安装交付有独立证据 | Mac、Windows、手机和安装包分别验证，不相互外推 |

## 2. Agent/Pi/Skill 验收样本

- **理解与选择**：用户一句自然语言目标，Agent 能识别目标、范围、已有输入和真正缺少的决定。它应自行读取证据并提出最小澄清，不要求统一参数表单。
- **执行与回读**：对一个已绑定作品完成一次素材读取、文案或镜头修改、保存新版本和结果回读。文本回复和执行记录不算保存证据。
- **失败与恢复**：工具失败、结果未知、停止、追加和重试都沿原请求身份处理。不能换 ID 重提或把排队说成完成。
- **证据与权限**：给定两个相似素材和一个撤权素材，Agent 只能使用有来源、版本和授权的候选，误用为零。
- **作品与分支**：同一作品产生两个方向，未采用分支不覆盖正式版本，采用后形成新 TimelineVersion。
- **发布与反馈**：一个真实平台完成发布确认和内容编号回读，公开可见性和数据状态分别记录。

## 3. 旧入口退役条件

满足以下条件后，才能移除统一创建表单作为默认入口和旧的阶段导航：

1. 新建视频打开持续 Conversation 与空作品区。
2. 目标、引用和必要参数可在对话中形成并持久化。
3. 作品台能显示当前版本、运行状态、结果和下一步动作。
4. 旧表单消费者不再是默认路由，仍可作为上下文检查器或特殊恢复入口。
5. 负向搜索确认没有“先填表再检查”作为默认文案、路由或测试保护。

旧入口退役只针对产品入口和文档表达，不删除历史数据或用户保存的作品。

## 4. 未决实证

以下事项必须分别取得真实证据后更新对应 Issue/PR，不能写成文档中的完成事实：

- 设备资源档和同一 userData 下的媒体任务。
- 真实 Provider key、模型、usage 和账单字段。
- Electron 桌面真实入口、刷新/重启恢复和最终成片播放。
- 人物/声音真实档案与授权。
- 一个真实平台的发布和反馈回读。
- Windows、手机、签名、公证、升级和生产环境。

## 5. 工作追踪

具体任务使用 GitHub Issues，代码使用 PR 和 CI，Multica 只保留状态、证据链接和阻塞可视化。不要在本文件追加日期型施工记录或测试计数。
